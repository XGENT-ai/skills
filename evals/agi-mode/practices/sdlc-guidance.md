# SDLC 指引 playbook：设计与验证记录

本记录服务于本次 skill 修订，不是安装后运行依赖，也不是项目开发进度台账。

## 目标、基线与检查清单

目标：用户从任意开发阶段调用 agi-mode，能获得符合当前证据、项目约定和授权的 SDLC 解释与下一步指引。知识随 agi-mode 分发，不要求用户先安装全部专用技能或初始化台账。

修改前基线：`d975b0e`；工作树干净。入口已含 `init-sdlc`、`what-next` 与实施 playbook，但没有 SDLC 知识与指导的专用入口。`docs/ai-native-sdlc.md` 是仓库级流程说明，包含快照与 SPMS 专用约定，不能作为只安装 agi-mode 时的必需文件。

- [x] 读取 figure-it-out 指定的 poteto-mode Principles，并核对 agi-mode 当前原则及编写流程。
- [x] A：界定范围与验收，检查现有 SDLC 文档、what-next、状态模型和相关技能合同。
- [x] B：固定下面的场景与判据，新增一个自包含 playbook，接通入口与相邻流程。
- [x] C：分单元修改并核对真实文件，保留失败与修订依据。
- [x] D：在本文件记录选择、验证及限制。
- [x] E：回读最终差异，检查分发可用性与授权边界。

严谨程度：文档与路由的结构校验，加逐场景人工核对。变更可逆，不涉及业务代码、平台写入或发布；不增加命令解析器、状态枚举或安装要求。figure-it-out 所引用的 show-me-your-work 未在可用技能及本地参考目录找到，使用本记录保留等价审计线索。

## 事先固定的验收场景

| 场景 | 应有结果 | 不能出现 |
| --- | --- | --- |
| 只有 agi-mode，询问从想法到上线如何推进 | 解释需求、设计、实施、验证、交付与反馈；专用技能缺失时仍能指导 | 依赖仓库外 docs 或先要求安装所有技能 |
| “PRD、CRD、计划、测试计划有什么区别？” | 给出职责、交接产物与边界，CRD 是完整文档往返 | 把 Q&A 当测试验收，或把 CRD 当开发计划 |
| 已有 Ready 计划，询问下一步 | 核对就绪与实施证据再建议推进对应里程碑 | 自动加载 dev-plan 重写计划，或直接执行 |
| 正在按已授权计划实施，中途询问流程 | 简答相关阶段后继续原任务 | 重新请求开工或重启整套规划 |
| 无台账的项目状态查询 | what-next 只读核对原材料，给具体建议 | 初始化目录或改写原文 |
| 计划全部完成，但跨期需求尚缺终验 | 分开计划完成、需求覆盖、验收与发布 | 推导整份 PRD 已交付 |
| 评审无待改项，另一个变体只处理 F-01 | 前者无需空跑 apply；后者保留其他未完项 | 强制整改或把局部处置算整轮完成 |
| 对方返回 CRD，正文也改了、本地有新增 | 比较发出/返回/本地版本，保留双方增量和待确认项 | 覆盖本地、重复粘贴回复、把提案当承诺 |
| 测试草稿已写好，问能否发布 | 核对实际执行、环境、版本、验收和发布条件 | 把 test-plan 或 CI 绿灯当完整验收/发布授权 |
| 不用 SPMS，或平台缺少所需能力 | 文档模式继续，真实工具与权限决定外部动作 | 虚构 key、缺失技能或强推平台状态 |
| 小缺陷、运行故障、退役咨询 | 分别缩减流程、止损与根因分开、检查迁移与退出条件 | 补造全套 PRD，或咨询中执行发布/删除 |
