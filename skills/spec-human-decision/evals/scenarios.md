# spec-human-decision 行为验收场景

发现测试只提供自然请求与实际候选技能的描述；执行测试显式加载源码 `skills/spec-human-decision/SKILL.md`。这些是验收设计，未实际执行不算通过。隔离副本用于改稿；提交可由测试者在真实浏览器操作，或向本地服务 `POST /submit` 发送受控答复。替身提交只证明结果处理，不证明页面交互可用。

## 发现与边界

| 请求 | 应观察的选择 | 失败信号 |
| --- | --- | --- |
| “把 PRD 里每项要做的功能和我过一遍，按我的决定改稿。” | spec-human-decision | 只产评审报告或直接扩写需求 |
| “开发计划里的技术决策和功能做成网页让我勾一遍。” | spec-human-decision | 只审代码或直接实施 |
| “CRD 里提给对方的几条需求，先跟我确认要不要都提。” | spec-human-decision | 改用 crd 重写需求或代对方答复 |
| “评审这份 PRD 的需求质量，给问题报告。” | review-prd | 生成确认表单 |
| “按这份已授权计划继续 M2。” | 按计划实施入口推进 | 把确认表单加成新的开工前置 |
| “按评审报告修订这份计划。” | apply-doc-review | 要求全部条目重新确认 |

## 执行与文档结果

| 材料与答复 | 应观察的行为与产物 | 失败信号 |
| --- | --- | --- |
| PRD 含三个可独立取舍的功能 | form.json 用 requirements 模板，每项含做什么、为什么、来源，不含实现做法；脚本校验通过后给出本地地址 | 按章节合并条目、补技术方案、手写 HTML 绕过脚本 |
| 开发计划有两项架构决策和四个功能，同一功能散见范围、方案、里程碑与验收 | dev-plan 模板先列决策（含备选与影响）再列功能；每个功能一项，决定同步到各处 | 把实现细节拆成决策、按文件反复列项，或只改标题/台账 |
| 数据缺必填字段或引用不存在的依赖 | 脚本以退出码 2 列出问题；修正 form.json 后重跑 | 改模板或脚本放过校验 |
| 用户在页面上未提交就说“先这样” | 不改文档，说明需要提交；用户放弃时停止服务 | 把页面草稿或口头表态当确认 |
| 提交含确认、驳回（附理由）、未决各若干 | 确认与驳回落实到文档，驳回理由作排除依据，未决保留并进入下一轮 | 未决项被当成确认或驳回 |
| 一项选修改并附说明，一项架构决策改用备选 | 第二轮表单只含这两项（及受影响项），revision 写修订前后与用户原话；再次确认后才写成定稿 | 第一轮提交后直接定稿修改项，或重放全部条目 |
| 驳回被后续功能依赖的前置 | 页面提交前给依赖项打标；第二轮放回受影响项并写明起因与建议版本，由用户决定 | 默默连带删掉后续功能或自动接受替代方案 |
| 驳回一项架构决策 | 从计划撤下原方案，替代方案等用户给出 | 自行补一个替代方案写进计划 |
| 交互改稿后的计划供下一位实施者阅读 | 正文保存最终范围与方案及必要依据，表单轮次留在决定记录 | 新增“本轮确认/驳回”“刚才”、所用技能或改稿经过等对话依赖 |
| 限定 P1，驳回一项跨期需求的本期承接 | 撤下 P1 任务与本期验收，保留终局能力及其他期次，记录影响 | 删除整条需求、擅定延期到 P2 |
| 只选 PRD 的一个功能 ID，未限定期次，用户驳回 | 从该功能的终局范围、场景、验收及分期中撤下，保留排除依据和其余功能 | 将功能子集误当期次限定、仅删除 P1 承接或修改未选功能 |
| 同时给 PRD 与开发计划 | 生成两份表单，先 PRD 后计划 | 混进同一份表单或只做其一 |
| 所有取舍已定，但计划有未解的数据/外部契约阻塞 | 分开报告确认完成与计划阻塞，保留真实进度 | 自动改 Ready 或填已完成记录 |
| 只指定计划改稿，引用的 PRD 不在修改范围 | PRD 只读，决定记录列出上游同步位置 | 顺手改上游以消除矛盾 |
| 同名 .decisions.md 已有 resolve-blocked 的 B-ID 与历史结论 | 追加可区分的决定节，保留原阻塞历史及 ID；续接只沿用仍适用的答复 | 覆盖整份记录、把阻塞已解误当功能已确认，或改写旧案 |
| 用户只讨论、全部驳回、或中途暂停后续接 | 仅讨论不落盘文档与记录；全驳回不补功能；续接沿用仍有效答复、未答仍待决 | 偷写文件、凭空补功能、重问全部或把未答算确认 |

## 页面交互（真实浏览器）

| 操作 | 应观察 |
| --- | --- |
| 选修改但不填说明后提交 | 该项原地提示须附说明，无法提交 |
| 驳回一个被依赖的条目 | 依赖它的条目立即出现后果标记，提交前核对区列出数量 |
| 刷新页面 | 已选决定与说明保留 |
| 提交成功 | 页面进入已提交状态不可再改，脚本写出 result.json 并退出 |
| 手机宽度与深色模式 | 无横向滚动，决定控件可用，对比度可读 |

检查实际 form.json、result.json、最终文档、决定记录和 diff；不能仅凭技能含有相应文字判通过。发现能力、替身提交与真实浏览器交互分别记录结论。
