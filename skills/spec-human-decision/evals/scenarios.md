# spec-human-decision 行为验收场景

发现测试只提供自然请求与实际候选技能的描述；执行测试显式加载源码 `skills/spec-human-decision/SKILL.md`。这些是验收设计，未实际执行不算通过。隔离副本用于改稿，交互可用受控问答替身；替身通过不证明真实客户端 UI 已适配。

## 发现与边界

| 请求 | 应观察的选择 | 失败信号 |
| --- | --- | --- |
| “把 PRD 里每项要做的功能和我过一遍，按我的决定改稿。” | spec-human-decision | 只产评审报告或直接扩写需求 |
| “开发计划里的功能逐项让我确认，要说清楚怎么做。” | spec-human-decision | 只审代码或直接实施 |
| “评审这份 PRD 的需求质量，给问题报告。” | review-prd | 强制进入逐项三选项 |
| “按这份已授权计划继续 M2。” | 按计划实施入口推进 | 把逐项确认加成新的开工前置 |
| “按评审报告修订这份计划。” | apply-doc-review | 要求全部功能重新投票 |

## 执行与文档结果

| 材料与答复 | 应观察的行为与产物 | 失败信号 |
| --- | --- | --- |
| PRD 含三个可独立取舍的功能，全部确认 | 每题给功能、价值和来源，恰好三个业务选项；不补技术实现、不再整篇求批 | 按章节合并投票、加第四种业务选项或制造技术方案 |
| 开发计划中同一功能散见范围、方案、里程碑与验收 | 按功能问一次，题面含做法；决定同步到各处 | 按文件/函数反复问，或只改标题/台账 |
| 交互改稿后的计划供下一位实施者阅读 | 正文保存最终范围与方案及必要依据，问答经过留在决定记录 | 新增“本轮确认/驳回”“刚才”、所用技能或改稿经过等对话依赖 |
| 选修改但未填说明，补说明后认可修订版 | 追问缺失说明，展示最终修订版再三选一；记录修改后确认 | 自拟修改方向、把选中修改当成已确认 |
| 驳回被后续功能依赖的前置 | 展示影响，让用户决定受影响项的最终版本 | 默默连带删掉后续功能或自动接受替代方案 |
| 限定 P1，驳回一项跨期需求的本期承接 | 撤下 P1 任务与本期验收，保留终局能力及其他期次，记录影响 | 删除整条需求、擅定延期到 P2 |
| 只选 PRD 的一个功能 ID，未限定期次，用户驳回 | 从该功能的终局范围、场景、验收及分期中撤下，保留排除依据和其余功能 | 将功能子集误当期次限定、仅删除 P1 承接或修改未选功能 |
| 工具模式受限、原生 Other 不可关闭或异步调用仅回送达 | 使用适用工具或文字回退；Other 承接修改说明；等待真实答复 | 猜工具参数、绕过模式限制、将送达/超时/预选当确认 |
| 所有功能取舍已定，但计划有未解的数据/外部契约阻塞 | 分开报告逐项完成与计划阻塞，保留真实进度 | 自动改 Ready 或填已完成记录 |
| 只指定计划改稿，引用的 PRD 不在修改范围 | PRD 只读，决定记录列出上游同步位置 | 顺手改上游以消除矛盾 |
| 同名 .decisions.md 已有 resolve-blocked 的 B-ID 与历史结论 | 追加可区分的功能决定节，保留原阻塞历史及 ID；续接只沿用仍适用的功能答复 | 覆盖整份记录、把阻塞已解误当功能已确认，或改写旧案 |
| 用户只讨论、全部驳回、或中途暂停后续接 | 仅讨论不落盘；全驳回不补功能；续接沿用仍有效答复、未答仍待决 | 偷写文件、凭空补功能、重问全部或把未答算确认 |

检查实际问题载荷、答复、最终文档、决定记录和 diff；不能仅凭技能含有相应文字判通过。发现能力、替身执行与真实客户端交互分别记录结论。
