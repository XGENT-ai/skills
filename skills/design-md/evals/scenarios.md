# design-md 行为验收

以下为待执行场景，不是通过记录。在隔离副本中运行，保留修改前后文件、来源与检查结果。不得为验证本技能修改真实产品仓库。

| 场景与请求 | 应观察的行为 | 失败信号 |
| --- | --- | --- |
| 现有 Portal 页面：「根据当前规范和代码更新 DESIGN.md」 | 追踪样式入口、token 和代表组件；保留产品约束；有依据才变更 | 套入营销站配色；把 demo 当生产；仅因代码偏差改写规范 |
| 规范明确按钮用品牌蓝，两个页面硬编码成紫色 | 保留蓝色规则，报告两处实现偏差 | 以出现次数认定紫色是新的品牌规范 |
| 无规范项目，有实际共用 token、另有未引用的旧主题 | 提炼实际生效 token 及用途，排除旧主题 | 搜到即收录；按框架默认值猜测当前配置 |
| 基础 CSS 是蓝色，入口注入构建品牌，provider 再覆盖租户色 | 追踪覆盖顺序，区分基础值、构建默认和租户最终值；保留语义 token | 把基础 CSS 的蓝色写成所有租户不可变规则 |
| 只有用户接受的间距调整，其他字段无变更 | 局部更新并保留其他约定；再运行无变化时不改文件 | 全文重写、重新推导品牌或添加时间噪声 |
| URL 可渲染，仅观察到一个页面的桌面亮色态 | 输出明确范围的重建草稿，不覆盖当前产品 DESIGN.md | 补出暗色、移动端、内部组件名或全站规则 |
| URL 无浏览器，只有截图与网页说明 | 交付有限观察，标记不能测量的数值和行为 | 编造 token、断点；宣称完整规范或视觉验证通过 |
| 外站草稿供当前产品参考，项目已有规范 | 草稿单列「对当前产品的借鉴」，映射到现有 token 并标出冲突，标为建议 | 草稿只有来源与未知项，实现者无法据此决策；或把借鉴写成当前规范 |
| 「把 DESIGN.md 导出成 tailwind 配置」「检查 DESIGN.md 能否过 lint」 | 触发本技能并按格式与验证处理 | 路由为无技能或其他技能 |
| 用户的 Markdown 格式与外部 schema 不同 | 保留现有契约；只有明确需要兼容导出时处理映射 | 无授权迁移文档或删除无法导出的规则 |
| 导出器退出成功，但丢失输入中的字体或主题 | 检查实际输出，报告失败或不支持项，保留原始设计信息 | 只检查退出码；删 token 后宣布通过 |
| 用户想找新风格、直接重构组件，或仅要求评审 | 交给相应流程；只读请求不写文档 | 把提案或评审意见直接写成正式规范 |
| 已明确要求「整理规范后继续改页面」 | 完成文档后沿原授权继续实现和验证 | 以本技能只写文档为由停工或重复申请批准 |

结构检查覆盖 skill frontmatter、description 全文及前 100 字符、相对链接。试跑结果另行记录输入、产物、已跑范围和限制；文档提炼通过不代表浏览器验收或后续实现交接已经通过。
