# 交底书分类型写法

先用「通用规则」，再读与本案类型对应的一节。下面是交底书章节建议，不是专利申请文件格式。

## 通用规则

- 文头给出案件名称、专利类型与模板要求的联系人信息。标题写清技术对象或产品，正文和附图用同一套名称。不用内部代号代替技术对象。
- 成文时按 [公开查新与证据比对](prior-art.md) 的「写回交底书」处理公开文献或用户提供的对比材料；读不到的部分不作比较结论。
- 发明和实用新型的技术问题写**需要解决的困难**，不要把本案的手段写进问题。技术效果说明由哪组机制或构造在何种条件下产生；区分有测试条件和基线的实测结果、未验证的预期效果。一起起作用的特征按组合讲清。
- 「欲保护点」用技术描述，不写正式权项。逐项问：去掉这个特征或特征组合，核心方案还能否解决所述问题？不能的列为必要特征，能的列为优选；证据不足时留待确认。每个必要特征都要能指回正文的构造、步骤或公式。有技术作用的参数不能机械归为优选。
- 图用用户提供且核对过的材料；只引用实际附入的图。逻辑流程足够清楚时可用本地文本 Mermaid 表达，步骤号同时出现在标签与正文。不从想象补画实物、结构或未见视角；缺图列明所需视角、部件或关系。

## 发明

1. **技术背景与现有做法**：交代应用环境、既有做法和具体局限；有已读对比材料时列来源和区别。
2. **要解决的技术问题**：写成不预设解法的问题，范围与技术效果相匹配。
3. **详细技术方案**：按案件实际写清执行主体、被处理或控制的对象、数据来源、模块关系、操作顺序、判断条件、分支和输出。系统或方法分别给可用的框图或流程图；只有相关的才写，不强凑模块。关键参数说明取值或获得方式、单位和作用；材料已有公式按原机制写，定义符号并核对参数和实施例。材料只写「智能判断」等结果时，追问实际判定规则，不替发明人补算法。
4. **技术效果**：写手段产生的技术变化，说明适用条件；没有实测时不量化改善。
5. **技术关键点与欲保护点**：分必要特征与优选特征；已有证据的等效实现写明改变和不变的机制。
6. **具体实施例**：至少写一个能走完主路径的例子，补上材料支持且影响实现的条件或分支；区分实施记录和有据的示意例。

## 实用新型

1. **技术背景与结构问题**：说明产品用途、既有构造及其装配、受力、空间或拆装局限。
2. **总体构成与连接关系**：按「件号—名称—形状或位置—连接或配合」写零件及其关系，再说明如何装配、工作或拆卸。对关键连接说清谁与谁、在何部位、怎样配合。从装配图、剖视或局部图提取有证据的形状与关系；不由整机照片猜内部构造。
3. **附图说明与实施方式**：图号和件号内外一致；局部、剖面或爆炸图说明与总装图的关系。关键尺寸、材料或公差有依据才写；缺失且影响复现时列待确认。
4. **技术效果与欲保护点**：将效果落到具体结构，并区分必要构造和优选件、尺寸或做法。工艺、软件或操作流程只能辅助解释结构作用，不作为独立保护点主线。

## 外观设计

1. **产品名称与用途**：记录外观所依附的产品；若材料明确是局部设计，说明设计部位及其与整件产品的关系。
2. **设计要点**：从可见形状、图案、色彩及其组合归纳。只有材料表明色彩是拟保护要点时，才按色彩主张描述。不要把内部结构、电路、受力、功能或制造工艺当成外观要点。
3. **视图及说明**：对照设计要点落面核对主视图、后视图、左视图、右视图、俯视图、仰视图、立体图中实际适用的图。同一产品、同一状态、同一部位的轮廓与线型前后一致；局部图注明来源视图。区分「有图」「有据可省略」和「缺图」：无证据不假定相同或对称，不凭文字补画未见的面，也不机械凑六视图。
4. **与在先外观的差异（有材料时）**：同一观察角度比较可见要点，标出来源；资料不足则列待补，不据此下相似性或授权结论。
