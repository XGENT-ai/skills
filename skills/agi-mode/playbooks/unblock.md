# 突破阻塞

在原任务内运行，输出能恢复推进的新证据或能力。进入时带上未满足的验收、已失败尝试及其实际结果；不要重新定义用户目标来消除阻塞。

## 先选择失败层级

决策入口：共同假设失效读 [检验前提](../principles/challenge-premises.md)，缺工具读 [构建杠杆](../principles/build-leverage.md)，选择区分实验读 [信息价值](../principles/information-first.md)。

| 观察到的信号 | 优先处理的层级 |
| --- | --- |
| 行为仍错，多个修复共享同一假设 | 重建问题模型 |
| 用户看到失败，检查却绿；不同候选无法区分 | 修复观测与验证 |
| 知道该观察或修改什么，但现有操作做不到或成本过高 | 建造最小能力 |
| 权限或外部依赖缺失，替代方式不等效 | 保留阻塞，推进独立工作 |

先验证分类。工具没启动不是业务假设被否定，测量无差异也可能只是噪声过大。

## A. 重建问题模型

1. 摘出失败尝试共享的前提，例如“缓存跨请求存在”或“每个参与者拿到同等负载”。
2. 建立相互竞争的解释，找出会使它们预测不同结果的最小输入或观测。按实际相关维度拆分总体结果，不用平均数掩盖局部失衡。
3. 在受控环境测试前提：交换角色、隔离依赖、关闭一个因素或改变输入规模。先预测结果，再观察，避免看到什么都能解释。
4. 前提被反驳时，撤回依赖它的补丁，改变状态归属、生命周期、算法或系统边界；前提仍成立时，沿新证据缩小原因。
5. 若目标是探上限，先估计不可消除成本，区分“少做无用工作”和“做同样工作更快”。用测量校准上限，不把理论估计写成已实现结果。

交回原 playbook 的是修正后的模型、已排除方向和下一项可检验行动。

## B. 修复观测与验证

1. 保留原始异常与当前检查结果，核对入口、构建版本、数据来源、采样时间和缓存。
2. 在隔离环境构造已知好、已知坏样本。检查是否命中目标路径，是否会被绕过，是否能区分两者。
3. 修复工具、负载或接线。把验证器修订与产品改动区分记录，避免同步调整两者掩盖问题。
4. 用修正后的检查重新测量未修复基线与候选。若无法重放基线，降低比较结论的强度，保留剩余未知。
5. 原判定因观测缺陷失效时，追踪依赖它的验收和后续阶段，撤销相应的通过状态并重验。

不能通过删除失败样本、调低门槛或放宽用户要求修复验证器。

## C. 建造最小能力

1. 定义缺口的输入与输出，例如“从大量 trace 中提取按调用栈聚合的耗时”，以及结果如何推进原验收。
2. 搜索当前已有工具和接口；有可复用能力则直接使用。没有时，手工完成一个代表性样本，确认转换或操作语义。
3. 实现最小脚本、解析器、批处理或驱动，不先建设通用框架。只读工具优先；写入工具提供预览、对象清单及必要的重跑保护。
4. 用手工样本、一个错误输入和一个边界输入检验工具；批量写入先试一个单元并读回结果。
5. 运行工具完成原任务。是否值得保留取决于重跑、审阅或复用需求；没有这些价值的临时工具可随实验结束移除。

新能力继承原任务范围和权限，不能绕过访问限制。无法达到所需证据质量时，报告具体缺口，而非无休止建设辅助工具。

## 验收与退出

完成一次明确的层级改变后，比较它是否新增可区分的证据或恢复了执行能力。有则返回原任务；无则根据新观察换层级，避免在同一动作上重试。所有合理路径均受阻时给出阻塞条件、保留产物和恢复入口。

## 交付

记录旧前提或能力缺口、改变了什么、新证据及其对原任务的影响。只保留可审查的决策摘要。
