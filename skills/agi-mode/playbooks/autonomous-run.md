# 自主任务总控

用于跨阶段自主任务、实施队列和需要持续推进的复杂目标。它管理阶段间依赖，不替代各阶段的具体 playbook；普通局部任务不加这一层。

当任务成为多个独立单元、堆叠 PR 或需要处理失联执行者的长期项目时，转入 [项目与队列编排](program.md)，保留这里的结果契约。

## 启动

决策入口：阶段边界读 [结果责任](../principles/outcome-ownership.md)，安排工作读 [关键路径](../principles/critical-path-throughput.md)，循环退出读 [收敛](../principles/bounded-convergence.md)。

1. 从请求和已有计划确定完整交付边界，将“完成”写为可检查的条件。列清哪些交付只是准备，哪些包括 PR、合并或发布。
2. 读取 [持续执行与恢复](../references/continuity.md)，沿用一份结果契约与进度记录，保存基线、改动归属和已有证据。
3. 按依赖组织阶段，每阶段列出输入、产物、验收与下一阶段。优先验证可能推翻目标路径的约束，再进行重复扩展。已有有效计划直接执行，不因启用本模式而重写。
4. 选择当前主 playbook。独立工作在环境允许时可拆分，但任务必须有所有者、写入边界和集成验收；单个执行者可完成的工作不强制分发。

## 每轮推进

1. 对照实际产物更新已满足与未满足的验收，读取用户的新要求和外部状态变化。
2. 找到当前阻塞交付的因素，选择能推进结果或提供区分证据的下一步，交给当前阶段执行。
3. 检查返回的真实产物，保留验证过的进展；失败则处理观测、执行或假设错误。不要把子任务自报完成直接写成总目标完成。
4. 阶段验收通过后直接进入已授权的下一阶段，传递证据与必要状态，不重复调查或索要许可。
5. 更新重要决定、排除的方向和恢复入口，向用户说明新增进展或变化的判断。普通状态询问回答后继续，明确暂停则切换 [会话交接](session-handoff.md)。

实现完成后仍可能存在集成、交付或远端状态验证。队列中的任务各有自己的完成条件，总目标还需检查组合后的依赖与结果。

## 处理停滞

- 可解决的范围内问题继续解决；连续失败、验证失效或缺工具时进入 [突破阻塞](unblock.md)，完成一次明确的策略改变后返回。
- 外部结果未到时推进独立工作。等待依赖时保留事件句柄或查询入口，不建立平台不存在的后台承诺。
- 范围外问题记录影响。若它是必要依赖，说明需要扩大哪部分范围，先完成可独立交付的部分。
- 无有用新路径时指出已尝试的不同方向、缺少的资源或输入，以及什么变化才能恢复。不要重复无信息的动作来维持“运行中”。

## 验收与退出

主文件的完成、等待依赖、资源受限、暂停与取消状态适用。全局完成需要全部必要阶段及组合验收成立。用户或环境限制迫使停止时保存状态，保留真实未完成项；达标后结束，不擅自添加下一批目标。

## 交付

原目标与实际完成状态、各阶段产物和证据、重要取舍、未满足项与恢复条件。长记录提供位置，回复只保留决定下一步所需的信息。
