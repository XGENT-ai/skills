# 性能优化

用于解决一次明确的性能问题。围绕指标持续搜索使用 [Hillclimb](hillclimb.md)；只比较已有候选使用 [Eval](eval.md)；只要求定位瓶颈时使用 [调查与诊断](investigation.md)。

## 执行

决策入口：选择测量读 [信息价值](../principles/information-first.md)，测量可信度不足读 [验证器反证](../principles/falsifiable-verification.md)，决定何时停止读 [收敛](../principles/bounded-convergence.md)。

1. 明确用户受影响的场景、目标指标和质量底线，沿用已有目标。持续搜索请求转入 Hillclimb，保留已取得的基线。
2. 读取 [实验与反证](../references/experiments.md)，建立代表性负载与可重复测量。确认测量命中目标路径，记录当前版本、环境、基线与波动。
3. 找出限制指标的机制，将假设写成可检验的预测。先处理最大的已证实瓶颈；“换一个库也许更快”不构成因果依据。
4. 每轮执行一个可解释的改变，测量候选并检查质量底线。相同条件下比较，必要时交替运行基线与候选以发现环境漂移。
5. 只保留超过噪声且代价合理的收益，或性能保持的有效简化。失败候选只撤回自己的变更，记录被否定的假设。
6. 多次修复无效时检查测量、重审前提或换优化层级。组合已有效的改动后重测，不假设收益相加。
7. 在最终保留版本上确认代表性场景、最容易退化的输入与必要回归，保存前后测量及对应版本。

测量工具失真则先修工具并重建可比基线。削弱校验、改变语义或丢弃工作不能伪装成同等质量的优化。

## 验收与退出

- 一次性任务在约定问题改善且验证充分后结束。
- 用户要求扩大为持续搜索时，交给 Hillclimb 管理实验、最佳候选和收敛条件。
- 没有可比的前后结果就不声称量化收益，不设无意义的最低迭代次数。

## 交付

指标、负载和采样口径，基线与最终值、波动、保留改动及成本、证据位置和验收状态。
