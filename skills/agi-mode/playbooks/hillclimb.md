# Hillclimb：持续搜索并保留有效改进

用于在明确目标与范围内连续改进代码、算法、skill、prompt 或 agent 流程。持有假设、实验、最佳候选与退出状态。一次性能修复使用 [性能优化](optimization.md)，只比较候选使用 [Eval](eval.md)。`autoresearch` 兼容入口直接执行本流程；多方向分叉使用内部 [Arena](arena.md)，不另设晋级规则。

决策入口：选假设读 [信息价值](../principles/information-first.md)，平台期读 [检验前提](../principles/challenge-premises.md)，目标与资源取舍读 [收敛](../principles/bounded-convergence.md)。持续维护 skill 时读 [技能演化与协作](../references/skill-evolution.md)。

## 1. 固定目标、可改表面与比较基线

1. 从真实任务确定主指标、方向、最小值得采用的收益、质量底线与成本约束。覆盖率、通过数、代码行数或 prompt 长度等代理指标须有真实目标依据，不能靠删测试或必要指令涨分。先选择“提升质量”或“质量在预定界限内保持，降低成本／复杂度”；不能看到结果后换目标。
2. 列出允许改动的表面，例如描述、正文、工具说明、模型／effort 或明确的 harness 模块。优先选修改便宜、可撤回、与目标有因果关联的表面。模型选择改变时记录身份，不硬编码不可用模型。
3. 固定数据、判定器、环境和协议版本，复现初始基线。行为比较按 Eval 校准；确定性性能使用校准过的测量命令。基线不暴露目标问题，先修负载；噪声高于可行动收益，先修评测。
4. 保存初始基线、当前探索最佳、已确认版本及可恢复快照。工作树已有修改先记录并保护；隔离副本须包含本轮真实起点，不能只复制 HEAD 丢掉未提交内容。撤回只作用于自己这轮的差异。
5. 分配搜索、诊断与最终确认的资源。预算沿用用户要求；未指定时从成本可控的一轮开始，不默认无限。已授权的范围内直接推进，不逐轮索要继续许可。

重复调优使用 Eval 的 search／可选 validation／confirmation 划分。搜索者只读 search 轨迹，按事前约定接收 validation 聚合反馈，最终确认前不接触 confirmation。没有未见任务时可以改进已知场景，但不能声明泛化已证实。

## 2. 保存一份搜索状态

复用已有日志，或使用 [评测记录模板](../references/eval-protocol.md)。每轮至少记录：

```text
attempt_id | parent_best | hypothesis | expected_effect | candidate_version
protocol_version | run_ids | guardrails | delta_and_uncertainty | cost
verdict | reason | evidence | restore_point
```

区分 `keep`（探索保留）、`discard`、`inconclusive`、`invalid`，最终确认状态另记。崩溃、补测与被拒绝的候选都保留证据；原始失败不能被成功重跑覆盖。每个运行保留独立原始日志与重跑关联，不用一个日志覆盖上一次结果。日志给搜索者的视图不能泄露受限材料，也不进入被测候选上下文。

接受版本可以是内容哈希、隔离快照、补丁或已授权提交，不要求每次实验制造 commit。下一轮读取已有尝试，避免重复已被反驳的假设。

## 3. 一轮机制假设，一轮判定

1. 从 search 的真实失败解释机制，注明预期改变、受益场景、可能回归及反证。优先解决足以产生可测收益的根因；证据不支持时，不靠同义改写堆轮次。
2. 从明确父版本构造最小候选。一次可修改实现同一机制所需的多处内容，不叠加不可归因的猜想。并行候选须隔离写入与运行状态，共用协议和资源限制。
3. 执行相同样本和预算的成对比较及质量底线检查；环境波动时交替运行。按计划在检查点回测初始基线，识别漂移与多轮微小退化的积累。
4. 依次检查运行有效性、质量底线、差异与不确定性、实际价值、增加的维护成本。采用条件按 Eval 预先固定；确定性且可复现的差异无需虚构随机区间。
5. 有效改善更新探索最佳；明确回归或无价值变化撤回；未定则按协议补测或暂存，不晋级；无效先修环境。候选自身崩溃或超预算按行为失败，不能一概归为基础设施错误。
6. 写完记录再进入依赖它的下一轮。组合赢家或从 Arena 移植片段都形成新候选，重新验证，收益不能相加推定。

不向 prompt／skill 粘贴失败原文、参考答案、题目标识或仅对基准目录成立的路径规则。把失败抽象为适用机制，并检查合法相邻场景；新增工具或 harness 特例须有真实任务需要的证据。评测数据与判定器不属于这一轮候选可修改的表面。

## 4. 平台期先诊断，再继续搜索

连续两三轮有效尝试停滞，或单个假设的可能收益已低于噪声时，先做一轮**不改候选的诊断**。读剩余 search 失败并按证据分桶：

| 原因 | 下一步 |
| --- | --- |
| 缺少能力或领域规则 | 补必要机制，验证适用与不适用场景 |
| 内容已有但没执行／未触发 | 检查发现、路由、指令位置与冲突；优先移位、去重复或纠正旧习惯入口 |
| 任务含糊、不可解或 judge 错判 | 退出本轮搜索，修评测并建立新协议下的基线 |
| 环境、截断、配置接线问题 | 核对真实运行条件，区分候选预算失败与基础设施无效 |
| 数据不足或随机波动 | 增加独立案例／可比重复，或报告无法分辨 |
| 目标已经饱和／约束限制上限 | 报告可达上限；目标允许时探索保质降成本，不移动原门槛 |

诊断结论可交给 [Reflection](reflection.md) 提炼机制，但 reviewer 一致不算因果证据。确有昂贵的结构分叉才用 Arena；没有新信息时，不用更多 agent 或更大改动替代诊断。

需要新能力时用 [突破阻塞](unblock.md)，解决后返回。扩大范围或改变关键取舍需核对授权，先交付现有可验证结果。

协议发生实质变化就重测初始基线和当前最佳，必要时重测仍有竞争力的候选。旧日志保留，不把换尺后的分数拼成连续涨分曲线。

## 5. 冻结候选，最终确认

探索达到预设条件后冻结一个候选及其哈希，在未参与选择的 confirmation 上与初始基线比较，按原目标检查质量、成本和重要分组回归。确定性性能也需确认目标负载与质量底线；同题重跑仅支持稳定性结论。

确认通过才更新已确认版本。失败则保留或恢复仍有效的已确认版本，保留负面证据；这次确认材料若参与后续改动就已暴露。没有新的独立材料时，不靠多次尝试同一确认集宣称通过。

目标已确认达成、用户要求停止、既有资源限制到达，或剩余探索已无合理信息价值时结束。区分“达标”和“搜索结束”；任意最低轮数不能替代证据。用户已指定尝试次数时遵从其约束，同时保留真实失败与状态。等待或恢复见 [持续执行与恢复](../references/continuity.md)。

## 交付与沉淀

交付初始基线到最终确认版本的可比结果、尝试与判定分类、接受的变化和代价、原始证据、恢复入口与目标状态。允许结论为“没有找到有效改进”。

经验写回 skill、测试或工具时，记录适用范围、反例、证据版本和失效条件；只在已授权维护范围内固化。删去因新机制而重复或冲突的旧指导，避免每次失败都加永久规则。后续真实任务发现回归时重新进入这一循环，不把一次赢分变成永久保证。
