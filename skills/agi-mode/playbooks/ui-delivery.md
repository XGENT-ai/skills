# 界面交付

用于界面实现、交互改进、视觉还原和跨尺寸适配。以实际呈现和用户操作验收，不从源代码推断屏幕效果。

## 执行

决策入口：体验取舍读 [使用者结果](../principles/experience-first.md)，接受截图与操作证据读 [真实结果](../principles/prove-real-outcomes.md)，差分或交互检查可疑时读 [验证器反证](../principles/falsifiable-verification.md)。

1. 明确属于开放设计、指定稿还原还是现有界面修复。读取项目设计约定、参考材料、实际用户流程和目标尺寸；还原任务不擅自重新设计。
2. 确定内容、主要动作、状态与信息层次。需要决定方向时先使用 [设计与原型](design-prototype.md)，方向明确后进入实现。
3. 打通主要交互，再覆盖此次任务相关的加载、空、错误、禁用或完成状态。保持真实内容与数据语义，不能用假成功交互冒充接通。
4. 启动实际界面，在代表性尺寸与边界宽度操作。检查文本溢出、滚动、焦点、键盘操作、触控区域及用户任务是否可完成；按本次风险选项，不机械扩大成全站审计。
5. 视觉还原时对齐视口、字体、内容、缩放和动态状态后比较截图。区分环境差异与实现偏差；像素差分提供定位依据，视觉和交互检查决定它是否影响目标。
6. 修改后重新查看受影响的状态，检查是否引入布局、交互或可访问性回归。保留能说明结果的截图或操作证据。

没有可用的渲染或控制工具时继续完成静态可验证部分，并标记实际呈现未验证。旧截图或设计稿不证明新实现的状态。不要用与用户任务无关的动画或装饰填补方向不清。

## 严格视觉等价

要求像素一致时，修改前建立受保护的参考截图与场景清单，确认视口、字体、数据、缩放、动画和设备像素比例可复现。先处理共享视觉基础，再逐个状态或组件迁移，每项都有图像差分。

用户要求零差异就保留零差异门槛；只有目标明确允许容差时才使用约定阈值。不能临时改参考图、裁掉失败区域或提高阈值来过关。参考有问题时保留失败证据并明确提出变更，不在实现与参考上同时悄悄修正。

环境噪声通过同一版本的重复捕获识别。先稳定环境再测；无法稳定时报告无法判定，不用肉眼相似替代严格等价结论。

## 验收与退出

- 实际主要操作链路可完成，目标尺寸和相关状态得到检查。
- 还原任务的差异有明确处置，环境噪声没有掩盖真实偏差。
- 关键体验决定仍缺用户输入时，交付具体候选及影响，并继续不依赖该决定的部分。

## 交付

体验变化、实现或预览位置、实际检查的尺寸和操作、截图或其他证据、仍存在的偏差与限制。
