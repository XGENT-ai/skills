# 功能交付

用于新增能力或有意改变行为。交付是用户能使用的端到端结果。

## 执行

决策入口：跨层依赖未定时读 [基础](../principles/foundations-first.md)，状态与签名设计读 [领域约束](../principles/domain-models-and-types.md)，接外部输入读 [边界](../principles/boundary-discipline.md)，添加抽象时读 [复杂度](../principles/minimize-complexity.md)。

1. 确定实际入口、成功路径和本次相关的错误或边界状态。检查已有实现、约定和测试方式，将新增行为与必须保持的行为分开。
2. 先描述数据形状、状态所有者和系统边界。昂贵设计分叉转入 [设计与原型](design-prototype.md) 解决后返回；局部明确的选择直接实施。
3. 选择最小端到端切片，先验证外部依赖、权限或状态转换等可能推翻方案的部分。将剩余工作按依赖拆分，每项都有具体产物与检查方法。
4. 完成一个真实可用路径，再扩展边界。沿项目现有结构组织实现；只删除本次改动造成的无用代码，不顺带改造无关模块。
5. 从消费者入口验证新增行为，检查本次改变可能影响的邻近行为。根据风险运行相应检查，不把单元测试或编译当作所有界面的证明。
6. 审阅最终差异与结果契约，检查接线、配置、调用方和必要说明是否遗漏。涉及 UI 的部分使用 [界面交付](ui-delivery.md) 的实际呈现验收。

外部依赖不可用时，可以用受控替身验证本地逻辑，但应保留真实集成未验证的状态。原型或假数据不能冒充已接通的功能。

## 验收与退出

- 用户能通过指定入口获得预期结果，相关失败行为明确且已按风险验证。
- 每项必要验收对应当前产物的证据，关键限制已说明。
- 交付边界按用户请求决定。只有任务包含 PR 或发布时才继续进入 [PR 生命周期](pr-lifecycle.md) 或 [合并与发布](shipping.md)。

## 交付

用户获得的变化、产物位置、重要取舍、实际检查与未验证部分。
