# 资源清理

用于用户请求的 worktree、模拟器、构建缓存等清理。判断依据是对象的实际用途与可恢复性，不能从目录老旧或名字像临时文件推导可删。

## 执行

决策入口：多个执行者占用资源时读 [状态归属](../principles/state-ownership.md)，判断可清理与实际释放量读 [真实结果](../principles/prove-real-outcomes.md)。

1. 记录文件系统可用空间和目标资源占用。区分磁盘空间问题与文件数量、配额或正在被进程持有的问题。
2. 从资源管理工具枚举对象：worktree 从 Git 注册信息取得，模拟器从设备管理工具取得，缓存从实际工具配置取得。使用工具返回的精确路径或标识，不凭目录命名猜测。
3. 对每个候选检查使用状态和独有内容。worktree 检查分支、合并状态、未推送提交、已跟踪修改、未跟踪及忽略文件、锁与活跃进程。忽略文件也可能包含用户数据，不能统一视为可丢弃。
4. 形成对象清单：可清理、保留、信息不足。列出预估空间、依据和不可恢复内容。已有授权覆盖且用途已确认的对象继续处理；不确定或会损失用户独有内容的项保留并请求具体决定。
5. 先处理一个确认对象，使用资源自身的删除或回收命令并读回状态。普通删除被锁、占用或脏工作区拒绝时重新调查，不自动升级为强制删除。
6. 继续已确认集合，最后重新枚举资源并测量实际释放空间。对象大小之和不等于真正释放量，开放文件、共享块和快照可能造成差异。

不为了判断占用扫描其他工作区的私人聊天。可以使用当前任务可见的进程、锁、任务记录和用户指出的活动集合。模拟器与缓存删除前同样确认是否包含用户数据以及重建成本。

## 验收与退出

仅授权集合中的确认对象被清理，没有丢失未确认的独有内容。剩余对象各有保留原因，实际空间变化已测量；无法确认释放时说明观测边界。

## 交付

清理对象与理由、保留对象与理由、前后空间、必要的重建或恢复说明。
