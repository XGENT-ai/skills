# 会话交接

用于接续旧任务、用户暂停或取消、上下文切换。先识别请求方向；“我去睡了，继续做”属于 [自主任务总控](autonomous-run.md)，不是暂停。

读取 [持续执行与恢复](../references/continuity.md)，沿用其最小持久状态格式与外部动作核对规则。

## 接续

决策入口：保存或恢复工作读 [上下文状态](../principles/context-as-state.md)，决定重验范围读 [证据时效](../principles/evidence-lifetime.md)。这两个入口也适用于下方的暂停与交接。

1. 读取任务现有契约、最后检查点和用户新增要求，确认工作位置、版本、当前阶段与最终目标。
2. 对照实际差异和运行状态，确认哪些变更属于当前任务、哪些是用户或其他执行者的工作。检查尚未结束的本地与外部动作，避免重复启动。
3. 复用仍对应当前版本和环境的证据。发生漂移、记录矛盾或关键证据缺失时，只重新检查受影响部分。
4. 指定第一个未满足的验收，进入对应主 playbook。接续动作到此结束，后续由实施流程持有任务。

旧摘要提供恢复线索，实际产物决定现状。不从零重做，也不把历史“完成”当作当前证明。

## 暂停或取消

1. 停止启动新工作，及时取消自己启动且能够安全取消的在途任务。不要为收尾开始新的功能修改。
2. 对已发出的外部动作核对状态，明确已完成、仍运行或未知。无法撤回就记录实际影响，不能声称已经取消。
3. 保存已有产物和检查点，记录修改归属、未完成步骤、后台标识、下一步与验证方式。需要恢复自己的半成品时只处理可确认归属的改动。
4. 不为保存进度自动提交、推送或发布。用户已有授权与暂停要求相容时才做必要收尾；明确禁止继续动作时遵从该限制。

## 上下文交接

在当前可检查的边界更新状态，保留任务句柄与下一步。不把上下文压缩当作用户暂停；新上下文恢复后继续既有任务。硬限制迫使退出时明确它与用户主动暂停的区别。

## 验收与退出

- 接续后下一步由当前事实确定，已完成工作没有被重复执行。
- 暂停后没有继续实施或遗留未披露的任务，取消的实际范围清楚。
- 新会话能凭记录定位产物、证据、未完成项和恢复入口。

## 交付

接续时说明恢复位置并继续工作。暂停时说明保存位置、在途状态和恢复的第一个动作；取消时另说明已经发生且未撤回的影响。
