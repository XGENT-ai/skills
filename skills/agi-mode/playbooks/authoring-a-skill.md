# Skill 编写与修订

用于创建或修改 skill、agent 工作流及指令。行为对照由独立的 [Eval](eval.md) 执行，持续搜索更好的版本由 [Hillclimb](hillclimb.md) 管理。编写任务不自动开启长循环。

## 执行

决策入口：纠正重复错误读 [结构化学习](../principles/structural-learning.md)，安排渐进加载读 [上下文状态](../principles/context-as-state.md)，设计行为判定读 [验证器反证](../principles/falsifiable-verification.md)。

1. 明确目标请求、当前决策缺陷和预期行为。阅读参考 skill 与目标环境的格式、调用约定；保留用户已有调用策略，不能只因自身偏好改成自动或手动触发。
2. 若环境提供适用的 skill 编写能力，按其实际说明使用；否则直接维护名称、描述、主体和必要资源。只写能改变决策的指令。
3. 将共通约束放在入口，将任务流程放进 playbook，将条件性方法放进 reference。每个链接说明何时读取，避免循环依赖和一次性加载全部内容。
4. 检查 frontmatter、文件路径、引用可达性、触发精度和冲突。沿真实请求追踪路由，确认不会把只读任务升级为写入、把普通任务升级为长期运行。
5. 对结构性行为变化分别检查发现／路由与执行：自然请求测试漏触发、误触发，显式加载测试实际行为；保留原调用策略。准备原始材料，覆盖新能力、合法相邻场景及容易误触发的请求。维护本模式时可参考 [行为验收场景](../evals/scenarios.md)，通过 Eval 隔离判定标准并执行比较。
6. 根据真实观察到的错误做最小修订，再执行受影响检查。若用户要求持续改进，则把目标、范围和当前版本交给 Hillclimb；一次性编写任务在交付条件满足后结束。

本手册不授权自行改全局指令、安装环境或发布 skill。修改与安装、发布的范围各按用户请求确定。

## 验收与退出

- 结构可加载，必要资源能找到，任务路由和授权边界一致。
- 每项验证声明标明实际执行到哪一层，未运行的场景不计为通过。
- 只有可比的真实行为证据支持时，才宣称优于旧版本或基线。

## 交付

skill 位置、改变的决策、验证方式与结果、未测试的能力。必要时附案例和失败证据，不只给规则摘要。
