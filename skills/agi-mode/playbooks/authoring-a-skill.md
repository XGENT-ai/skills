# Skill 编写与修订

用于创建或修改 skill、agent 工作流及指令。行为对照由独立的 [Eval](eval.md) 执行，持续搜索更好的版本由 [Hillclimb](hillclimb.md) 管理。编写任务不自动开启长循环。

## Frontmatter 与调用

字段名按 [Claude Code 文档](https://code.claude.com/docs/en/skills#frontmatter-reference) 精确书写，拼错不报错，只会被静默忽略。本仓有意使用规范外字段；通用校验器或 claude.ai 上传报 `Unexpected key(s)` 时，不要为通过校验删掉它们。

- `description`：先触发条件与关键排除，再核心产出。全文不超过 250 字符，中文不超过 200 字符（尽量 100 左右），前 100 字符独立表达适用边界；这是本仓的写作目标，不是客户端的截断上限。
- `when_to_use`：补 `description` 没覆盖的同义说法、触发短语或示例请求，不重复正文条件；它是全表唯一用下划线的字段，写成 `when-to-use` 会被静默忽略。客户端把它接在 `description` 后展示，合并到 1,536 字符才截断，所以它不是放宽描述上限的理由。目标客户端不读该字段时不必加。
- `disable-model-invocation: true`：只用于有副作用或时机必须由人掌控的流程、需要显式进入的入口。代价是描述不进上下文，Claude 不能自动加载，也不能被 subagent 预载或被定时任务当作 prompt 运行；别用它掩盖描述的触发精度问题。已有的显式调用策略保持，不按个人偏好改。
- `argument-hint`：需要参数才加，用 `<必填>`、`[可选]`、`/` 分隔备选，与 [README](../../../README.md) 的参数提示约定一致；hint 只在补全时提示，正文仍要说明没给参数时怎么办。

新增或启用 frontmatter 字段后，同步 `test/skills/test_skill_metadata.py` 的字段白名单，否则 `npm test` 直接失败。

## 执行

决策入口：纠正重复错误读 [结构化学习](../principles/structural-learning.md)，安排渐进加载读 [上下文状态](../principles/context-as-state.md)，设计行为判定读 [验证器反证](../principles/falsifiable-verification.md)。

1. 明确目标请求、当前决策缺陷和预期行为。阅读参考 skill 与目标环境的格式、调用约定；保留用户已有调用策略，不能只因自身偏好改成自动或手动触发。新建 skill 时列出同领域已有 skill／playbook 的顶层硬规则，以同等显著度写进新 skill；只属于兄弟特定模式的规则不照搬。
   **融合前 review gate**：将参考 skill 的规则或流程融合到现有 skill 时，修改前向用户展示逐项清单：目标文件/规则、现有行为、参考来源/段落、拟采纳/改写/不采纳的内容、对现有原则与立场的影响、验证办法；涉及适用边界、调用策略、授权、接口或验收时明确说明。以现有原则为基线，冲突内容适配或拒绝；融合请求本身不授权改变原则、立场或调用/授权策略，尚未获授权的变更先请用户裁定，已有明确授权不重复确认。执行后对照清单核对 diff；新增行为变更先更新清单并处理冲突，不在融合完成后补交清单。普通修订未融合参考内容时不触发本门。
2. 若环境提供适用的 skill 编写能力，按其实际说明使用；否则直接维护 frontmatter、主体和必要资源。只写能改变决策的指令。
3. 将共通约束放在入口，将任务流程放进 playbook，将条件性方法放进 reference。每个链接说明何时读取，避免循环依赖和一次性加载全部内容。
4. 检查 frontmatter、文件路径、引用可达性、触发精度和冲突；被镜像进发布包的 skill（如 `phoenix-diagram` 的 bundle）要按该工具的构建流程重建并通过其检查，不能只改源码。沿真实请求追踪路由，确认不会把只读任务升级为写入、把普通任务升级为长期运行。
5. 对结构性行为变化分别检查发现／路由与执行：自然请求测试漏触发、误触发，显式加载测试实际行为；保留原调用策略。测试前确认实际加载的是被修改的版本，安装副本和插件缓存可能落后于源码，必要时让执行者直接读源码路径。准备原始材料，覆盖新能力、合法相邻场景及容易误触发的请求。维护本模式时可参考 [行为验收场景](../evals/scenarios.md)，通过 Eval 隔离判定标准并执行比较。
6. 根据真实观察到的错误做最小修订，再执行受影响检查。宣称规则生效需全新上下文按原请求重放，用例能区分新旧版本，且行为发生在读到新规则之后；指明改动再复判或单次冒烟只能说明可遵守、可达。若用户要求持续改进，则把目标、范围和当前版本交给 Hillclimb；一次性编写任务在交付条件满足后结束。

本手册不授权自行改全局指令、安装环境或发布 skill。修改与安装、发布的范围各按用户请求确定。

## 验收与退出

- 结构可加载，必要资源能找到，任务路由和授权边界一致。
- 每项验证声明标明实际执行到哪一层，未运行的场景不计为通过。
- 只有可比的真实行为证据支持时，才宣称优于旧版本或基线。

## 交付

skill 位置、改变的决策、验证方式与结果、未测试的能力。必要时附案例和失败证据，不只给规则摘要。
