# 将重复教训变成可执行约束

**触发**：同类错误或人工纠正重复出现，现有文字规则未能阻止问题。

## 决策

先解决当前问题，再确认是偶发事件、稳定模式还是目标改变。根据失败机制选择类型构造、schema、静态检查、测试、规范入口或自动化核对，把容易遗忘的要求放到执行位置。

依赖判断的规则保留简明指导和能区分误用的反例。确定机制已接管后删去重复说明，避免同时维护冲突的规则副本。保留教训的来源、适用边界、反例和失效条件；评测中暴露的失败是开发材料，不能继续冒充未见确认样本。

## 判据

重放原失败时新机制能识别或阻止它，合法相邻场景仍能通过。能指出规则的权威位置，修改时相关行为检查会暴露回归。

## 边界与反例

不是每次纠正都值得永久固化。持久偏好、全局指令或其他 skill 的修改需在授权范围内；不能从一个项目的要求推导所有项目都适用。

例如：证据文件会过期，就校验依赖与内容；反复加一句“请认真验证”无法检测旧日志。
