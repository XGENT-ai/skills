# 优化到达结果的关键路径

**触发**：选择并行方式、安排多阶段工作、积累大量待审产物，或尝试提高任务吞吐。

## 决策

先识别当前限制交付的是调查、实现、验证、集成还是外部等待。优先减少该环节及其依赖上的延迟，而不是增加所有环节的活动量。

只有独立且可集成的工作适合并行。先打通一个真实单元，再按实际审阅和集成能力增加在途数；产物积压时先消化队列。机械重复能由工具完成时优先使用工具。

## 判据

已验证并交付的结果更快增加，未验证库存、冲突与返工没有失控。进度来自实际产物和依赖解除，不来自活跃执行者或提交数量。

## 边界与反例

不能委派时串行采用相同依赖顺序。测量与复核属于必要工作，不能为了表面速度跳过。关键路径会随阶段变化，需要据当前事实调整。

例如：审查已成为瓶颈时再开十个分支会增加库存；完成当前集成并改善验证入口更可能缩短交付时间。
