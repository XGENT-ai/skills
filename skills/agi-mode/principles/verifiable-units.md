# 按可验证单元推进

**触发**：批量编辑、迁移、跨层实现，或安排多次提交与 PR。

## 决策

每个单元从已知输入出发，结束于一个可观察结果。按真实依赖排序：基线先于处理，必要基础先于消费者，原触发失败先于修复后的证明。

单元大小应让错误易于定位且结果有意义。一个行为需要同时改多个文件时作为一个单元处理，不把文件数当边界。单元未通过时停止依赖它的后续工作，独立工作仍可继续。

## 判据

能将回归定位到具体单元，证据能对应其输入与版本。集成后仍检查组合行为，不能把每个局部通过相加得出全局通过。

## 边界与反例

过小的单元会增加构建与协调成本，可以按风险合并成批。失败测试可作为开发过程的证据，但是否提交或合入失败状态遵守项目交付规则。

例如：先迁移一个真实调用方验证转换，再扩展批次；不改完几百处才第一次运行转换检查。

执行见 [重构与迁移](../playbooks/migration-refactoring.md) 和 [项目与队列编排](../playbooks/program.md)。
