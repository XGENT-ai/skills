# 用可核对的效果处理重试

**触发**：操作可能重复、崩溃、超时或在部分完成后恢复。

## 决策

以目标后置状态设计操作，明确如何识别一次逻辑请求。优先使用稳定操作标识、幂等键、原子状态转换与实际状态核对，使重复执行收敛。

超时只说明客户端不知道结果。先查询该次操作或目标状态，确认成功则继续，确认失败且可安全重试才重试；无法判定时保留未知状态。部分完成时采用已定义的对账、续作或补偿，而非假定整步没发生。

## 判据

在相关阶段重复调用或中断后恢复，检查不重复产生用户可见效果，也不遗漏应完成部分。记录能关联请求、远端结果和本地进度。

## 边界与反例

外部系统不支持幂等时，不能靠本地布尔标记宣称恰好一次。补偿不总能消除影响，发送过的消息、触发过的通知仍是已经发生的事实。

例如：部署请求超时后按操作 ID 查询，而非立刻再发一次部署。
