# 修改产生错误的机制

**触发**：正在调试、打算加保护分支，或同一症状在多个位置反复出现。

## 决策

复现后区分触发条件、错误状态和表面症状。沿因果路径寻找哪一步违反不变量，用运行观察或受控干预验证；修改负责产生该状态的机制。

在任务范围内查找共享同一原因的其他位置，不以相似文本代替同根判断。重启相关问题检查持久状态、缓存和锁，但保留原始证据；清空数据后症状消失还不是完整修复。

## 判据

原触发条件不再产生错误，相关路径也保持正确；修复位置与已证明的机制对应。临时缓解与根因修复分开报告。

## 边界与反例

故障止损可以先于完整修复，但不能因此结束用户要求的根因工作。边界拒绝非法输入是有效修复，内部随意吞错以隐藏缺陷则不是。

例如：重复定时器来自生命周期未释放，应修复生命周期；只提高触发阈值会留下累积问题。
