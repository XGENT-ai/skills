# 先消除共享写入，再协调必要共享

**触发**：多个执行者、线程、请求或作业可能修改同一个对象、文件、分支或资源。

## 决策

先判断是否真的需要同一个可变对象。独立事实由各自所有者发布，在读取或集成边界汇总；不要把无关状态塞进一个共享文件再要求大家小心。

必须共享的不变量采用单写者、事务、原子比较交换或正确锁机制。明确读取的一致性要求、更新顺序、失败恢复和所有权转移。锁的存在本身不证明这些关系成立。

## 判据

能够列出每个可变对象的写入者。通过相关并发交错检查不丢更新、不重复执行、不接收过期写入；迟到执行者不能覆盖新所有者的结果。

## 边界与反例

真实全局不变量不能简单拆成多个独立副本。共享内存只读、不可变快照也不需要为了“隔离”增加重复系统。

例如：各执行者写自己的报告，再由单个集成者更新总账；扣减同一库存则仍需要统一的原子约束。
