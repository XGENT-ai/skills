# 建造能放大执行或验证的工具

**触发**：重复工作、难以复核的操作，或现有能力不足以产生下一步所需证据。

## 决策

先完成一个真实样本，理解操作语义与错误边界，再选择最小 codemod、解析器、生成器、检查脚本或驱动。已有工具能满足时直接复用。

价值同时来自执行效率与复核能力，一次性任务也可能值得脚本化。比较构建、校验与维护成本，确定工具服务的当前目标；能够一次确定处理的工作不拆给多个执行者手工重复。

## 判据

工具在已知样本、错误输入和相关边界上得到检查，并实际推进原任务。会写入的工具能预览目标、控制范围和核对重跑效果。

## 边界与反例

不要为证明采用了原则而制造文件。两处直接可核对的修改未必需要工具；复杂操作也不自动值得通用框架。新工具继承原任务范围与权限。

例如：重复迁移用经过样本校验的脚本；一次查询现有日志不需要新建日志平台。
