# 先建立后续工作依赖的基础

**触发**：开始一个跨层功能、安排多阶段工作，或尚未确定关键数据与访问方式。

## 决策

先核实数据形状、主要访问路径、状态所有者和必须成立的不变量。选择能使后续逻辑直接表达这些关系的结构，再填充实现。

某项基础只有在后续阶段确实依赖它时才前置。例如先打通测试入口再修复，先确定共享协议再拆分调用方；不先建设假想框架、全套工具或未来扩展点。

## 判据

第一个真实切片能经过所选数据与接口，后续阶段不需要各自补同一条规则。基础能减少可见的依赖阻塞，成本相对于本次工作合理。

## 边界与反例

基础设计服务于已确定的使用目标。若关键问题是用户流程不明，先观察或原型，不先冻结一套精密类型。

例如：批量处理前先跑通一个真实单元与检查路径；不为三处局部文案改动搭建自动化流水线。
