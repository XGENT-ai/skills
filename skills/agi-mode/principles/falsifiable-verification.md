# 验证器必须能够拒绝错误

**触发**：新建关键验证器、异常漂亮的结果、不同候选测不出差异，或检查结果与真实体验矛盾。

## 决策

先验证观测链路的辨别能力。在隔离环境提供已知坏样本，确认它失败；提供已知好样本，排除永远失败的检查；核对实际命中代码、负载与输出。

验证器有缺陷时分开记录工具修订与产品修改，重跑基线和候选，并撤销依赖旧判定的通过状态。评价标准来自用户目标，不能由候选实现自行降低。

## 判据

目标行为被破坏时检查会拒绝，正确行为可通过。观测结果与真实入口相符，比较差异超过仪器或采样噪声。

## 边界与反例

坏样本只检验它覆盖的错误，不证明验证器完备。判断性评审也有不确定性，应利用独立证据和反例，不能为其编造绝对客观评分。已有可靠验证路径不必每次重新做完整校准。

例如：源码改成无条件成功，非法输入测试却仍绿，应先核对是否运行旧构建，不能接受这次修复。
