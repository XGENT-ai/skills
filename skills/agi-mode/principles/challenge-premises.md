# 失败重复时检验共同前提

**触发**：同一前提下两次有效尝试仍未解决问题，或新证据与当前解释明显冲突。

## 决策

写出所有失败尝试共同依赖的前提，先区分执行失败、观测失真和假设被否定。设计能直接检验前提的观测，再决定第三次修改。

按相关维度分解总体结果，例如参与者、生命周期、数据规模、时间或状态。出现不均衡时继续追踪分配机制，不能仅凭偏斜就断言需要轮换角色或加锁。

## 判据

新实验能够区分原解释和竞争解释；结果改变后续动作。前提被反驳时撤回依赖它的补丁，重新建立模型，而不是为旧结论追加例外。

## 边界与反例

两次失败是重新审视的信号，不是错误前提的数学证明。环境没有启动不算一次有效业务实验，也不需要硬凑两次才接受直接反证。

例如：增加缓存容量无效时，检查缓存是否跨请求存在；如果实例每次重建，第三次调大容量仍在重复错误假设。
