# 用可比较的方案解决设计分叉

**触发**：没有成熟先例，多个方案都可行，且选择会带来较大的后续成本。

## 决策

提出机制不同的候选，包含复用现有能力或移除问题来源的可能。先用硬约束筛选，再找会改变选择的未知；只为这些未知建立最小原型。

各候选使用同一场景、负载与判定标准。记录各自失败条件和长期成本。连续换名字或调整同一结构的参数不算探索了不同设计。

## 判据

能够说明某条实际证据为何支持选择、什么变化会改变推荐。原型只承担它真正测量过的结论，不承担未经验证的生产可靠性。

## 边界与反例

机械修改、目标明确的 bug 修复、约束只留下一个方案时直接实施。探索已有足够结论后结束，不为候选数量继续造方案。

例如：比较每次计算、缓存和消除重复调用，并核对失效语义；只改三种缓存容量无法回答是否该缓存。
