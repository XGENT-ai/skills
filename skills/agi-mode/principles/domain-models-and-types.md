# 让结构与类型表达领域约束

**触发**：状态组合复杂、形状假设重复，或签名允许语义混淆与不合法输入。

## 决策

按领域知识和状态归属组织模块，不简单按执行先后拆成多个重复规则的步骤。用合适的集合、索引、状态机、带区分标记的类型或小型边界消除重复判断。

存在不合法组合时改变构造方式；语义不同且容易混用的 ID 使用区分类型；外部数据经过真实解析再进入内部模型。协议已有权威 schema 时派生类型，避免维护第二份形状。

处理变体时利用语言的穷尽检查，避免用强制转换掩盖缺失分支。只有操作实际需要更强保证时才加强类型，不为描述得更精确而增加所有调用方负担。

## 判据

以前需要注释提醒的错误组合现在难以构造或会被检查拒绝。新增状态能暴露遗漏处理，现有正常输入仍可使用。动态语言可用集中构造和运行时验证保持相同不变量，不假称有编译期证明。

## 边界与反例

简单、局部且稳定的数据无需强行框架化。编译通过不证明运行时输入可信，内部可变状态也可能使旧保证失效。

例如：用 `open` 与携带完成时间的 `done` 变体替代可矛盾的 `completed` 和可选时间字段。
