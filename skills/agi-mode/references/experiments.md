# 实验与反证

仅在关键未知阻碍行动、多个解释竞争、持续优化或验证可信度不足时读取。已经有充分证据支持的局部修改不必走实验流程。

这里提供实验方法。比较完整候选使用 [Eval](../playbooks/eval.md)，持续生成并筛选候选使用 [Hillclimb](../playbooks/hillclimb.md)；方法参考不替代两者的运行记录和退出规则。

## 选择能改变决定的观测

先明确当前决定，再列出足以改变它的未知。实验的价值来自区分候选解释，而不是产出更多日志。

例：请求超时可能来自上游慢，也可能来自本地排队。先分别测量排队时间与上游耗时。直接提高超时阈值可能掩盖症状，无法区分这两个解释。

对一个实验只需说明：

| 项目 | 内容 |
| --- | --- |
| 假设 | 什么机制导致什么现象 |
| 竞争解释 | 还有什么机制能产生同样现象 |
| 干预或观测 | 改变或测量什么，保持哪些条件一致 |
| 预期区分 | 不同结果分别支持或削弱哪个解释 |
| 行动分支 | 结果出现后，继续、撤回还是换方向 |

不能写出结果如何改变下一步时，缩小问题或改用更直接的观测。调查任务保持只读；运行现有无副作用的检查即可，不为回答问题偷偷修改系统。

## 昂贵分叉：先购买信息

决定会影响大量调用方、公开接口或数据布局时，先找最容易推翻首选方案的场景。

1. 从真实约束提出结构不同的备选。无需为显而易见的小修改制造候选。
2. 优先比较既有机制能否满足目标，其次才考虑新增结构。
3. 每个原型只验证一个关键取舍，保持可丢弃，不提前做生产级包装。
4. 用同一用户场景比较结果，记录依赖条件和失败情形。
5. 选出足够好的方案后回到交付。原型不能直接冒充已验证的生产实现。

“上限探索”可以询问：如果移除最昂贵的同步、重复计算、错误状态或人工交接，原问题还存在吗？这只是待验证的设计方向。用一个局部证据决定是否值得深入，不据此跳过兼容性、数据语义和迁移成本。

## 先校验尺子

新建的测量工具、异常漂亮的结果、与真实体验矛盾的绿灯，都需要检查观测链路。

- **已知坏样本**：让检查面对必然违反目标的输入，确认它报告失败。
- **已知好样本**：确认检查不是因为环境或接线错误永远失败。
- **路径命中**：确认命令、测试或请求实际到达待检查的代码和数据。
- **版本一致**：确认缓存、构建产物、服务进程和被修改的源文件对应。

按疑点选择检查，不要求每次全做。坏样本在临时副本、独立测试或隔离环境中构造。

发现验证器错误时，先记录错误及影响。修复后重跑基线和候选；旧结论标记失效。若必须改变验收语义，回到用户目标重新确认，不能偷偷改口径。

## 持续优化：保护目标免受指标劫持

在首轮改变前确定代表性工作负载、指标方向、质量底线和比较条件。已有用户目标直接沿用；无法推导的关键取舍才提问。

测量有噪声时重复采样，并让基线与候选处于可比环境。报告采样方法与波动，不把单次幸运结果当作改善。负载差异很大时，分别比较相关场景，避免只给平均数。

每轮记录假设、改动、前后结果、回归结果与去留。判断顺序为：

1. 是否仍满足正确性、用户体验和约定的质量底线。
2. 改善是否超过噪声，且适用于目标工作负载。
3. 增加的维护和运行成本是否值得。

关闭日志、跳过校验、减少测试输入或改变响应语义，都可能让数字变好而目标变差。明确用户授权的取舍可以执行，但报告语义和成本变化，不能将其包装为无代价优化。

持续搜索时，按同源任务分组后留出未见最终确认集；反复用于选方案的验证分数属于开发证据。独立重跑只验证稳定性，不证明对新任务泛化。组合两个有效改动后重新测量；收益不保证可相加。具体可见性与采用规则由 Eval 持有。

## 连续失败：提升问题层级

同一前提下的两次有效实验仍失败时，暂缓第三次参数微调：

1. 写出所有失败尝试共同依赖的前提。
2. 核实失败发生在执行、观察还是结果本身。环境没启动，不说明业务假设错误。
3. 找能直接检验共同前提的观测。按数据、时间、状态、调用方、所有者或并发参与者切分，选择与问题有关的维度。
4. 当前提被反驳，重新建立因果模型；当前提仍成立，沿新的证据寻找原因。
5. 撤回失去依据的补丁，只保留独立有用且验证过的修改。

不要把“怀疑前提”固化为某一种根因。分布不均不必然意味着所有权错误；两次失败也不证明重写更优。

## 判断何时收敛

优先尝试成本低、可区分且尚未探索的路径。结果已经足以决定交付时结束探索。若新一轮没有改变产物、知识或后续成本，必须改变动作类型；无法提出有信息价值的下一步时，给出局限和恢复条件。

不要设任意最低实验次数来证明努力，也不要为了完成而移动成功门槛。
