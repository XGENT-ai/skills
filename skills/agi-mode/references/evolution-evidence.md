# 进化证据：样本、尝试与实际效果

用于从真实工作积累可复核样本，并在后续实践中评价进化方法本身。适用于不同被优化对象和效果环境；具体业务的阶段、字段和采集入口由实践案例定义，不成为本 skill 的通用要求。用户只要求积累数据时，不启动对比或搜索。

## 1. 分清三个层次

| 层次 | 含义 | 需要区分的证据 |
| --- | --- | --- |
| 进化方法 | 如何选信息、提出修改、验证、保留或撤回 | 观察到什么，基于什么假设采取什么变化，如何判定，花了多少资源 |
| 被优化对象 | 本轮允许改变的代码、skill、prompt、配置或流程 | 初始版本、候选差异、组合关系、实际采用版本 |
| 效果环境 | 使用该对象完成真实任务并产生结果的条件 | 输入、执行条件、产物、可观察效果、质量底线与成本 |

被优化对象有好结果，不自动证明进化方法有效；某次任务失败，也不自动说明对象或进化方法有错。区分原有能力、实际改动、执行偏离、随机波动和外部条件变化。归因不明确时保留假设，不制造精确贡献分。

## 2. 积累两类记录

**工作样本**保存真实任务如何发生、产生了什么效果。复用项目已有记录和原始材料，不以文字总结替代它们：

- 稳定样本身份、来源、与同源任务的关系；允许一个任务关联多个输入和下游结果。
- 当时的请求、已知约束、阶段信息截止点，以及可恢复的输入与输出版本。
- 实际使用的方法及可获取的模型、工具、环境条件；缺失标未知。
- 可观察结果、判定依据、原始证据位置及覆盖限制；区分首次、重试／补救后和最终结果。
- 后续反馈发生时间、针对的原版本、依据和替代关系；未知、取消、失败和环境无效分别保留。

**进化尝试**保存 agi-mode 如何利用样本改变被优化对象。复用 [Hillclimb](../playbooks/hillclimb.md) 日志和 [评测记录](eval-protocol.md)，补齐以下关系，而不另造一套台账：

```text
进化方法的版本与运行条件
  → 目标、可改表面、预算及本轮实际可见样本
  → 假设与来源证据、父版本、候选差异
  → 验证协议、实际运行与结果、资源消耗
  → 保留／撤回／未定／无效及理由
  → 最终独立确认与交付状态
```

只收工作样本，可以建立题库与失败假设；只有同时记录真实进化尝试和结果，才能评价方法是否成功利用了这些经验。不要根据最后版本反向编造中间假设、尝试次数或被否决方案。

## 3. 保持材料可恢复、时间关系可核对

在有意义的任务／阶段边界保全输入和输出，反馈后来到达时追加关联。当前工作文档可以持续更新；归档版本和原始结果不能被静默覆盖。

优先使用已有可取回的版本与稳定证据路径。hash 只能核对内容，不能恢复文件；可变、临时或可能消失的材料需要必要快照。记录真实起点中的未提交内容，不能只写 HEAD 或 dirty。保存范围限于任务所需且已授权的数据；不要求采集全部聊天、全部命令或内部推理，不自动上传、提交或访问其他工作区。

效果证据绑定它实际观察的输入、实现与环境。后续报告重写不改变旧证据属于哪个版本；成功重跑不能抹去此前失败。采集不完整时分别说明哪些结果可以复核、哪些起点可以恢复、哪些执行可以重放，不用一个“已落盘”代表全部能力。

## 4. 历史证据与候选效果的边界

- **历史效果复核**：重读已有产物与记录，可以确定原任务的已观测结果、证据缺口和改进线索。
- **代理验证**：候选在已知样本上改变了决策、输出或错误识别，可以支持局部机制假设；不能直接继承原任务的效果分。
- **实际效果验证**：候选参与新的可比执行，产生了新的效果证据，才能报告该条件下的真实变化。最终采用再遵守 Eval 的独立确认要求。

观察到坏结果时，核对问题在当时是否可知、目标是否中途改变、执行是否使用并遵循了被评价版本，以及验证器是否可靠。后来的纠正既不是自动正确标签，也不能倒推为当时已知输入。

分析者可读取允许用于开发的完整样本；候选只获得任务截止时可见的材料，后续结果与参考修复留在评判侧。同源任务及其变体保持同组，分组、隔离和确认集失效规则由 [Eval](../playbooks/eval.md) 管理。

## 5. 评价进化方法本身

先定义改进目标、质量底线、预算与独立确认方式，再运行实践。按任务性质观察：

- 相对初始对象，是否获得独立确认的有效改善，是否引入关键回归。
- 在同样资源条件下，取得这些改善付出的实验、验证、运行和维护成本。
- 假设是否有证据来源，失败后是否修正解释，能否拒绝有害修改并保存有效版本。
- 是否正确处理未知、失效评测、数据污染和停止条件；没有找到改进时是否如实报告。

假设数、规则数、评委赞同数或“保留”的候选数不直接等于能力。方法选择、测量和结论是否可靠需要核对实际记录；不能只依赖被评对象的自评。

将来比较进化方法时，保持被优化对象起点、任务分布、基础模型／工具和总预算可比，记录方法版本及其可见信息。一次实践只能支持对应条件下的结论；通用自进化能力需要来自不同任务族的证据，不能由单一业务案例外推。

## 6. 当前只做采集时的完成条件

已有材料可定位、关键版本可恢复、效果与版本关系可追踪，采集缺口明确。尚未开始的进化尝试留空，不预填成功状态，不以数据积累替代能力验证。业务案例的详细存储、采集和结果解释放在相应项目或仓库级评测材料中，保持 agi-mode 的通用性。
