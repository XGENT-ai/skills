# 评测协议与记录模板

在建立可复现评测或接续多轮搜索时读取。优先映射到项目现有格式；以下是最小内容约定，不是必须实现的框架。空缺标为未知或未执行，不用示例数值冒充观测。

## 协议：首轮前固定

```yaml
protocol_id: <version-or-content-hash>
question: <要决定什么>
objective: quality  # 或 cost_at_quality / simplicity_at_quality
baseline: <内容版本，包含相关未提交改动>
change_surface: <允许改动的文件或配置>
guardrails: <逐项底线与检查方式>
primary_metric: <名称、单位、方向、任务权重与聚合方式>
minimum_effect: <最小值得采用的收益及理由>
quality_loss_limit: <保质优化允许的最大损失；不适用时注明>
cases: <受控清单版本、来源、标签、独立分组与目标分布>
splits: <search / 可选 validation / confirmation 的组、种子与可见性>
grader: <版本、判定锚点、校准证据；若有 judge 则含模型与设置>
runner: <命令或真实工具入口、版本、环境快照、复位方式>
configuration: <候选模型、effort、工具、采样参数、缓存条件>
repeats: <每个任务的重复数与配对方式>
invalid_runs: <基础设施无效的定义、重跑规则与记录方式>
uncertainty: <估计单位、区间方法、置信水平与小样本限制>
adoption_rule: <keep / discard / inconclusive 的事前条件>
checkpoints: <何时查看结果、补测规则、最大候选与资源约束>
confirmation: <何时冻结、未见数据由谁持有、反馈暴露后的处置>
artifacts: <原始结果、轨迹、匿名映射与恢复点的受控位置>
```

模板存储位置并不提供隔离。评测侧持有完整版，给候选和搜索者导出各自可见的材料。按目标环境的真实权限验证隔离；没有独立 runner 时如实标记。

## 样本与逐次结果

每个样本至少有 `case_id`、`source`、`group_id`、`split`、`task`、必要的公开契约、预期可观察行为、适用标签。公开任务输入与评判侧答案分开；失败样本的同源变体保持同组。

每次执行一条 JSONL 或等价记录，包含：

| 字段 | 内容 |
| --- | --- |
| `run_id`, `attempt_id`, `protocol_id` | 唯一执行、搜索轮次与协议版本 |
| `case_id`, `group_id`, `split`, `repeat` | 任务、独立单位、集合与重复编号 |
| `candidate_id`, `candidate_hash` | 中性标签与内容版本；真实身份另存 |
| `environment`, `configuration`, `seed` | 可重现条件；不支持种子时标未知 |
| `status`, `reason`, `retry_of` | `ok` / `behavior_failure` / `infra_invalid`；重跑指向原记录 |
| `checks`, `score`, `grader_version` | 逐项判定与证据；无有效分数用 null，不伪造零分 |
| `tokens`, `cost`, `latency`, `units` | 资源消耗，未知用 null；超时记录已耗资源 |
| `artifact`, `trace`, `grade_evidence` | 真实产物、完整轨迹与判定依据的位置 |

`ok` 表示完成有效运行，不保证通过所有判定。有效行为失败计入预定分母；基础设施无效单独报告。结果摘要不能抹去重跑链。

## 差异判定示例

先统一方向：令质量差异 `ΔQ = Q候选 − Q基线`，令成本收益 `ΔC = C基线 − C候选`，因此两者均以正数为好。下面是可采用的一组保守规则，须首轮前选定；不是普适门槛。

- 质量优化：所有底线通过；`ΔQ` 的区间下界超过预设的最小实际收益。
- 保质降成本：`ΔQ` 的区间下界不低于 `−质量损失界限`；`ΔC` 的区间下界超过预设成本收益。还要检查失败率与关键任务，不让廉价失败降低平均成本。
- 区间覆盖接受与拒绝区域：`inconclusive`，按事前规则补测或结束为未定。不能把“未显著下降”当作质量保持。
- 确定性、可复现检查使用实际差异与底线，不强造置信区间；同样记录输入覆盖限制。

按独立任务或来源组做配对比较，在组内处理重复。若使用 bootstrap，同一抽样组中的基线与候选一起重采样，不把同题重复视作独立任务。区间只描述当前抽样与协议的不确定性，不自动覆盖分布漂移、错误 grader 或多候选选择偏差。

评价进化方法本身时，另关联进化方法的实际版本、运行条件、本轮可见样本以及原始尝试记录；被优化对象的候选版本不能代替方法版本。原任务的历史结果不能直接赋给新候选。样本与尝试的关系见 [进化证据](evolution-evidence.md)。

## 交接与续做

搜索侧记录 `initial_baseline`、`search_best`、`confirmed_best`、剩余资源、下个假设与恢复点；不要只记最后一次结果。每个候选关联父版本与补丁，跨轮比较同时保留对初始基线的累计差异。

Eval 返回给搜索者：协议／候选版本、有效性、底线、允许可见的分数与差异区间、成本、判定和证据引用。未见集合的逐题详情不进入该返回值。

最终报告注明样本与独立组数、重复数、实际与无效运行数、尝试总数、被选择版本及冻结时间、确认集是否真正未见、结果局限和目标是否达到。结构检查、纸面场景审阅、真实候选运行与独立最终确认分开报告。
