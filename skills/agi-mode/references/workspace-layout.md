# 状态目录与原文档边界

`.xgent-ai/` 是 agi-mode 的工作状态目录，开发生命周期的状态放在 `.xgent-ai/sdlc/`。**`sdlc/` 只放状态及其索引、协议、事件，不存放或复制 PRD、开发计划、评审报告、实施/验收记录、测试计划、日志、截图或原始证据。** 这些原产物的位置由用户习惯、项目约定与已有链接决定，本约定不改变各写作和评审技能的原文档落盘规则。

只读查询不创建目录；初始化和更新仅保存必要的状态文件，不为统一目录而搬迁或重命名原文档。

## 状态布局

```text
.xgent-ai/
  index.md                     工作状态总入口
  experience/                  开发经验收件箱，首次有效记录时创建
    index.md                   任务记录导航
    <task-id>.md              简短观察、证据链接及复盘处置
  tasks/                       非开发任务按需创建
    index.md                   任务目录
    <task-id>/
      index.md                 本任务状态文件入口
      state.md                 恢复状态
  sdlc/
    index.md                   分类导航与当前重点
    protocol.md                项目内可独立执行的状态回写协议
    state-model.md             固定状态、证据门槛与自愈规则
    event-template.md          单次状态变化记录模板
    status/
      index.md                 状态类型导航
      prd/index.md             PRD 状态索引
      prd/<object-id>.md       每份 PRD 的状态与原文链接
      plan/index.md            开发计划状态索引
      plan/<object-id>.md      每份计划的就绪、实施进度和记录链接
      review/index.md          评审状态索引
      review/<object-id>.md    每轮评审的结论、整改状态和报告链接
    events/
      index.md                 事件类型导航
      <kind>/
        index.md               对象事件目录
        <object-id>/
          index.md             本对象事件清单
          <event-id>.md        每次状态变化一文件
```

按需创建，不预建空对象。无计划的开发任务需要恢复状态时，可增加 `status/task/` 等状态类型，不为跟进强建计划；实验也只登记状态和产物链接，实验材料仍沿用户指定位置保存。

`experience/` 保存待复盘线索，不是 SDLC 状态或原始日志；收集由 `experience-capture` 负责，复盘由 `$agi-mode 复盘` / `$agi-mode reflect` 读取。只安装 agi-mode 也可读取已有记录，无需先安装收集 skill；用户指定或项目登记的已有经验目录优先，不双写。

## 每层目录索引

`.xgent-ai/` 下每个实际创建的目录都维护 `index.md`，包括根目录、中间层、对象事件目录、任务目录及后续归档/分片目录；不要求原文档所在目录采用本约定。新目录与其索引同批创建，旧状态目录缺索引时在获准维护范围内补齐，查询模式只报告缺失。

普通目录使用 [通用目录索引模板](../assets/directory-index.md)，SDLC 入口使用 [工作导航模板](../assets/sdlc/index.md)，对象分类使用 [类型索引模板](../assets/sdlc/type-index.md)。每层索引列出直接文件及子目录入口，子目录链接其 `index.md`；索引自身不自列，不在上层重复展开全树。目录用途、覆盖范围和维护规则入口随索引保存，非开发任务索引也保留维护约定，不依赖 SDLC 已初始化。

创建或改变目录内容的执行者负责同步索引；内容未改变去向时不逐级重写。新增、移动、归档、删除及多机合并的完整规则见 [协议：目录索引维护](../assets/sdlc/protocol.md#目录索引维护)。索引是可重建导航，不是进度事实、锁或不可变事件；事件枚举必须排除索引文件。

## 身份与来源

- 状态对象与事件使用独立 UUID；原文件不要求 UUID 命名、不嵌入台账编号，不因登记改名。每次实际评审有独立对象 ID，通过所审对象、范围、版本和报告链接区分轮次。
- `artifact`、`sources.path` 保存原产物的仓根相对路径或可访问的稳定 URL；Markdown 链接按状态文件所在目录计算。例如状态页可引用仓内 `docs/requirements/`、`goal/`、`design/` 或任意用户目录，不能假定原文在 `.xgent-ai/sdlc/` 下。
- 原文移动时先核实对应关系，沿用对象 ID、登记新旧路径并更新索引链接；状态整理本身不授权移动原文。跨机器按各自仓根解析路径，来源缺失标明未同步或不可核验。
- 状态只存简要事实、关系、版本/指纹、证据位置、阻塞及下一步。完整问题说明、验收步骤和运行日志留在原处，不在状态目录另存副本作为新事实源。
- 状态码按随仓保存的 [状态模型](../assets/sdlc/state-model.md) 固定，原文自述与证据质量单列。原计划状态行并非绝对真相；可用适用的实现、验证及处置证据纠正台账，保留差异与历史，不擅自修改原文。

## 增长与按需读取

- 每个对象独立状态页，计划页面链接各轮评审页面；不把所有 PRD、计划与历史塞进一个 `STATUS.md`。实施状态归对应计划，详细实现与验收记录继续按原计划链接读取。
- `sdlc/index.md` 列直接文件和状态/事件子目录入口，可快捷链接分类索引与当前重点。类型索引一对象一行，列 ID、标题、来源、状态页和活动/归档标记，不复制进度正文；归档标记须有来源，不按文件年龄推断。
- 类型索引过大时按领域或年份分片，父索引列全分片及范围。归档另列索引，保留原对象及事件；不要求搬动原文或历史记录，不截断列表冒充完整盘点。
- 查询先读分类索引，再读活动/指定对象及依赖；枚举对象和事件文件可发现遗漏，不默认全文加载全部历史。原产物从用户提供的位置、项目约定、已登记链接及仓内文档发现，不将状态目录当作唯一搜索范围。
- `.xgent-ai` 是隐藏目录，状态发现显式使用 `rg --files --hidden .xgent-ai/sdlc`（目录存在时）或等价枚举；原文在其他隐藏目录时同样显式定位。必要来源被忽略时说明限制，不擅自改变项目忽略规则。

## 已有台账与共享

状态台账位置按「用户指定 → 仓库明确登记 → 默认 `.xgent-ai/sdlc/`」确定。已有 `docs/project-status/protocol.md` 或等价台账沿原协议维护；新旧入口并存又无明确切换记录时先核对，不建立竞争台账或双写。

用户要求迁移台账时，只迁移状态资料：保留对象/事件 ID、历史结论、来源版本，转换相对链接并记录路径映射，核验后登记新入口。原文档不在迁移范围内；旧入口留指引，不同时维护两套状态。不可变事件的历史路径可通过映射解析，不改写历史 hash。

开发任务仍以原计划及实施记录为恢复入口，状态页只是跨对象索引；没有现有恢复记录时才按需补充任务状态。使用 [项目状态流程](../playbooks/what-next.md) 与 [可复制协议](../assets/sdlc/protocol.md) 回写。协议、状态页与事件可随 Git 共享，来源文件仍各按项目方式同步；状态已同步不代表源码、原文和证据已同步。
