# 先用是非题筛选，再决定要不要做昂贵的事

**适用条件**：第一步只读一小段证据，就能让大部分输入绕开取整份客户记录、调用慢模型或人工深审。若后续问题并不更贵，且只用同一段文本，应选[推测式并行提问](fan-out.md)：额外一轮没有省下工作。

**原例：共享收件箱。** 先只看来信，问一道 Noul：“发件人是否在等回复？”正例是有待答问题或明确请求；反例包括收据、通讯简报，也包括真人发的单纯致谢。不要先查订单再筛，否则最想省的查询已经发生。

| 第一步的 P(是) | 代码接下来做什么 |
| --- | --- |
| `< 0.30` | 归档，不读客户记录、不跑完整分诊。 |
| `> 0.70` | 查询客户及订单，再同批判断请求类别、紧急度和是否为重复联系。 |
| 其余，含两个端点 | 进入快速人工查看队列；既不静默丢弃，也不自动跑重流程。 |

**检验分流**：原例里「配件少了一颗螺丝，我用备用的装好了，知会一下」得到 0.44，不能仅凭它提到缺件就查订单；有交付期限、正在等货的来信得到 0.98，才需要读取订单。用团队自己的邮箱标注调阈值，尤其抽查被提前归档的邮件有没有漏掉真正的请求；同时比较减少的下游调用与新增的首轮延迟。

这里的 `noul` 是 Jev 的是非题。移植到其他供应商时读取“是的概率”，而不是“不论是或否，赢家有多确定”。来源：[TypeSafe · Screen with a Noul first](https://docs.typesafe.ai/patterns/noul-screen.md)。
