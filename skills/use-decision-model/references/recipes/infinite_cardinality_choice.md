# 从大目录中选一个：两次筛选，一次比较

来源：[TypeSafe 官方配方：Infinite cardinality choice](https://docs.typesafe.ai/cookbooks/infinite_cardinality_choice.md)

**输入与结果。** 一句模糊的寻片描述，每部影片的 ID、片名、年份、短剧情和长剧情，以及对应各轮的本地回执。结果是一部影片或一张短名单。目录可以很大，但最后一道 Choice 只比较读得下的候选，不把全集硬塞进选项。

| 轮次 | 状态和问题 | 应用怎么用答案 |
|---|---|---|
| 全库粗筛 | 状态为寻片者原话。每部片各一道 Noul：“要找的是《片名》（年份）吗？其剧情是……”接约 100 词的短剧情。 | 各片独立计分，按 `(-noul, id)` 取前 80；原例每块 300 题，分块只是为控制上下文，不在块内先淘汰。 |
| 长文复读 | 保留原话和同一命题，换成约 600 词的长剧情。关键场景可能在短摘要之后。 | 只读入围者；原例每块 40 题，合并本轮新分数再按 `(-noul, id)` 取前 20，不累加前轮分数。 |
| 候选决选 | 一道 Choice：“寻片者说的是哪部影片？”选项键用 ID，说明写片名、年份和长剧情。 | 记录 `choice`、`confidence` 和整份分布。展示顺序按 `(-probability, id)`，同分用 ID 固定顺序。 |

原例的展示规则是：`confidence >= 0.8` 时只展示选中影片；否则展示决选排名前三。前两轮的多个 Noul 可以同时很高；最后的 Choice 才让影片在同一组内竞争。0.8、候选数和分块大小都是该目录的示例配置，不是普适界限。

**手算。** 用户只记得“有人把寄错的明信片送回山顶”。两片的短剧情都写了送信，A、B 都入围；长剧情里只有 B 写到山顶。假设决选的概率排序是 B、A、C，而回包的 `confidence` 为 0.72，便展示三部。若首选仍是 B，但回包的 `confidence` 恰为 0.80，则只展示 B。不要用 `probabilities[B]` 替代这里的 `confidence`。

**核对。** 用已知片名分别数“进前 80”“进前 20”“决选第一”。若正确影片在复读前就消失，改短摘要或放宽粗筛，不要只调最终门槛。即使决选分布很集中，也不证明目录里一定有答案。
