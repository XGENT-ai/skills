# 严重程度与是否可信，是两根轴

**输入 → 输出：** 一条缺陷报告 → 人工分诊、待办、本迭代或通知值班。Score 的数值表示可能的影响程度，`confidence` 描述答案分布的集中程度，不是“该不该升级”。

1. 建五档有序尺度：纯外观问题、主要任务仍可完成、故障但有替代方案、核心任务无法完成、数据损失或大面积中断。只让模型据报告评定情形。
2. 先处置不确定性，再用分数路由。原例取 `confidence < 0.5` 人工分诊；其余 `score < 1.5` 进待办，`1.5 ≤ score < 2.5` 进迭代，`score ≥ 2.5` 通知值班。实际投用前用本地标注重定阈值。
3. 用一个反例检查顺序：「更新后笔记不见了，也可能是我删的。」原例回包 `score=3.19, confidence=0.34`。只看均值会通知值班；按设计应先问清是不是数据丢失。

若业务关心的是「用户被阻断的风险」，而不是“分值平均有多高”，可直接用 `P(核心任务无法完成) + P(数据损失或大面积中断)`，与允许的漏报代价比较。尤其要覆盖分布集中在相邻两档、而策略边界刚好切在中间的用例。

来源：[TypeSafe · Routing by confidence](https://docs.typesafe.ai/patterns/confidence-routing.md)。
