# 给选择题配一道“这些候选里有匹配吗？”

**问题**：一道必须选一个的 Choice 回答的是“相对最像谁”，不是“确实属于谁”。TypeSafe 原例中，用户投诉的是店里不卖的**台灯**，Choice 却以 0.96 选中**书桌**。把高分当作存在证明，就会派错产品团队。

让两道独立问题读取同一条消息与同一份产品清单：

- `product`（Choice）：如果只比较清单里的产品，消息最相关的是哪一个？候选写明确的名称及说明。
- `about_our_product`（Noul）：消息实际涉及我们清单中的产品吗？其他商家的产品、不在清单的服务或纯招聘来信都算否。这道题不引用另一题的答案。

先读是否匹配，再读赢家。原例的阈值如下，迁移时要用自己的样本重定：

```text
P(清单内有匹配) < 0.30                       → 通用收件箱，忽略赢家
P(清单内有匹配) > 0.70 且 P(赢家) > 0.70    → 派给该产品团队
其余（含端点）                               → 人工分流，赢家只作提示
```

台灯来信的存在分只有 0.02，所以即使书桌得 0.96 也进通用收件箱。反过来，能肯定是自家产品、却分不清哪一款时，要走人工而非查无匹配。只加一个 `other` 会让它和具体产品争夺同一份概率，难以区分这两种情况。

多款产品可同时命中时，改成每款各问一道是非题。若要判图中目标，能返回框的接口也可同批独立问存在性，未命中就不消费坐标。这里的两题是**同批**问；若目标是为省成本而跳过下一阶段，看[先筛后查](noul-screen.md)。
