# 恢复丢失的文档格式，不改写内容

**输入**是一份硬换行、丢失标题和项目符号的纯文本备忘录；**输出**是 Markdown 和块到原行的映射。模型只判断边界和类型，最终文字始终由代码取自输入。

**第一遍：断行是否切开了句子？** 给非空行依次编号 `L000`、`L001`……，保留行前是否有空行。用带编号的全文作上下文，对没有空行隔开的每对相邻行，引用两行原文同时批量问：“下一行是否接着上一行尚未说完的那句话？”取肯定概率 `p`。不要问“是否同一段或同一话题”，同一清单的几项往往话题相同，却不应合并。

按原顺序组块：第一行或空行后的行必开新块。否则看上一行，若以句末标点结尾（原例 `. ! ? : ; …`，可跟闭引号或括号），示例合并线为 `p >= 0.5`；悬空结尾为 `p >= 0.2`。达到才接到上一块，保留所用行号。英文硬折行用空格连接；处理中文时让标点识别和连接方式匹配原文。

**第二遍：每个块是什么？** 新编 `B000` 等块号，把整篇块序列交给决策模型。一次为每块单选“标题、正文、列表项、引文、代码、提示框”，并预问附属题：“若是标题，是文档标题、大节还是小节？”“若是提示框，是注记、建议还是警告？”以及二元题“这是必须按顺序做的一步吗？”只用命中类型所需的附属答案。原例只给不长于 90 字符的块问标题级别，缺省级别用大节。

**渲染由代码完成。** 标题级别映射到 `# / ## / ###`；正文照录，引文加 `>`，提示框加对应的 `> [!NOTE]`、`> [!TIP]` 或 `> [!WARNING]`。连续代码块合并加围栏，只展示不执行。连续列表项成一组，整组的“顺序重要”概率**均值 ≥ 0.5** 才编号，否则用 `-`。这里的数值都是示例策略。

**手工回放**：原文四行依次为 `Participants`、`The following teams will`、`attend:`、`Design`，第五行为 `Support`。只给第二、三行的续句判定高分，其余低于各自合并线。所得四块应依次渲染为标题、完整引导句 `The following teams will attend:`、两条独立无序项，而不是一段团队名称。逐块检查行号是否按序且无遗漏，类型置信度低的块可单独标注待核，不重写句子。
