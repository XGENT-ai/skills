# 分类不够确定时，返回上一级

一家企业可能刚出售一个业务部门，报告里出现两个行业，并不代表两个都还是主营业务。这里不要求模型再猜一次，而是让代码决定答案该有多具体。

**输入**：本地报告正文、四位 SIC 行业代码及名称、行业大类区间表。**输出**：`{level, label, group, confidence}`，其中 `group` 始终记录原选项，`level` 明示对外报告的粒度。

1. 把四位代码当字符串，按前两位分组，保留前导零；以组 ID 作候选键。每组用总称（若有）和若干成员行业名描述。由区间表建 `division[group]`，例如 `20–39 → 制造业`。原数据整理为 75 组、10 个上级大类。
2. 在同一道本地 `Choice` 中列出所有组，问：“报告描述的这家公司自己正在经营哪种业务？”不要把客户所在行业、旧业务、计划业务当作答案。从响应读取获选组、全分布及 **Choice 的 confidence**；它反映分布集中程度，不等于最高概率，也不是让模型自报把握。
3. 代码只查获选组的上级，不汇总概率另选上级，也不再发问。以下 `0.90` 是原例阈值：

   ```text
   g, c = answer.choice, answer.confidence
   若 c >= 0.90：返回 {level: group,    label: g,           group: g, confidence: c}
   否则：        返回 {level: division, label: division[g], group: g, confidence: c}
   ```

例如把两份离线响应交给同一函数：`(28, 0.96)` 报组 `28`；`(38, 0.20)` 只报“制造业”，保留 `38` 供追溯。粗类不够下游使用时，后一条应交人核实，而不是冒充精确匹配。

**核对**：用有实际申报代码的留出样本，比对“始终报组”和“低信心报大类”。报组的按两位代码判对，报大类的按真实组的上级判对，同时报告两种粒度各占多少。只看总命中率会掩盖变粗的代价。
