# 给读者评分找可复用的问题

假设一批虚构的桌游说明已由读者按“是否容易上手”评分。与其让模型再猜一个总分，不如寻找能解释预测误差的细问题。模型负责提题、读文本；哪些题值得留下，由未参与提题的数据决定。

**输入**：本地说明、评分、版本族 ID、固定的数据划分；以及本地保存的候选题、逐行回答和提案记录。**输出**：保留的题文与量表、编码列、每次增删改的误差账本和一次最终留出集比较。只有少量样例时可手算编码，不据此宣称发现了有效特征。

1. 同一桌游的不同版本放在同一组，再划分可读集、检查集、最终留出集。提议者只能读可读集里的文本、评分与折外预测偏差，不能读检查样本或测试结果。比如几篇“逐步讲了规则，却没说谁先行动”的说明得分被高估，可提议新增“是否指明第一步由谁操作？”（Noul）。也可改写含糊题或删掉无用题，但不能用某篇说明的专有词识别该样本。
2. 回放每行文本对应的一组模型回答，输入不给评分。存在性用 `P(是)` 一列；程度用五级 Score。例如“示例在多大程度上演示了完整一轮？”从 0 无示例到 4 完整逐步演示，若 2、3 级各占一半，期望等级为 2.5，标准差为 0.5。把这两列输入回归器，而非把 2.5 当成读者评分。改了题文或量表即换版本；缺相应回答的提案标记未评估，不沿用旧列。
3. 以有变化的首批问题建基线。在可读集与检查集合并的开发集做固定折的交叉验证，每行预测来自未训练该行及其版本族的折。只用检查行的折外 RMSE 判定后续每一项增、改、删；同一折、同一回归器（原例为 CatBoost），才能比较差值。将可读行的典型残差及开发集特征重要性反馈给下一轮。预设提案预算与最小改善，预算耗尽或连续尝试无改善即停。

**账本算例（虚构）**：约定误差至少降 0.01；首批 RMSE 为 0.52。加“是否指明先手”后为 0.49，保留；再加“是否用了感叹号”后为 0.488，拒绝。若某题在开发集几乎恒定，记为无区分度，跳过它。没有更多本地提案就到此结束。

**验收与局限**：锁定题组后在开发集重拟合，在同一最终留出集比较开发均值、原文回归、直接问总分（仅用开发集校准量尺）、首批题和最终题的 RMSE。按相同留出组配对比较，微小差距可能只是抽样波动；不得看了结果再回去挑题。原例的礼貌度任务在一次运行中从首批题的 0.471 降到最终题的 0.456，不是桌游任务的预期收益。读者评分反映该批读者的偏好，重要列不是因果解释，也不评价作者本人。
