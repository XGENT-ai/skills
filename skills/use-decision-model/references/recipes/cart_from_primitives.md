# 从点单原话组装购物车草稿

**输入**：顾客原话、本地菜单；**输出**：按提及顺序排列的商品，每项含菜单 ID、商品置信度、字段及各自置信度。菜单是允许选择的全集，不让模型发明商品、价格或规格。

例如 `latte` 的描述可写“拿铁、奶咖”，字段为 `size=[小,中,大]`、`milk=[全脂,燕麦,杏仁]`。另列 `filter_coffee`、`blueberry_muffin`、`almond_croissant`，各有独立描述，后两种糕点没有可选字段。

**先找商品，数量事先未知。** 保持原话不变，每轮用尚未命中的菜单 ID 和描述生成单选，另加 `nothing_else`（剩余候选都没被点）。问题列明已命中项：“还点了哪一种？若还有多种，选原话中最先提到的那种。”代码控制循环：

```text
剩余 = 菜单的副本；已选 = []
最多 6 轮（示例硬上限）：
    剩余为空则结束
    答案 = 本地单选(原话, 已选, 剩余 + nothing_else)
    若选 nothing_else：结束
    在剩余表中查出该 ID，记录 ID 和置信度，并从剩余表移除
```

**再填字段，字段事先已知。** 对每个命中商品按菜单定义生成一组单选，与原话一起判定。例如同时问“这杯拿铁点了哪种杯量？”“这杯拿铁要哪种奶？”每道题只给本字段枚举和 `unspecified`（顾客没说）。无字段的商品直接得到 `{}`，不再问。代码按商品、字段 ID 拼装结果；两种哨兵不能混用：`nothing_else` 停止找商品，`unspecified` 只留空一个规格。

**手工回放**：“一杯大杯燕麦拿铁，再来个蓝莓松饼”。商品选择应依次为 `latte → blueberry_muffin → nothing_else`，草稿包含 `latte {size: 大, milk: 燕麦}` 和 `blueberry_muffin {}`。若只说“拿铁”，两个字段都应为 `unspecified`，不默认中杯或全脂。命中即移除，所以“两杯拿铁”在本方案里仍只有一条，不能当作数量已识别；达到轮数上限也不等于已确认点完。此步骤只返回草稿，不提交订单或扣款。
