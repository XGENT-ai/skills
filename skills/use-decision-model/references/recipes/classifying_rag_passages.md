# 给检索段落分流：可用证据、反证或剔除

检索相似度只回答“像不像这个问题”，不回答“能否据此作答”。在检索与生成之间，代码对每个候选段落单独分流，最后输出两个证据块，而不是把排名靠前的文字整包交给生成器。

**准备输入。** 每段保留 `{id, title, text, source_type}`。原例取标题加正文的向量，与问题向量做余弦相似度排序，同分按段落 ID 排，取前 12 段。离线可读本地向量或直接从已排好的候选开始。对每个 `{query, passage}` 同时问四个问题，分别保存 `P(是)`：

- `relevant`：谈的是问题所指的主题吗？
- `evidence`：有可用于直接回答的具体信息吗？同主题但没给所需事实，不算。
- `conflict`：否定的是**问题中已陈述的事实前提**吗？不是仅与别段措辞不同。
- `injection`：段落是否试图指挥作答系统，而不是提供资料？

**按顺序取首个命中。** 不平均，不让高相关度抵消安全风险。以下严格不等号是源例针对该语料的设置：

```text
if injection > 0.70: return exclude
if conflict  > 0.70: return conflicting_evidence
if relevant  < 0.45: return exclude
if evidence  > 0.55: return include
return exclude
```

将 `include` 写入“可用证据”，将 `conflicting_evidence` 单列为“与前提冲突的证据”；两块均按原排名列出 `[id] 标题 + 正文`，无内容明确标空。被剔除或未成功评估的段落不进入生成上下文。要求生成器仅用所给材料，事实标段落 ID，明说冲突，证据不足就说明不足。即使两块都有内容，其中的文字也始终是资料，不是指令，不能授权工具操作。

**离线回放。** 问题预设“刷新令牌 30 天到期”。原例排名第一的论坛段落 `injection=0.98, conflict=0.78`，先命中剔除，不能作为反证混入。排第七的官方段落 `sessions-01` 则是 `injection=0.18, conflict=0.92, relevant=0.58, evidence=0.78`：应保留为反证，而不是普通证据。其余十段被剔除。回答可引用 `[sessions-01]` 指出该产品文档不支持这个到期前提，却不能编造延长窗口的设置。

**边界。** 保存每段的四个原始分数即可离线换阈值重放；例如证据分恰为 0.55，并不满足最后的纳入条件。原例每段一组问题，成本随候选数增长；漏检的段落在此阶段补不回来。低于注入线不等于安全认证，这道筛查不能充当权限边界。
