# 同一份证据，提前问分支问题

**输入 → 输出：** 一条工单 → 分类队列、该队列需要的字段，以及跨队列的优先响应标记。适用于后续问题的证据已经在工单中、只是暂时不知道会走哪条分支的情况。

一次请求共享工单正文，发送五道彼此独立的题：Choice 分「缺陷、账务、建议」；Score 判缺陷影响；Noul 判是否给了复现步骤；Noul 判是否明确请求退款；Score 判挫败程度。在问题里提到具体工单，不写「依据上一题」——同批问题读不到彼此的答案。

```text
类别是缺陷 → 只读影响和复现步骤；按两者决定进缺陷待办还是升级
类别是账务 → 只读是否请求退款；把请求标给账务，不直接退款
类别是建议 → 记录建议，忽略缺陷和退款字段
所有类别   → 挫败程度可独立决定是否优先回复
```

验证时给出一条「希望支持暗色主题」：即使模型也返回了一个缺陷影响分，代码也不应因此建缺陷工单。若完整分诊要另查账单、调用慢模型或交给人，且大多数工单不需要这一步，则改用[先筛后查](noul-screen.md)。合批节省往返，并不意味着增加问题没有 token 成本。

来源：[TypeSafe · Speculative fan-out](https://docs.typesafe.ai/patterns/fan-out.md)。
