# 聊天过滤：先描述消息，再决定怎样显示

**输入**：本地聊天记录，每条带频道标题、游戏名、用户和消息原文。**输出**：每条的类别分布、两项风险概率，以及本地预览动作。模型不删除消息、不处罚账号。

对同一条记录同时问三题：

- **主目的是什么？** 单选 `question`（真心求信息）、`hype`（欢呼、刷表情）、`conversation`（一般交谈或有用链接，亦作兜底）、`backseat`（未经请求指导操作，即使写成问句）、`spam`（未经请求的推广）。重复表情本身不是广告。
- **是否针对他人侮辱或骚扰？** 二元题，取肯定概率 `toxic`。
- **是否透露当前游戏的剧情或结局？** 二元题，取 `spoiler`。与主目的分开问，一条普通闲聊也可能剧透。

由代码按优先级分配动作，两个 `0.70` 都是示例阈值，不是平台标准：

```text
规则 = {question: 高亮, hype: 显示, conversation: 显示, backseat: 隐藏, spam: 隐藏}
若 toxic >= 0.70：隐藏，原因=骚扰
否则若 规则[获选类别] 是隐藏：隐藏，原因=类别
否则若 spoiler >= 0.70：模糊，原因=剧透
否则：采用该类别的规则
```

**离线回放。** “这一段音乐叫什么？”若结果为 `question, 0.02, 0.04`，则高亮；若一句闲聊是 `conversation, 0.03, 0.95`，则模糊；相同剧透分若属于 `spam` 则隐藏，而不是降为模糊。按输入顺序保存结果，切换“安静模式”只需把欢呼改为隐藏、闲聊改为淡化，重放规则即可；若改问题、游戏上下文或模型则不能复用旧判定。

在自己的已标注聊天里检查阈值附近和前两类接近的消息，必要时标记待审。只有游戏名时能判断“像不像剧透”，不能判断主播是否已玩到该处；后一要求必须提供实际进度。
