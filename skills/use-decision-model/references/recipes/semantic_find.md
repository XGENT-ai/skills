# 逐行语义检索：把“看哪一行”和“有没有答案”分开

来源：[TypeSafe 官方配方：Line-by-line search](https://docs.typesafe.ai/cookbooks/semantic_find.md)

**输入与结果。** 给定本地文档、一个问题，以及同一文档版本上两道题的回执。输出文档级结论（已回答／部分涉及／未回答）和带 ID、原文、相关分的证据行。

1. 按可引用的行或条款切分，从零编号，拼成 `L000| 原文`、`L001| 原文`……作为共享状态，并保留 ID 到原文的映射。用户问题放在两道题的指令里，不改文档。
2. `where` 用 **Choice** 问“哪行包含这个问题的答案？”每个行号是一个选项，说明留空，文字已在状态中。`exists` 用 **Noul** 问“至少一行是否明说或直接蕴含答案？”正例要求有依据，完全没涉及为反例。两题看同一份全文，但分工不同。
3. 从本地 `where.probabilities` 按文档行号取分（原例缺键取 0），降序展示前几行，同分让前面的行先出。独立读取 `exists.noul`：原例 `>= 0.70` 为已回答，`< 0.35` 为未回答，中间为部分涉及。刚好 0.35 仍属部分涉及。门槛要按自己的文档核准。

**手算。** 馆规的 `L000` 写“常设展免费”，`L001` 写“周末十点开馆”。问“周末有免费导览吗？”即便 `where` 给 L000 分配 0.82，若 `exists` 为 0.12，结果仍是“未回答”；L000 至多是相关文字，不能据此说导览免费。Choice 的概率之和为 1，无答案也会有第一名。

**边界。** 原配方的一道 Choice 最多容纳 255 个选项。更长文档先按窗口选择，再在选中窗口内排行；保留全局行号供引用。窗口内的最高分不能替代对答案是否存在的判断，尤其不能把漏选窗口解释为全文没有答案。
