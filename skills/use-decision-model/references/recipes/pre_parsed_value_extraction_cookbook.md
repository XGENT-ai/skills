# 从原文候选中选值，不让模型重写号码或金额

**输入**：文档和字段角色（“回执发往哪里”，不是笼统的“邮箱”）。**输出**：命中的原文、规范化值、判定置信度，或明确的 `none`。

1. 代码用适合该格式的正则或本地解析器尽量找全原文片段，按出现顺序去重。比如在美式票据中用 `[$€£¥]\s?\d[\d,]*(?:\.\d{2})?` 找带币符的金额。给候选编号并保留 `编号 → 原字符串`；不按大小或出现顺序预判角色。
2. 让决策模型读取全文，选项为“编号：原值”，另加“没有一个符合”。问：“这些金额中哪一个是最终应付额？”代码只允许从候选表复制所选字符串；选 `none` 或无候选则不解析。原文没被找进候选时，后面的选择救不回来。
3. 将角色选择与规范化分开做：

   | 字段 | 具体问题 | 代码怎么处理 |
   |---|---|---|
   | 邮箱 | 同一组地址分别问“哪个是发件地址？”“发件人要求把回执寄到哪个？” | 按两个选择分别回取原文；示例对地址做小写规范化。`To` 不一定是正文指定的回执地址。 |
   | 电话 | 从总机、传真、手机中选“哪个是直拨手机？”并单选“办公室在哪个国家？” | 将选中的原号和受支持地区交给本地号码解析器，例如 `(415) 555-0177` 与 `US` → `+14155550177`。地区无证据或解析失败就待核。 |
   | 金额 | 分别选“应付总额”“已抵扣额”；另选币种，并针对每个已选金额问“这是抵扣或退款，而非收费吗？” | 按文档数制解析 `Decimal`，币种与收支性质另存。原例 `P(抵扣)>0.5` 才记作抵扣，此为示例分界。 |

**演算**：原文“明细合计 $70.00，抵用 $10.00，美元应付总额 $60.00”。候选依次是三个原串。总额选第三项，币种选 `USD`，应付记录为 `Decimal('60.00'), USD, charge`；抵扣选第二项，记 `Decimal('10.00'), USD, credit`。这里是抽取已写明的总额，不是重新结算或付款。

**核对边界**：`1,315.50` 与 `1.315,50` 不能用同一套去标点规则；先确定小数符约定，不能确定就待核。选项过多时（原接口最多 255 项，包含兜底），先选段落再选片段；人名没有可靠格式时，改用本地名册或实体识别提供候选。
