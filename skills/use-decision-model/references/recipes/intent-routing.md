# 按意图概率路由：认出意图不等于同意执行

**输入 → 输出：** 一条自然语言指令 → 支持人员、只读页面、澄清问题或待确认页面。适用于相同入口既能查询也能发起高影响操作的场景。

1. 对指令问一道 Choice：「用户在查询余额，还是想查看待确认的转账？」另留未支持的意图；如果无匹配很常见，同批用一道 Noul 问「是否属于这些业务」。
2. 取赢家和 `probabilities[choice]`。这是所选意图的概率；不要换成其他模型的同名 `confidence` 再使用原阈值。按错误代价为每个分支定门槛。
3. 原例的策略如下。`p = 0.90` 时仍走澄清，超过才展示明细。这些值是示范，不是银行策略：

```text
不支持的意图或 p < 0.70          → 转支持人员
查余额且 p ≥ 0.70               → 鉴权后显示余额
转账意图且 0.70 ≤ p ≤ 0.90       → 追问是否要查看待确认转账
转账意图且 p > 0.90              → 显示金额和收款人，请用户确认
```

即使「那个转账……嗯，好吧」被打出很高概率，也只说明它指向转账，并非用户核对了明细。验证时让同一意图分别落在阈值两侧，再输入一个未支持的操作；所有路径都不能仅凭模型答复完成转账。

来源：[TypeSafe · Routing by probability（原 Intent routing）](https://docs.typesafe.ai/patterns/probability-routing.md)。
