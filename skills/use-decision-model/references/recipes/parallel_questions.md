# 一份公告，三个互不依赖的问题

要判断一份公告是否值得人工细读，可以一次读同一份文本，分别判断事实、类别和强度。选题的检验很简单：删掉另外两问，剩下的一问能否原样作答？“若上一问选延期，新的日期是哪天”不适合同批，应拆到下一步。

**输入**：本地公告、带稳定 ID 的题表，以及同一文本和模型版本下保存的逐题或整批回答。**输出**：按题 ID 排列的答案表；若有两种方式的多次独立记录，再输出按题比较表。不具备记录时，下面的虚构公告足以手工走通流程，无须联网。

> 原定周一的排练改至周四；舞台组与合唱组都需要重新登记。

| ID / 类型 | 只根据公告作出的判断 | 输出示意（非实测） |
|---|---|---|
| `register` / Noul | 是否明说需要重新登记？ | 是的概率 0.96 |
| `change` / Choice | 排练是取消、改期、照常，还是未说明？ | 改期，最高概率 0.94 |
| `scope` / Score | 影响范围：0 未点名组别、1 一组、2 两组及以上 | 期望等级 1.8；除以最高等级 2 得 0.90 |

**离线处理**：固定公告字节、问题措辞、选项顺序和模型版本。从记录中按 `(方式, 重复编号, 题ID)` 对齐；缺任一项就标记缺测，不以零补齐。Noul 比较是的概率；Choice 同时比较胜出标签与最高概率（两个相反标签都可能是 0.94）；Score 仅在等级定义相同时比较归一化分数。整批与单题各自在每道题上算均值和样本标准差，不跨题平均。只有一份记录就只报单次差值，不把重复读取同一缓存当作独立重复。

**核对与取舍**：先按原句核对“改期”，再看合批后是否换标签、越过业务阈值或比单题重复波动更大。用记录中的输入、输出 token 和同一份单价计算费用；单题串行耗时才可相加，并发则应比较实际墙钟时间。官方原例在一份长文上以 13 题各跑 5 次，串行单题费用约为整批的 12.2 倍、时间约为 11.8 倍；不是其他文长、模型或并发方式的承诺。两种方式一致也不表示答案正确，这张表用于筛读，不替代对公告的核实。
