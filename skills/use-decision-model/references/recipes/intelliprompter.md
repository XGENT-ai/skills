# 演讲清单：只给尚未讲完的要求打分

来源：[TypeSafe 官方配方：Intelliprompter](https://docs.typesafe.ai/cookbooks/intelliprompter.md)

**输入与结果。** 把演讲提纲拆成要点，每个要点可含多条验收要求。每条有稳定键、供演讲者阅读的短标签和供评分的具体描述。输入按时间排列的本地转写片段及每轮 Score 回执，输出原提纲顺序的勾选状态和各项最后得分。不需要麦克风或实时转写服务。

**如何评分。** 每轮把新片段接到全文末尾。对每条未勾选要求问一道 Score：“截至现在，演讲者把这项要求讲到了什么程度？”共用**累计全文**，不只看最后一句。五档依次是未提、略提或间接提及、直接提及、大体讲清、讲清且有实用细节。原始分是 `Σ(档位序号 × 该档概率)`，序号 0 至 4；展示分加 1，因此可以有小数。原例用展示分 **≥ 2.5** 作为覆盖条件，这是清单规则，不是模型置信度。

```text
covered = 空集合；latest = 空表；全文 = ""
对每个新片段：
    追加到全文；pending = 全部要求键 − covered
    若 pending 为空：结束
    读取本轮针对全文和 pending 的本地回执
    对每个 pending 键：
        latest[键] = 原始 Score[键] + 1
        若 latest[键] >= 2.5：将键加入 covered
最后按提纲顺序展示；一个要点的全部要求都在 covered 中才勾选要点
```

**手算。** “说明用途”要点有两条要求：说出工具名称、举出至少两个应用场景。第一轮两项原始分为 2.1、0.4，显示 3.1、1.4，只勾名称。后面先讲课堂，再讲产品演示；第二个场景出现时，累计全文才同时具备两个例子。若此时场景项原始分为 1.5，显示 2.5，刚好勾选，整个要点完成。

**核对。** 下一轮的问题里不应再出现已勾键；保存它上次的分数，不把缺席当零分。允许一轮勾零项或多项。若把离线回放接成实时界面，只在文本变化且上一轮已结束时开始下一轮，防止较早的回执覆盖新状态。
