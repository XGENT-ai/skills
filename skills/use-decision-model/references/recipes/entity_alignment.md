# 专辑记录对齐：给出关联建议，留出待核对的一档

来源：[TypeSafe 官方配方：Knowledge graph entity alignment](https://docs.typesafe.ai/cookbooks/entity_alignment.md)

**输入与结果。** 输入已配对的两条目录记录，各含标题、艺人、年份、厂牌；这一步不负责从两个全库找候选。每对记录的本地回执应有一个有序 Score 和三个诊断用 Noul。输出建议为“不关联／送编目员复核／建议 sameAs”，不直接写入知识图谱。

把两条原始记录并排作为 `entity_a`、`entity_b`。四道题共享这个状态：

| 问题 | 判别依据 |
|---|---|
| `link_state`（Score）：“这是怎样的两张专辑？” | 0＝不同专辑；1＝关系密切但身份未定，如再版、合辑、现场版、特别版或标题有歧义；2＝同一专辑。中档不是简单的“模型没把握”。 |
| `same_title`（Noul） | 标题是否相同？忽略大小写、标点和转写差异。 |
| `same_artist`（Noul） | 是否同一主艺人？允许文字系统、姓名语序不同，以及同一主艺人增列合作者。 |
| `same_label`（Noul） | 厂牌简称或地区分部可以算同一厂牌；子品牌与母公司不算。`-` 和 `[no label]` 表示未记录，不是两个相同厂牌。 |

**分流。** 只用 `link_state.score`。若回执给三档概率，则分数为 `s = 0*p0 + 1*p1 + 2*p2`。将 `s` 取到最近一档，正好居中时向上：`s < 0.5` 不关联，`0.5 <= s < 1.5` 复核，`s >= 1.5` 建议 sameAs。这两处分界源于本例三档刻度，不是概率门槛；不要对三个 Noul 投票，也不拿 `confidence` 替换 `s`。

**手算。** 两个标题只差一个空格，艺人与厂牌一致，发行年份相差很远。若三档概率分别是 0.10、0.55、0.35，`s=1.25`，应送复核。编目员可以沿年份查再版，而不是因艺人分高就合并。年份在共享状态里，若要列出年差可用普通代码比较两边非缺失的年份，无需第四道 Noul。

**核对。** 把目录已有的 `known_same_as` 留到分流后再对照，不给模型看。优先复核“建议关联但无既有链接”或“不关联却已有链接”的样本；目录可能重复或错链，一致率不是人工核验的准确率。
