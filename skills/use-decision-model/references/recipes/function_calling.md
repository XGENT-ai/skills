# 把自然语言请求变成有类型的候选函数调用

先构造调用，再决定是否执行。输入是用户原话、代码注册的函数表，以及一份说明每个函数和参数含义的规格。输出不是一段可执行文本，而是 `Call(name, kwargs, decisions, confidence)`。离线时用本地保存的选项概率或手填分数代替模型回答即可。

**从签名出题。** 去掉类型外层的 `Annotated` 和可空包装，忽略返回类型。用一道 `Choice` 问“用户要看价格走势、比较收益，还是查看可选标的？”，选项只能来自注册表。再为所有函数的封闭参数出题，题号带函数名前缀；一次评估全部题，解码时只读获选函数的题。

| 签名 | 具体问法 | 代码如何填参 |
|---|---|---|
| `Literal[...]` | “要看哪个时间跨度？”给 `1mo`、`3mo` 等原值配上语义说明 | 取概率最高的枚举值 |
| `list[Literal[...]]` | 对每个标的分别问“用户要把它纳入比较吗？” | 收集所有 `P(是) >= 0.5` 的成员，不是只留第一名 |
| `bool` | “用户要在图上显示成交量吗？” | `P(是) >= 0.5` 为真，否则为假 |

规格可给参数再配一道 `stated` 题：“用户明确指定了时间跨度吗？”若 `P(是) < 0.5`，直接从 `kwargs` **省略键**，不是传 `None`；否则照常填。相同候选集也应问清角色，例如“被衡量的标的”和“作为基准的标的”不能混用。整数、日期、自由文本不靠这套题填写：原例的整数 `limit` 保留函数默认值；若是没有默认值的必填参数，先补齐，不调用。

**离线走一遍。** 对“比较 NVDA、AMD 近三个月的收益”，假设函数选择概率为 0.96，两只标的入选概率为 0.95、0.91，其余各不超过 0.10；时间被明确指定的概率为 0.88，选中 `3mo` 的概率为 0.97。若没有更弱的判断，得到 `compare_returns(symbols=['NVDA', 'AMD'], window='3mo')`，整次置信度为 **0.88**。记录每个实际分支的概率质量：选中或为真取 `p`，排除、为假或省略取 `1-p`。整次取函数与所有分支的**最小值**，而不是乘积；源例只在展示单个参数的综合把握时乘起该参数的分数。

**检查与回退。** 用“最近 AMD 是否跟着 NVDA 走”检查角色与省略：原例选滚动相关，基准为 NVDA，未指定的跨度和粒度沿用默认值。`0.5` 是该例的解码界线，不是执行授权线。封闭枚举防得住非法值，防不住选错合法值。缺答、弱项或歧义应返回候选及需要澄清的字段；只有应用代码核实注册表、签名、调用权限与适用的确认条件后，才调用实际函数，不执行模型生成的代码。
