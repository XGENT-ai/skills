# crd · 提出方的跨项目协作需求文档

CR（Change Request）的文档称为 CRD，承载协作需求、**Q&A 问答澄清**与回复历史。默认整份文档往返：提出方形成需求，接收方在文末追加答复并返回完整 CRD，提出方整合后续谈；独立消息是补充输入。

```formal
INTENT:
  GOAL: independently_readable_and_answerable_crd
  SUCCESS: ["谁需要另一方提供什么、为什么、怎样算满足、哪些事项未达成一致均明确",
            source_grounded_current_view, preserved_response_history]

RULE @role_routing:
  MUST: ["从上下文确定双方项目、协作目标、文档路径及当前代表的角色；角色不明且影响动作时询问，不直接把当前仓库认作提出方",
         "按角色选技能，不按收到文档或追加回复等动作词选；反问或补充不互换双方角色",
         =>[representing_receiver, "定位并读取可用 crd-respond，包括原样追加其已拟答复；停止提出方流程，缺技能则说明，不虚构调用"],
         "多方参与时逐条注明责任项目，不假设同仓、同版本或同发布节奏"]

RULE @collaboration_scope:
  MUST: boundary_contract_only
  MUST_NOT: [design_receiver_internal_implementation,
             "把写文档当作发送请求、接受需求或启动开发的授权",
             "未经用户另行明确授权，通过邮件、聊天工具或项目系统发送 CR"]
```

## 1. 定位本次动作与事实来源

| 本次动作 | 读取与处理 |
| --- | --- |
| 发起或修订 | 读简报、相关代码/接口文档及已有 CR，形成可答复条目 |
| 提出方补充或答复澄清 | 核对接收方反问、替代方案及条件，文末追加本方澄清、补充或有依据的确认；未授权表态标草案，不替接收方接受或承诺 |
| 整合返回 CRD | 读返回稿、发出基线、本地当前稿，按 §4 核对增量并同步摘要，不让用户另摘已有回复 |
| 收录独立回复或续接 Q&A | 先读完整 CR 与最新往返，再对照来信/聊天/评审材料收录实际回复，保留发言归属并同步摘要 |

```formal
RULE @source_fidelity:
  MUST: ["只询问会改变需求对象、范围或答复归属的缺项，其余标待确认并继续可确定部分",
         "区分本方观察、对方陈述、推测和待核实事项；每项事实有文件/段落、接口文档或消息日期与发言方等可定位来源",
         "原消息时间与整理时间分记，未知人员、日期及排期如实注明"]
  MUST_NOT: ["因本方找不到能力断言对方不存在", fabricated_replies_or_counterparty_positions]
```

## 2. 写出对方能逐项处理的需求

新建时读取 [CR 模板](assets/cr-template.md)，按实际规模删去不适用内容；更新既有 CR 时沿用其结构与编号，不强制重排。路径优先使用用户指定或仓库已有约定；没有约定时用 `docs/cr/CR-<主题短名>.md`。先查同主题文档，避免续谈时另建一份。

```formal
RULE @stable_identifiers:
  MUST: "R-01 / Q-01 / RESP-01 分别标需求、问题、往返记录；沿用已有编号，新条目递增，撤销号不复用；它们是本地追踪号，不冒充外部系统 ID"

RULE @request_contract:
  SHOULD: ["每条可独立答复和验收：角色/条件/动机、当前阻碍与影响、可观察请求、双方配合、非目标和前置均明确",
         "契约只展开相关输入/输出、字段语义、权限、错误/重试、兼容版本及交接；已有约定标来源，未定设计标提议",
         "验收写前提 → 动作 → 可观察结果及必要失败行为，并写验证方、环境或交付节点，可用具体示例",
         "优先级有影响与理由；提出方期望、接收方估计、明确承诺分开，不编造截止日"]
  MUST_NOT: [vague_acceptance, "把小请求扩成完整 PRD 或强制对方采用未达成一致的内部方案"]
```

## 3. 维护 Q&A 与当前结论

```formal
RULE @current_view:
  UNLESS: verbatim_append_only
  MUST: ["Q&A 逐条保留问题、关联需求、提问方/待答方、是否阻塞及阻塞步骤、当前回答/待确认点、状态与答复链接；未知答案明确待答，建议标建议",
         "部分回答只更新对应项，未答项继续待答；已回答不等于已接受，已接受不等于已交付",
         "单方新范围、替代方案、时间仍是待确认提议；一致结论须有有权限一方的明确确认，需要双方确认时保留双方依据",
         "新旧答复冲突时列出影响，仅有明确撤回或替代依据才采用新结论，否则待澄清，不按时间覆盖承诺",
         "需求/问题/答复互引；问题关闭有实际回答及必要确认，CR 关闭有约定范围验收证据或明确拒绝/撤回理由",
         "正文写当前已确认需求与验收，未确认变更留提议/待决项；正文与历史差异可追到依据，历史保留当时原意"]
```

## 4. 整份 CRD 往返与文末答复

### 交付给对方的版本

```formal
RULE @handoff_version:
  WHEN: preparing_handoff_version
  MUST: ["保持 CR 标识，注明当前版本与本轮基于版本；沿用既有约定，无则可用 v1、v2 等交接版本",
         "交付完整需求、Q&A 与全部往返，关键内容不只链接对方不可访问的本地文件；接收方保留原需求与历史，文末追加答复，范围/验收修改先列建议",
         "用已有文件或版本控制保留可定位的发出基线，不为每次编辑造副本；未实际发出称待发送版本，有用户提供的发送事实才记已发出"]
```

### 整合返回文档

```formal
WORKFLOW @merge_return:
  TRIGGER: returned_crd_integration_requested
  DO: ["核对 CR 标识与版本关系，基线齐备时比较返回稿、本地稿各自增量，缺失时按 @missing_versions 处理；文件名或新时间不证明新 CR 或覆盖权",
       "文末已有答复保留或并入一次，不将整份返回稿再粘为新回复；来源定位返回文件/版本/章节，保留原发言方与时间",
       "对需求、验收、Q&A 结论或历史的直接修改列差异与影响；未确认实质变更留作提议/冲突，不静默变成共同基线；历史更正用追加记录",
       "合并双方无冲突增量，冲突保留双方意见与待确认项，不丢本地补充；编号碰撞保留来源版本限定（如 v2-甲方/RESP-02）及明确映射"]

RULE @missing_versions:
  WHEN: returned_crd_integration_requested
  MUST: [=>[sent_baseline_missing, "仍整理可识别答复，说明无法完整核实正文改动"],
         =>[local_version_missing, "可将返回 CRD 作当前工作稿，保留来源与未核实范围，不声称已完成版本合并"]]
```

### 追加规则

```formal
RULE @response_history:
  MUST: ["所有轮次按收录顺序追加到文末‘往返答复记录’，其他章节在前；双方发言用同一格式，收录不等于代答",
         "每轮有 RESP 编号、发言方/项目、原消息时间（未知注明）、整理时间、来源、关联 R/Q、内容、未答项及下一步",
         "拟答复标‘草案，未发送/未确认’，收到答复标‘已收到’，不推定双方已认可",
         "原文与已读材料一致；概括标整理摘要，保留条件、否定、例外与承诺边界；长原文可链接原件并保留关键答复",
         "更正以新记录引用旧编号、差异与依据，不改写或删除历史；可按 @current_view 同步正文",
         "追加前按来源标识及内容去重；有新增条件的相似消息另记并注明变化",
         "逐项对应 R/Q；不能可靠归属则标关联待确认并保留原意；允许同步当前视图时，为新反问建 Q 编号并链接本轮",
         =>[verbatim_append_only, "只追加原文与必要标识，不重写需求或采纳方案；仅获整理、同步或续接要求时按证据更新当前视图"]]
```

## 5. 回读与交付

```formal
REVIEW:
  CHECK: [@role_routing, @collaboration_scope, @source_fidelity, @stable_identifiers,
          @request_contract, @current_view, @handoff_version, @merge_return,
          @missing_versions, @response_history]
  ALSO: ["核对本次改动及关联位置，编号唯一、引用和相对链接可达，无未答项、部分接受、冲突或时间条件丢失",
         "草案、提议、已收到、已确认、验收完成不混用；修改仅涉及本次 CR，文档检查不冒充业务验收"]
  EXPOSE: on_issue

OUTPUT:
  FORMAT: markdown
  MUST: ["交付文档链接、本轮新增或变化结论、仍待谁回答的阻塞问题",
         "未实际发送则说明‘文档已保存，未发送’；只落盘不增设发送审批"]
```

## 调用示例

```text
使用 $crd，为订单项目向账号项目提出批量查询用户展示名的协作需求。
使用 $crd，站在提出方订单项目，答复账号项目的 Q-02，在文末补充查询用途与已有确认。
使用 $crd，站在提出方订单项目，这是账号项目返回的 CRD，请与上次发出版本及本地当前稿核对，整合新增回复并更新 Q&A。
使用 $crd，把下面收到的账号项目回复收录到订单项目的 docs/cr/CR-user-display-name.md，并同步需求与 Q&A 当前状态。
使用 $crd，作为提出方，将本方这段补充原样追加到现有 CR 末尾，保留正文。
```
