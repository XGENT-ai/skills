# Files 代成员保存（用户模式）

文件要存进本 App 的应用空间、由 App 掌控（用户删改不得），又要让作者本人在文件管理里看得到时读取。
用户要「另存到我的空间」、自己能删改的，用令牌交换出的用户态写个人/团队空间，不用本文。

## 1. 写入

基址为去掉末尾 `/` 的 `PORTAL_BASE_URL` 加 `/svc/files/api/v1/files`，令牌是本 App 服务账号的服务态 TDT（`files.write`）。

- 新建时带 `onBehalfOf=<userId>`：`POST /presign` 放 body，`POST /content`（请求体就是字节）放 query，
  `POST /closed-uploads` 放 body。不传 `spaceId`，文件落你自己的应用空间、仍归你，只是记下署名成员。
- `onBehalfOf` 是成员的**门户用户 id**——该成员门户令牌自省结果里的 `user_id`。**不是你 App 自己的用户主键**。
- 只有应用空间的所属 App 能署名：用户态令牌、写进别的 App 的应用空间（哪怕有 editor 授权）一律
  `VALIDATION_FAILED`（`details.field="onBehalfOf"`）。
- 写入前 files 向门户核实此人是本租户**在职**成员：非成员或已停用 → `VALIDATION_FAILED`；
  门户不可达 → 503 `PORTAL_UNAVAILABLE`，不写入，稍后重试。
- 署名写入时确定，之后不能改；replace 出的新版本继承署名。已写入的未署名文件补不上署名，
  要让作者看见只能带 `onBehalfOf` 重新新建一份（新 fileId），再删掉旧的。

## 2. 谁能看、谁能动

| 角色 | 权限 |
| --- | --- |
| 你（所属 App） | owner：改名/移动、删除、replace、标签、`PUT /:id/content` 原位覆盖 |
| 署名成员 | viewer：在「应用存储 › 我的应用文件」看、预览、下载；**不能**改名、删除、替换、打标签、分享 |
| 其他成员 | 看不到 |
| 租户管理员 | 默认看得到；平台为该租户打开「成员内容隐私」后只剩容量（个数、字节） |

「我的应用文件」按目录收起，你的目录约定（比如把媒体放 `/media/`）会原样出现在成员面前。

## 3. 对齐成员内容隐私开关

用服务态令牌调 `GET /app-spaces`，读你自己那一条的 `memberPrivacy`。为 `true` 时，把你 App 里
「看全部」一类的角色也收窄成「只看自己的」——否则租户管理员给自己授一个「看全部」角色就绕过了平台开关。
应用空间在第一次写入时懒建，还没写过时列表里没有你的那一条，那时也还没有任何署名文件。
开关在 files 侧最多 30 s 收敛。
