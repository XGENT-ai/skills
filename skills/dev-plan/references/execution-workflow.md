# 依赖与并行调度：写计划与评审时用

写计划时细化里程碑的依赖与并行边界、评审时核对编排能否安全执行，读本文件。实施者不读它：实施需要的并行、回写与记录约定已原样写进计划的「实施者定位」「实施进度」两节（见 `plan-skeleton.md`），改这里的规则时同步改那两节。

## 并行执行

每次调度前检查依赖与当前工作树。有独立任务、工具可用且并行收益超过委派与集成成本时，使用 subagents；主 agent 处理不冲突的任务或集成准备。小任务直接完成，不为凑数量拆任务。

### 哪些任务可同时启动

- 前置成果已通过所需检查，输入/接口契约已稳定；依赖落到实际成果与检查 ID，不默认等待上游里程碑全部终验。数据/安全/发布风险门及用户约定的分期门不能绕过。
- 区分开发、集成和终验前置：稳定契约下可先用 fixture 开发；真实接口可用后再联调，同环境的 API/UI 主路径集中走查。局部检查通过不代替阶段终验，集成与评测放明确的收口里程碑负责。
- 写入的文件集合互不重叠，不会在另一个任务仍依赖的文件中改接口/导出/行为。共享类型、公共入口、锁文件、生成产物和迁移序号指定一个负责人，先确定契约或串行集成。
- 测试和运行资源互不影响：共享数据库、种子/迁移、端口、开发栈重启、同一浏览器会话或外部环境写入需隔离或串行。独立 worktree 只能隔离文件，不能自动隔离这些资源。
- 无法证明独立就先串行完成前置或重新划界。用户要求串行、工具不可用或资源受限时如实说明，按可用并发数调度，其余串行，不虚构已启动的 subagents。

### 委派、交付与集成

主 agent 给每个 subagent 一份精简任务说明：目标及章节/需求/检查 ID、已稳定契约、可写与禁改路径、运行资源、需回报的阻塞。不复制整段聊天或无关历史；工具支持时选择最小上下文，让 subagent 按需读取规则和相关文件。

**模型默认继承**：如无特别要求，subagent 使用与主 agent 相同的模型。启动工具支持继承时省略模型覆盖参数；必须显式指定时填写主 agent 的模型。只有用户或适用指令明确要求其他模型时才覆盖，不自行因任务难度、成本或速度降级/换模型。

每个文件同一时间只有一个写入者。**计划与里程碑记录由主 agent 单写**；subagent 返回结果、改动路径、验证命令/环境/基线/结果与缺口，主 agent 归入对应记录，默认不另建任务文件。复杂交接或证据确需独立保存时才指定任务记录路径并链接。任务结束、阻塞或暂停时及时交付；不得替其他 agent 修改文件或回滚他人改动。边界变化先回报，主 agent 调整分工后再继续。

主 agent 审查交付与 diff，完成里程碑规定的检查；已通过且相关代码、配置、依赖、输入与环境未变的证据可引用，受影响检查重跑，收口仍做必要集成回归。有任务失败则保留成果，只阻塞依赖任务。里程碑完成立即回写，下游只需部分成果时保存其前置检查证据即可推进。结束对话前收集或停止尚在运行的任务，记录可接续状态。
