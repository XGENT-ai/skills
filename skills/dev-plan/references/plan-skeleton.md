## 写作自检(发出前过一遍)

- [ ] 决策表每行都有「含义」——只写选择不写影响的决策等于没做。
- [ ] 每条取舍都有**代价**字样;每个排除项都有去向。
- [ ] 每个上游契约要么「已核实(路径)」要么列了精确增量——没有第三种状态。
- [ ] 里程碑表每行「验证」列非空,最后一行落到全量回归 + 真实环境走查。
- [ ] §6 安全清单每条能对应 §7 的一条断言。
- [ ] §11 映射覆盖全部原始需求 + 项目硬约束 + 排除项。
- [ ] 已知坑节搬运了相关历史教训。
- [ ] 交叉一致性:机制用到的凭证/scope 在配置清单中存在;验收断言与设计相符;承诺的不变量互不冲突;新增标识符(错误码/导出/env/部署值)都有登记点;同一口径的多处提及逐处对齐。
- [ ] 上游行为级核实:分页推进/限流数值/claims 形状/密钥域/事务语义——计划依赖的行为与代码实际一致,不止"文件存在"。
- [ ] 闸门顺序与错误面:多道闸写明顺序,承诺的错误码 = 第一道会失败的闸抛出的;权限位从 UI 可见性到服务端真闸逐跳追通。
