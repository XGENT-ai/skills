# 仓库来源创作

图要解释真实仓库时读本文件。源码是职责、调用、边界与持久化的依据；请求的含义全部覆盖、每条断言都有来源支持时，图才算完成。只读用户指定的仓库与切片，不全仓扫描，不 fetch、不改仓库，也不调托管 API。

## 按需阅读

1. **固定身份。** 在目标仓库记录 `git rev-parse HEAD`、`git remote get-url origin` 与 `git status --short`。origin 若含 HTTP(S) 用户名、密码或 token，先去掉再写入 candidate（工具会拒绝带凭据的 URL）；保留其传输方式、端口、路径与 `.git` 后缀，不把内部 SSH 地址改写成 HTTPS。把去凭据的 URL 与 40 位提交写进 `meta.repository`。SSH origin、非 GitHub/Gitee/GitLab 托管、只需本地链接或测试用仓库时设 `link_mode: "local-only"`；只有 GitHub、Gitee、gitlab.com 或声明 `provider: "gitlab"` 的自管 GitLab HTTPS 地址能生成网页链接。来源按固定提交的已提交字节核对，不按工作树：工作树有改动时，工具对与固定提交不同的被引文件记 `worktree-differs`，答复中仍须列出这些改动路径。
2. **划定切片。** 用项目说明、manifest、入口、注册与部署配置定位相关运行单元，读入口、配置和与请求相关的模块。沿 import 与调用点追到该职责实际的输入、输出或副作用；读一小段相连的切片，不为找方便的标签扫描整个仓库。
3. **追踪归属。** 运行与 I/O 关系取自调用点上实际的执行者、操作和目标；部署与信任关系取自对应配置或执行处。区分发起操作的控制者、执行它的运行时和接收字节的存储。文件或数据库边的来源必须指向实际读写者；“负责维护任务”之类的职责描述不能证明直接 I/O。已配置的提供方、注入的适配器、本地 stub 与持久服务是不同断言，只标来源支持的那一个。
4. **边读边记来源。** 每个组件和重要关系记下仓库相对路径与闭区间行号。沿实际分支、重试、回退与错误处理走；导出或配置了但正常路径不调用的函数是可选能力，不是必经边。关于权威状态变更或控制归属的断言，要追到实际写入或执行处及其允许条件。
5. **写明不确定。** 把未解决的问题写在受影响的断言旁，例如“这里调用了 `writeFile`，持久性未知”。继续读下一段相关源码解决它，或作为明确的未知保留；不把标签、包描述或配置值变成未观察到的服务或行为。

每个请求的职责、关系与边界都有来源支持，剩余未知不会改变这一覆盖时停止阅读。没有节点、边、引用或卡片数量目标。用带原始行号的方式读源码（如 `nl -ba <file> | sed -n '40,90p'`），从显示的行号抄写引用起止行；摘录读到文件末尾时写实际末行。

## 各图型的来源

只有主要元素写 `sources`，每个至多三段：Architecture 组件，Workflow、Dataflow 与 Tree 节点，Sequence 参与者，Lifecycle 状态，ERD 实体，Class 类型，Timeline 事件，Waterfall 跨度。关系、消息、流与转换没有来源：把调用、写入或转换处引在拥有它的元素上（调用方、写入方、离开的状态），其余依据写进 note 或卡片。目录节点引用自己的 README 或入口文件，否则引用定义或运行它的文件。

Timeline 事件引用固定提交里记录它的文件（如 changelog 条目），时间取自该历史中的 tag 或提交；只有日期的记录写在该偏移的 12:00 并设 `precision: "day"`。不在该历史中的 tag 或提交不能引用。没有记录 trace 的 Waterfall 用 `meta.evidence: "illustrative"`，时长保持示意标注，不为计时去运行项目。

## 交付与答复

```sh
"$PD" finalize <type> candidate.json diagram.html --repo-root "<仓库根>" --json
```

`--repo-root` 必须是该仓库的顶层目录。核对只读：校验 origin 与声明一致、固定提交存在、被引文件与行在该提交中存在，并逐段比较工作树文件（不跟随符号链接）。缺少 `--repo-root`、git 不可用或超时、提交或对象缺失、文件缺失、行越界、工作树不同，或旧版 git 遇到部分克隆时，对应来源记为待核实并附原因；HTML 照常生成，来源状态不改变四门结论和退出码。

读回执 `evidence.status`：`verified` 表示全部来源已核对且每个主要元素都有来源；`partial` 表示部分核对；`unverified` 表示零条核对；`none` 表示没有声明仓库也没有来源。答复中列出待核实元素及原因、未提供来源的元素和工作树改动路径，不把非 `verified` 的图称为已核对。工具只证明“路径与行在固定提交中存在，且作者读到的工作树与之相同”；引用内容是否支持断言，由作者按上文纪律负责。
