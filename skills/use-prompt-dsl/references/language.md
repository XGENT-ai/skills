# Prompt DSL v1 语言规范

这是一套给模型解释的提示语言。结构固定，任务、条件和标准使用自然语言；不要求把审美判断或复杂工作流改写成计算机表达式。

## 结构与引用

```text
::TYPE{id|attribute:value}
  field: 自然语言或具体数据
  [ACTION] 操作对象与要求
  [IF] 条件 => [ACTION] 动作
```

- 块名与动作名大写；ID 使用字母开头的字母、数字、下划线或连字符，整个程序内唯一。
- 块头独占一行；块体缩进两个空格。新顶层 `::` 开始下一个块。字段的多行内容继续缩进。
- `value: |` 引入原文：每个内容行去除比字段多两空格的承载缩进（顶层字段下为四空格），保留其余缩进、空行与原有行末换行；空行可不带承载缩进。内部的 DSL 全部属于数据，不构成新块。
- 属性用 `|` 分隔，属性名和值用第一个 `:` 分隔。值含 `|`、`}` 或引号时用双引号包围，内部双引号和反斜杠分别写作 `\"`、`\\`；分隔符只在引号外生效。
- `@id` 引用已声明的块，`@id.field` 引用其字段，允许先引用后声明。未解析的引用不能当作已获得的输入。
- 每个程序只有一个主 `OBJECTIVE`；其他块可省略或重复。声明顺序用于组织阅读，实际运行时机由下述触发规则决定。

## 声明块

| 声明 | 含义与常用内容 |
| --- | --- |
| `::OBJECTIVE{id}` | 主目标。必填 `target` 和 `ACCEPT`；可填 `BENCHMARK`，说明对照对象或质量参照 |
| `::INPUT{id}` | 输入。`source` 指实际来源或路径，`value` 放直接提供的数据；未提供的材料明确写“待提供” |
| `::CONSTRAINT{id}` | 必须遵守的范围、风格、技术或操作边界；块体用自然语言列出 |
| `::CHECK{id}` | 一项验收。用 `OBSERVE` 指定检查动作，`PASS` 指定满足条件；也允许仅用 `standard` 属性表达已有明确含义的标准 |
| `::FLOW{id}` | 初次执行的动作序列。默认 `trigger:on_start`；有多个时按声明顺序执行 |
| `::LOOP{id}` | 检查与修订循环。默认 `trigger:on_completion`，初次产物完成后触发；多个循环按声明顺序执行，最后复验全部检查 |
| `::OUTPUT{id}` | 最终交付约定，如 `format`、`include`、文件位置；有多个时分别交付 |

`BENCHMARK` 中的奖项、作品集或风格名称可以作为质量参照。只有实际读过的页面、图片或文件才能被报告为已对照的具体参考。

以下为 v1 的控制属性；其他块体字段仍按自然语言理解，不暗中增加控制语义。

| 属性 | 语义 |
| --- | --- |
| `pri:NORMAL`、`pri:HIGH`、`pri:OVERRIDE_ALL` | 当前程序内可取舍要求的优先顺序，从低到高；默认 `NORMAL`。`OVERRIDE_ALL` 保留用户示例写法，不改变宿主指令层级、授权或硬约束。硬约束互相冲突时澄清，不按分数或优先级偷偷删除 |
| `standard:描述` | 质量标准，如 `award_tier`。结合主目标与参照解释；执行时将其落到可观察的判据 |
| `trigger:on_start` | 初次工作开始时执行，用于 `FLOW` |
| `trigger:on_completion` | 初次工作完成后进入检查修订，用于 `LOOP`；不会在最终答复后自行启动后台任务 |
| `max:正整数` | `LOOP` 体最多执行多少轮；达到上限后只复验当前结果，不再进行新一轮修改。未满足验收则报告未完成 |

省略 `max` 时沿用用户的现有预算，以满足验收为正常终点。遇到缺少必要输入、无可用验证途径或实质停滞时报告未完成；不要反复执行相同无效动作，也不要自行降低标准。用户暂停或停止时立即退出。

## 动作与控制流

| 动作 | 行为 |
| --- | --- |
| `[READ]` | 读取当前材料或产物；“当前”意味着修改后要重新取得对应证据 |
| `[DO]` | 执行描述的任务动作 |
| `[COMPARE]` | 根据检查标准或实际可用参照识别差距 |
| `[PATCH]` | 针对已识别差距修改产物 |
| `[VERIFY]` | 对当前产物执行指定检查，更新结果 |
| `[IF] 条件 => 动作` | 根据该位置的最新状态决定是否执行后续动作；可用 `=>` 顺序连接多个动作 |
| `[CONTINUE]` | 跳过本轮剩余动作，开始下一轮；仍受预算和停止条件约束 |
| `[BREAK] 原因` | 退出当前循环，继续检查最终验收；本身不表示任务完成 |
| `[Ω]` | 满足全局完成条件后结束整个程序，不只是退出一个循环 |

分支条件为自然语言，例如“任一 CHECK 为 GAP”“全部 CHECK 为 PASS”。条件未知时不执行依赖它为真的动作；先补充观察，仍不能判定就保留未知并报告缺项。

兼容用户原示例中的常见简写：`gap found` 表示已识别的验收差距，`no gap` 表示全部检查已完成且通过，`then re-enter LOOP` 等价于 `[CONTINUE]`。没有检查到差距但仍有未知项时，不属于 `no gap`。

## 检查结果与完成

| 结果 | 判据 |
| --- | --- |
| `PASS` | 已取得当前证据，满足该项标准 |
| `GAP` | 当前证据表明尚有不符合项，指出具体位置及差距 |
| `UNKNOWN` | 缺少必要输入、工具或观察，暂时无法判定 |

这些是程序内单项检查结果，不替代项目已有的评审结论或工作流状态。每项结果附一句可核对的依据；命令、截图、交互、引用等按任务需要保留具体位置。

`[Ω]` 的全局条件是：主目标的 `ACCEPT` 满足、所有 `CHECK` 均为 `PASS`、全部硬约束满足、交付符合 `OUTPUT`。程序没有声明 `[Ω]` 时也沿用此完成条件。后续修改使既有检查过期时，应复验受影响项；任何单个循环不能越过其他检查提前宣告完成。

“没有可见改进空间”按已声明维度、实际对照和当前证据判断，并报告判断依据；不表示数学上证明了最优。`standard` 简写、预算上限或退出动作都不能充当通过证据。
