# 已提交过程文件的历史瘦身

只在用户要求分析历史体积、或准备/执行历史瘦身时读取。以下命令是操作形状，仓库、路径、refs 和输出位置均须换成实际核对值；不在用户当前工作仓试跑改写。

## 先把方案做成可审阅的结果

1. 记录原仓位置、分支/标签与对象 ID、未提交及未推送工作、实际 Git 存储占用。确认源仓是否浅克隆、部分克隆或依赖 alternates；信息不完整时不能宣称覆盖全部历史。只改普通删除提交或 `.gitignore` 不会移除旧提交中的对象。
2. 在仓外新建独立副本；本地源用 `git clone --mirror --no-local <源仓> <新的仓外路径>`，保留原仓供恢复。核对本地 refs 与已知远端分支/标签的覆盖，不把本地 `--all` 当成服务器所有引用；拉取缺失引用前确认范围。克隆副本不包含原工作树的未提交、未跟踪或忽略文件，这些保持原位，需另行保存的材料单独核对。
3. 在独立副本运行 `git filter-repo --analyze`，读实际生成的路径、已删除路径、重命名和对象大小报告。工具不可用时说明所缺依赖，不静默安装全局工具或改用 `filter-branch`；仍可用 Git 的历史与对象查询交付已知盘点。
4. 逐项核实应移除的**历史精确路径**，包含旧名称及已经删除的版本。过滤不会自动跟随重命名。只因某个 blob 很大不能删除；同内容可能也被业务文件使用，不用全局大小阈值或 blob ID 清除来代替用途判断。混有 `round.json`、packet、评审原文等记录的目录不能整体移除。
5. 将备份写在过滤副本之外：`git bundle create <仓外备份.bundle> --all`，再 `git bundle verify <仓外备份.bundle>`；需要保留的本地文件另存并核对。备份不能只藏在待清理仓库内，bundle 也不包含仓外 LFS 内容。
6. 展示移除路径/旧名、保留项、覆盖 refs、备份与恢复路径、实测基线及预期效果；说明提交 ID 和签名会受改写影响、协作者需要重新同步。**历史改写与远端替换分别核对授权**：普通清理或仅分析不授权这两项。缺授权时在上述准备完成后询问具体动作及范围；已有明确授权继续执行。

## 在独立副本改写并验证

只按批准的集合操作，不为绕过 fresh-clone 检查添加 `--force`；检查失败先核对副本来源与完整性。用精确路径过滤，例如：

```bash
git filter-repo --invert-paths \
  --path 'docs/reviews/orders.ui-captures/r1/U1-default-390-light.png' \
  --path 'docs/reviews/orders.ui-captures/r1/logs/console.log'
```

示例以副本全部 refs 已获改写授权为前提；仅批准部分引用时，显式用 `--refs <批准的引用>` 限定。它会启用 partial 改写，保留其他引用及其旧对象，不把这种结果当成完整历史瘦身。

路径多时可用 `--paths-from-file <仓外清单>`，但它不是 NUL 路径列表：换行分隔，有 `literal:`、`glob:`、`regex:` 及 `==>` 等语法。对含换行或这些特殊语法的文件名，改用结构化参数传逐个 `--path`，不把路径误解析成通配或重命名指令。

逐项验证：

- 在批准覆盖的 refs 中查历史，确认清单里的每个旧名、新名均已移除；只看当前树没有文件不够。未覆盖的引用仍可保留旧对象，不能声称全部释放。
- 比较过滤前后的各分支/标签末端文件清单与内容，除已批准路径外，源码、业务素材、测试基线、报告和状态内容一致；再运行 `git fsck --full`。
- 从改写后的独立副本另做一次无本地对象共享的新克隆，复测 `git count-objects -vH` 和实际 Git 磁盘占用，给出实测差值。压缩、重复对象和保留引用会影响结果，不能承诺按文件大小等量缩小。
- 确认仓外 bundle 能恢复原 refs，记录新的提交映射与完整恢复命令。保留原仓和备份，不顺手在原仓执行 reflog 过期或立即 prune。

## 远端同步与退出

没有远端替换授权时，到本地已验证副本交付，给出原仓、瘦身副本、备份和下一步。获准时先读取远端当前 refs，与分析时记录的对象 ID 比较，处理并发更新；逐项核对批准分支/标签的保留、更新和删除，使用绑定旧对象 ID 的 `--force-with-lease`，不盲目 `push --mirror` 或 `push --force`。filter-repo 可能移除 `origin`，重新设置远端时仍以获准目标为准。

推送后核对远端 refs，并从远端做新克隆验证。旧克隆、隐藏/PR 引用、LFS 对象及服务端回收策略可能继续占空间；没有服务端实测就只报告已验证的克隆体积，不宣称托管平台已释放磁盘。协作者应按交接步骤重新克隆或迁移独有提交，避免把旧历史重新合入。

操作语义以 [git-filter-repo 官方手册](https://github.com/newren/git-filter-repo/blob/main/Documentation/git-filter-repo.txt)、[Git clone](https://git-scm.com/docs/git-clone)、[Git bundle](https://git-scm.com/docs/git-bundle) 和 [Git count-objects](https://git-scm.com/docs/git-count-objects) 为准。官方命令能力不扩大本次授权范围。
