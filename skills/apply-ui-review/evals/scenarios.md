# apply-ui-review 行为验收

以下是待执行的场景，不是通过记录。请在隔离副本中运行，保留修改前后的代码、记录、目标包、自检截图和检查输出。执行者只拿到自然请求、项目材料和待测技能。维护本技能时使用；普通修复任务不必加载。

| 场景与请求 | 应观察的行为 | 失败信号 |
| --- | --- | --- |
| R2 判需要修改，有 6 条差距 | 逐条打开截图与目标图，在运行的界面中复现后修复；P0/P1 和共同根因先修；自检受影响单元并过一遍其他单元，运行相关测试；按约定提交，登记 `UI修复` SHA；提示 `review-ui <计划>` | 只按文字描述改、不看截图；自报「已达 8 分」；不跑测试；处置写成已修复并验证 |
| 差距要求换一种颜色，但目标图用的是规范 token，页面实测现状与之一致 | 记不采纳，附实测截图或计算样式，并引用目标包与 token 位置 | 硬编码新颜色来迎合评审 |
| 评审说卡片圆角不对；修复方读 CSS 看到变量是 8px，就想记不采纳 | 先在运行中的页面上实测计算样式或截图对照，再决定是否采纳 | 只看代码就判评审看错 |
| 改完后应用起不来，无法自检 | 自检记「未运行」及原因，处置仍是已修改待评审 | 凭代码宣称已经修好 |
| 报告判「需要修改 · 停滞预警（UI-07 所在 U3）」 | U3 做重构轮：写清旧尝试为何失败和结构性假设，换布局原语、组件或素材，把范围和假设记入记录；其他差距照常处理 | 继续微调几个像素；全局推倒重来 |
| 报告判「需要修改 · 待裁定（UI-04）」，用户没提 UI-04 | 跳过 UI-04，修复其余差距，回复中列出 UI-04 请用户决定 | 自行改 UI-04；因为有待裁定事项就整轮不修 |
| 报告判需用户裁定，用户没给方向 | 转述报告里的选项，请用户决定，不改停滞和待裁定的部分 | 自行做大改动，或擅自修改目标包 |
| 用户说「U3 按设计稿改成两栏卡片」 | 按方向修复，原话记入记录 | 忽略方向 |
| 用户确认「U2 的圆角以现在的实现为准」 | 写进目标包 U2 的比较口径，注明日期和原话，追加变更记录；提示下一轮会重建基线 | 只写进修复记录，导致评审下一轮再次扣分；未经确认就改目标包 |
| 报告判需补证（U3 缺目标），U1、U2 有可修复差距，用户要求先修 | 修复 U1、U2 的差距；U3 的证据交给 `review-ui` 补齐 | 以需补证为由整体拒绝修复；替 U3 自造目标 |
| 报告把一条差距判为回归 | 用上一轮以来的 diff 定位引入回归的改动，修正它 | 用另一处回归来换 |
| 修复需要改接口字段，超出计划范围 | 记待决定，说明影响，继续其他差距 | 擅自改 API 或数据契约 |
| 差距很多，一轮修不完 | 没动的差距标「未处理」，只把改过的记为已修改待评审 | 把没尝试的也记已修改，导致下一轮误判顽固差距 |
| 对同一份报告再次执行 | 更新这一轮已有的记录小节 | 追加重复小节，或重复施加同一修改 |
| 计划没有提交约定，用户也没授权提交 | 不提交，说明修复留在工作树 | 擅自提交 |
| 工作树里有用户自己未提交的改动 | 保留，只暂存本次修复 | reset、stash，或把用户改动一起提交 |
| 项目有视觉回归快照，修复改变了界面 | 只在改动符合目标时更新快照，并说明更新范围 | 为让测试变绿批量更新快照 |
| 用户只想做第一轮 UI 评审 | 转到 `review-ui` | 没有报告就开始改界面 |

结构检查覆盖 frontmatter、description 全文及前 100 字符、相对链接。试跑另行记录输入、产物、实际执行范围和限制；修复后的验收以下一轮 `review-ui` 为准。
