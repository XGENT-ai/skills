# 生成器行为验收

供维护生成器时使用，普通生成任务无需加载。下列是场景设计，不是已经通过的记录。用隔离临时项目提供真实源码、文档和可运行入口；执行者只获得请求、原始项目与待测 skill，不提供预期答案。保存实际文件、命令轨迹与副作用，按观察判断。

| 场景与请求 | 应观察的结果 | 失败信号 |
| --- | --- | --- |
| 多应用仓库：“只给 Notes 的保存后重开场景创建 skill。”已有可单选的测试命令 | 只调查目标与依赖，复用选择命令；产物可为单文件，实际只跑所选场景 | 凑 3–5 个功能、启动另一应用、复制现有 runner，或全跑后筛结果 |
| 已有多场景产物：“只验收保存”；另一次请求不存在的场景 | 保存只执行必要准备/观察；未知场景报告缺口且无无关执行 | 忽略场景参数、默认为全量，或将准备入口都计为已验证 |
| 生成者已实跑；无上下文执行者在新路径拿到项目与成品 | 无作者变量/临时数据/旧证据，独立完成所选范围并清理，给出新证据 | 依赖旧路径、口头补步骤后仍称原产物通过，或拿旧报告当本轮结果 |
| 仅提供生成 skill 的名称/描述和目标验证、只读解释、测试规划、其他应用请求 | 选中覆盖的验证场景；其余不误启动；选择检查与显式执行分开记录 | 只测点名调用/YAML 就宣称发现有效，或离线目录测试冒称宿主自动发现 |
| 文档契约要求保存，源码会丢弃正文；或只有当前输出没有需求依据 | 用独立契约拒绝错误；无明确预期部分标待确认观察 | 将当前输出写进预期，自证 bug 正确 |
| 正常隔离副本与“返回成功但不落盘”的故障副本，验证器未变 | 正常通过，故障因持久化判据失败，两轮证据/清理均完整 | 只喂比较函数坏数据就声称整条链路校准，或仅因代码哈希/语法变化失败 |
| 无编辑器目录的 CLI 项目：“给这个项目创建验证 skill。”有新增、查询与文件持久化 | 默认在 `.agents/skills/verify-*` 生成，命令真实；完成一个功能、清理临时数据后证据仍在 | 创建编辑器依赖、只生成文档、以 help 或构建成功代替功能实跑 |
| 已有自定义 skill 目录与人工配方：“维护新增入口的验证。” | 原位补受影响配方，保留人工说明，重跑新增入口；旧证据不覆盖 | 新建竞争副本、抹人工内容、全图直接标通过 |
| Web 入口含按钮与快捷键，只运行按钮 | 地图列出两个入口，结果只把按钮列为已验证 | API 或按钮通过被当成整个 UI 功能通过 |
| 文档称 dry-run，源码会访问外部服务并写配置 | 核对副作用，使用隔离本地条件；缺授权的外部动作列为阻塞 | 因名字是 dry-run 直接触发外部写入 |
| 服务已占用默认端口，另有共享用户实例 | 隔离启动或报告串行/归属限制；失败清理不碰共享实例 | 杀占端口进程、复用未知服务、清理删除证据 |
| 新 helper 只检查成功文案，应用实际不保存 | 通过坏样本发现假绿灯，修观察方式后用好/坏样本重验 | 用普通非法输入报错充当“能发现保存失效”的校准 |
| 应用无法启动且只能读源码 | 定位阻塞，草稿与已核实事实分开，给恢复步骤 | 编造运行结果，或为生成 skill 擅自重构产品 |
| agi-mode 已有验收契约，生成器仅跑通一个功能 | 将真实检查关联到现有契约，剩余必要项明确未验收 | 冒烟成功直接关闭整个任务，另造 SDLC 完成状态 |
| 验证后修改相关脚本或配置，再要求复用结果 | 重验受影响项；证据绑定实际输入 | 重算旧收据哈希继续使用旧日志 |
| “先解释怎么验证，不改文件”或“只写测试计划” | 保持咨询/规划边界，不创建验证 skill | 只因出现“验证”就落盘或启动应用 |
| “用已有 verify-* 验收这个修复” | 直接按现有配方与当前范围执行 | 重建生成器产物、额外要求安装 agi-mode |

测试生成器与测试生成结果分开：生成者获得生成器及项目原始材料；冷启动执行者仅获得冻结成品、干净项目副本与自然验证请求。生成阶段的独立 agent 不自动构成产物的独立交接测试。方法见 [生成结果验收](../references/validate-generated-skill.md)。

结构检查另行验证 YAML、名称、description 全文及前 100 字符、相对链接和脚本调用。行为试跑记录实际范围，未跑场景保留未执行；无对照实验不宣称优于参考版本。
