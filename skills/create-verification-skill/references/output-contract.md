# 生成产物约定

这是写作约定，不是可以原样复制的成品。生成时把应用名、入口、命令、判据落实为已核实事实；未跑通的部分明确写阻塞，不留虚构配方。生成结果应能在项目的另一个检出副本执行。

## SKILL.md

frontmatter：`name: verify-<app>`，名称与目录一致；`description` 先写该应用哪些场景/表面的验证触发与必要排除，再写产出，不将只读解释或其他应用纳入范围。整条尽量不超过 200 字符，前 100 字符独立表达适用边界。新文件不需要编辑器私有字段。描述选择测试与显式加载执行分别验收，格式有效不等于发现有效。

主体至少覆盖：

| 部分 | 生成时应写实的内容 |
| --- | --- |
| 使用范围 | 应用身份/工作目录、场景 ID、入口、本轮选择方法及必要依赖；拆分时先读索引，再按需读配方；未覆盖的请求不启动无关检查 |
| 启动 | 工作目录、版本/构建确认、实际命令、必要环境变量与测试数据来源、就绪判据和等待上限；超时保存日志并清理 |
| Doctor | 可直接执行的只读检查，核对应用身份、当前版本/构建、配置、实例归属、认证与可用性；不能仅凭端口通就操作 |
| 驱动 | 现有 harness 的调用、稳定选择器/命令/路由、状态重置和可观察的等待条件；短命 CLI 每次独立运行，无需守护进程 |
| 证据 | 本轮 ID 与目录的生成方式、输入版本/环境、动作与结果如何记录、断言和副作用检查 |
| 清理 | 本轮资源的准确标识、释放和确认命令；成功与失败都执行，保留证据和非本轮资源 |
| 报告 | 按功能 ID 和入口列出状态、实际观察、证据路径、限制与清理结果；本轮未跑的必要检查明确列出 |

配置只记必要变量名与非敏感值；凭据引用项目现有安全来源，不写进 skill、截图、命令日志或提交文件。Doctor 失败时先排查，不能偷偷改连一个不属于本轮的服务。

没有可用 UI 驱动工具时，记录缺口与可执行的部分；HTTP 验证不能冒充 UI 交互证据。库以公开接口的最小消费者验证，不能改内部状态制造结果。只在生产系统已有的外部边界隔离模拟，并明确真实与模拟覆盖。

直接使用已有测试选择器、命令和报告，只有它们不能满足本轮要求时才补最小 helper。无需统一 CLI、包装层或新的结果协议。新增 helper 应保留所选范围，约定失败退出码、超时与清理；通过解释器调用，或具有可执行权限。每个 helper 在主体中给出实际调用，不能只扔一个脚本让读者猜接口。单场景独立命令已经足够时，不必为了“可选择”添加参数解析器。

## 场景与可选索引

单场景直接写在 `SKILL.md`；需要按需读取多个配方时，才拆出 `features/README.md` 和场景文件。索引只链接场景、共用前置与覆盖缺口，不复制全部步骤。下列列结构可按项目习惯调整：

| 场景 ID | 用户能力与入口 | 必要依赖 | 配方/实际选择命令 |
| --- | --- | --- | --- |

不把文件存在、已有测试名称或过去的运行状态当成功能验收通过。多个入口可以共享配方，但运行覆盖必须可区分。

## 单个场景配方

独立文件用用户能理解的标题；内嵌配方用相应小节。内容包含以下信息，可合并段落，不要求固定标题数量：

1. **子行为与判据**：稳定 ID、预期行为与必要边界，以及已读的来源路径/条目或用户要求。区别约定行为与当前实现观察；后者不能独自成为正确性依据。预期缺失或矛盾时说明待确认项，保留可执行的观察，不报符合要求。
2. **用户入口**：实际页面路径、按钮/快捷键、命令或公开接口；列明本轮选择与其他已知入口。
3. **操作与观察**：先列前置状态和数据准备，再将每步“用户动作 → 可执行操作 → 预期观察 → 证据”连在一起。区分准备状态和真正被验收的动作；不能直接写数据库来证明创建功能。
4. **陷阱与清理**：影响复现的焦点、异步完成、权限、持久化与重置细节；引用共用清理，仅补充该场景独有资源。

共享准备和相邻观察入口是依赖，不自动算作所选场景之外的验收覆盖。更新时沿判据来源与实际命令检查影响，不重生成不相关配方；拆文件时保留原场景 ID 和有效调用方式。

## 每轮运行记录

沿用项目现有报告格式，只补足可复核的信息。没有约定时，在本轮证据目录用简短 Markdown 保存：

- **运行身份**：run ID、时间、目标版本、相关工作区改动/输入指纹、构建与工具版本、必要环境和隔离资源；HEAD 不能代表未提交内容。
- **检查明细**：所选场景/子行为 ID、入口、前置条件、动作或命令、预期及来源、实际结果、状态、原始证据链接；实际动作须对应所选范围和必要依赖。
- **覆盖缺口**：本轮必须验证却失败、受阻或未跑的项及原因，区别地图中不属于本轮的项。
- **清理结果**：释放了哪些本轮资源、是否有残留、清理后哪些证据仍可读取。

这些是 `verify-*` 日常执行的记录。生成器的结构/选择检查、作者实跑、校准和冷启动结论放在生成交付记录中，不要求使用者每次验证应用都重做或汇报这些生成质量检查。

Web 证据保留动作轨迹、相关截图/可访问性快照和持久化观察；CLI 保留命令、stdout、stderr、退出码及文件等副作用；API 保留脱敏请求、响应及后续可见状态。只截最终成功页面、只记录退出码或只贴单元测试绿灯，不能替代对应的真实用户路径证据。

报告状态约定：`passed` 是已执行且满足本项判据，`failed` 是已执行但不符预期，`blocked` 是缺具体前置条件，`not-run` 是未执行。无法完整观测时不能填 `passed`。清理失败单独报告，不能因功能通过而隐去残留。

使用 agi-mode 的机器可检查证据契约时，先读取其实际协议，复用已有文件，不另造相似但不兼容的 JSON 格式。验收先确定，输入指纹在执行前取得，结束确认输入未变后关联原始证据；哈希一致只能说明文件一致，不能证明环境仍相同或目标已经完成。
