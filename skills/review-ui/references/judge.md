# 独立评审

## 派发

- 每轮派**全新上下文**的 subagent，模型继承主 agent。评审只读，不改文件，不再派生其他 agent。
- 只给以下材料：
  - 目标包；
  - 本轮各单元的截图，以及本轮的 `capture.md`（每张图对应的单元、状态、视口和主题）；
  - 交互关键帧与操作记录；
  - 差分图（可选）；
  - 复审时，每个单元上一轮（最近一次覆盖它的轮次）的同名截图，以及那一轮 `judge.md` 中该单元的部分。目标包自那一轮以来有变更时，附上变更记录。
- 不给以下材料：代码、diff、提交说明、修复记录、修复者自述、完整报告、机器检查结果、门槛分、主 agent 的看法。
- 一位评审要能逐张细看图片（本轮、目标、上轮合计，经验上一组不超过约 30 张）。超出时按单元分组并行派发，每位拿同一份提示和各自单元的材料。并发受实际槽位限制，不够就分批，但不能漏单元。
- 发送绝对路径。评审打不开图片时，按派发失败处理。

## 评审提示

主 agent 填好花括号里的内容后，原样发送：

```text
你是独立的 UI/UX 验收评审，只读，不修改文件，不派生其他 agent。请判断当前产品界面离目标还差多少，按标尺打分，并给出完整、可执行的差距清单。

材料（只打开这里列出的文件和目录；目标包里指向其他文件的链接，除目标图外都不要打开）：
- 目标包：{路径}（单元、目标图、规范要点、比较口径）
- 本轮截图与交互记录：{目录}；每张图对应的单元、状态、视口和主题见 {capture.md 路径}
- 上一轮截图与评审结论：{各单元的目录与 judge.md 路径}（首轮没有）
- 差分图（可选）：{目录}

逐个单元打分，可以给小数：
- 布局（0–3）：区域结构，主要组件的位置、尺寸、对齐、间距和层级；每个视口下的排布、换行和滚动；有没有溢出、遮挡、截断。
- 视觉（0–3）：配色与用色语义，字体（字族、字号、字重、行高），对比度，图标与图片，圆角、边框和阴影，主题；是否与规范 token 一致。
- 交互与状态（0–3）：主路径能否走通；加载、空、错误、禁用、成功等状态及反馈；悬停、焦点、按下态；键盘操作与焦点可见；表单校验与提示；过渡是否帮助理解。
- 细节（0–1）：逐处细抠文案、数字与日期格式、图标对齐、像素级间距、截断与省略、多语言。一个像素都不应不同。

锚点：
- 3 分：与目标一致，只剩应归入「细节」的微小差异。
- 2 分：方向与结构正确，但有设计师或用户一眼就能看出的偏差。
- 1 分：只有部分正确，有结构性偏差或多处缺失。
- 0 分：缺失、根本不同或不可用。
- 细节维度：1 分 = 逐处比对没发现差异；0.5 分 = 有若干小差异；0 分 = 差异很多。
每个维度用一句话说明为什么不是更高一档。

要求：
1. 挑剔、精确、完整。差距很多就列一份很长的清单。目标是另一位 agent 照单修完回来后，分数明显提高。
2. 每个单元的失分都要能由差距解释：该单元各条差距的「可挽回分」相加，约等于 10 减去单元分，误差不超过 0.5。
3. 每条差距都要可执行，写清以下内容：
   - 单元与截图中的位置（区域、元素或文字）；
   - 「现状 → 期望」，期望引用目标图的位置或规范要点；
   - 具体修法：改哪个组件、用什么布局方式、哪个 token 或属性、什么素材、什么结构；
   - 严重度和可挽回分。
   不要写「看起来廉价」「不够精致」这类话，要说出造成这种观感的具体原因和改法。
4. 期望在目标图和规范要点里都找不到依据的，单独列为「建议」，不扣分。按目标包的比较口径，忽略示例数据之类的差异。
5. 需要推倒重做布局、换组件或重做素材时，直说，不要粉饰。目标是做到与目标一致，不要放水。
6. 只依据截图与记录下判断，不凭常识、经验或对常见实现的了解去推测界面效果。没拍到的状态既不算通过也不算失败；图缺失、模糊或看不出状态时，写明哪张图看不出什么。
7. 有上一轮评审时，保持评判尺度一致，但不必维持或提高分数；变差了就给更低的分。逐条给上一轮差距标：已解决、部分解决、仍存在、回归、待核实（看不出）、不再适用。同一问题沿用原编号；新问题用临时编号「新-1」「新-2」……

严重度：
- P0 阻断：主任务无法完成；内容或数据错误、不可见；必需视口的布局崩坏。
- P1 严重：用户会明显困难或误解；主路径不满足 WCAG AA（对比度、键盘、焦点）；主要区域与目标明显不符。
- P2 一般：能察觉的偏差，但不妨碍完成任务。
- P3 打磨：几乎察觉不到的细微差异。

输出：
1. 评分表：每个单元的四个维度分和单元总分，每个维度附一句理由。
2. 上一轮差距复核表（首轮省略）。
3. 差距清单：所有仍未关闭的差距，包括沿用编号的旧差距和新差距。先按严重度、再按可挽回分排序。每条写编号、单元与截图、维度、严重度、现状 → 期望（依据）、修法、可挽回分。
4. 建议（不扣分）。
5. 看不出的格子：哪张图、看不出什么。
6. 总评：最低分单元及主要原因；哪些地方需要结构性改变。
```

## 复核

- **完整性**：每个单元都有分；每条差距都有截图位置和依据；可挽回分与失分大致相符；上一轮差距都有复核结果。有缺项时，工具支持续接就让同一位评审补齐；否则只就缺的单元另派一位全新评审。
- **看不出的格子**：只有评审自己报告看不出时才处理。主 agent 先补采（调整目标包的「采集」节并记录），再派一位全新评审重评涉及的单元。每个单元取两次中较低的分，差距取并集。补采后仍看不出的，标待核实。
- **事实抽查**：打开对应截图，核对评审描述的现象。认为评审看错时，只在报告该差距下附核对说明，写清截图里实际看到的事实。
- **主 agent 不改分、不删差距、不改门槛项，也不因争议换评审重评**。有争议的差距交给修复方核实，下一轮由评审复核。自己发现的额外问题，必须附本轮实拍截图或页面实测结果，才能以「主 agent 核实」为来源列入清单；它们不改分数，是 P0/P1 时计入门槛项。
- **确认评审**：本轮将判通过、但最低单元分低于「门槛 + 0.5」时，用同一批材料再派一位全新评审。每个单元取两人中较低的分，差距取并集后去重。
- **合并与编号**：主 agent 合并各位评审的结论，把临时编号换成正式编号，按报告合同写入本轮的 `judge.md`。

## 来源与有意取舍

本评审改编自 `local/workflow.md`（Dream Loop Pro，一个用于 3D 场景还原的循环）：实现 → 截图 → 全新上下文的评审 → 照单修复 → 再评。原流程按构图、光照、材质各 0–3、细节 0–1 打分，≥ 8 分收工；最佳分 2 轮内没涨满 1 分，或同一差距连续被点名，就从整体上重新思考做法；重构仍无效就交给人裁定。实践中 8 分以上基本达到预期。

保留的部分：独立评审、四个维度的 10 分制、挑剔的口吻、完整可执行的清单、用上一轮结论校准尺度、8 分门槛、两段式停滞处理。

为 UI/UX 验收做的调整：

- **维度**：换成布局、视觉、交互与状态、细节。交互证据用关键帧和操作记录，不只看静态图。
- **冻结矩阵与目标指纹**：单元 × 状态 × 视口 × 主题固定下来，每轮全量、同条件采集，分数可以前后比较，也能发现没改动单元里的回归。期望或目标图一变就重建基线，只改采集步骤则不影响。
- **取最低分**：多个单元时取最低分作为本轮分数。验收要求每个界面都达标，平均分会掩盖短板。
- **门槛项**：P0/P1（含机器检查发现的）一票否决，相当于原流程里的帧率门槛。
- **失分可追溯、编号跨轮稳定**：每一分的扣除都要对应到具体差距，清单完整与否可以核对；「同一差距反复出现」也能直接判定，不靠印象。
- **无依据只作建议**：找不到依据的期望不扣分，避免评审按个人口味无限挑刺，导致循环收不了尾。
- **评审信息隔离**：评审只读目标包、截图和上一轮的 `judge.md`。看不到修复者自述、代码、机器检查和门槛，避免确认偏差和朝门槛凑分。
- **争议不重评**：主 agent 有疑问时只能附核对说明，不能改分、删差距，也不能换一位评审重新打分，杜绝挑评审。补采或确认时的重评，一律取较低分。
- **确认评审**：过线但余量很小时，加一位评审确认。误判通过会提前结束循环，代价远高于多评一轮。
- **停滞分范围，每个范围只重构一次**：全局平台期只在低于门槛时判定，单条顽固差距只重构它所在的单元。重构后仍满足预警条件即停滞，不会因为每轮涨一点点而无限循环。修复方与评审各执一词、或等待素材和决定的差距，转为待裁定事项交给用户；在用户决定之前一直保持这个状态，其余差距照常推进。只剩待裁定的门槛项挡住通过时，直接交用户裁定。
