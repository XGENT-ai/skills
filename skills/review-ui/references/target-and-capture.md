# 目标包与采集

## 目标包

目标包是整个验收循环的合同：每个单元应当长什么样、怎么用，以及每轮怎样采集才能前后比较。评审和修复都以它为准，循环中途不能悄悄改变期望。

评审只读目标包和截图，不打开计划、PRD 或代码，所以目标包要自带评审需要的全部期望。门槛分不写进来，因为评审不该知道门槛。

**路径**：`<前缀>.ui-target.md`，前缀见报告合同。目标图优先链接仓内原文件。只能在线访问的设计稿（如 Figma），在允许时导出到 `<前缀>.ui-target/`，并记录来源和导出日期；评审必须能直接打开图片。

**期望来源**按单元逐个确定，取下列第一个可用的：

1. 用户本次指定的目标图或设计稿；
2. PRD 或计划链接的设计稿导出图或截图；
3. 项目 DESIGN.md 或主题 token，以及同一产品里已经确立的页面模式；
4. PRD 的界面需求与 UAT，计划的前端状态清单与 UI 走查要求；
5. 用户已确认的设计参考或 brief：只约束方向，不当像素目标。仅存在、未接受、已过期或候选不唯一的 brief 不构成期望；需要原文时直接读取，不能把「找到了文件」当成已接受。

有目标图的单元按**还原模式**比较。只有规范的单元按**规范模式**比较，每条期望都写出规范原文或要点并注明出处；不能只写 `FR-3` 这样的编号。用到的 DESIGN.md 规则和 token 值也摘进来。

- 一个单元既没有目标图也没有规范：不写它的期望，该单元判需补证。
- 来源之间冲突（例如目标图与规范不一致）：不自行裁定，列为待裁定事项。
- 定位材料后读取实际 DESIGN.md、PRD、brief 与接口原文，注明缺失部分。工具建议不能替代项目规范或已确认目标，不能自动改变已冻结期望，也不把未知 token 猜成实值。

**单元**是一个可以单独验收的页面、弹层或流程，范围覆盖本次计划改动到的界面。状态（默认、加载、空、错误、禁用、成功等）、视口和主题都放进矩阵，不另拆单元。单元数量够判断验收即可，一般 2–8 个。

````markdown
# <功能> · UI 验收目标包

- 需求来源：<PRD 与期次，或无>

## 单元

| 单元 | 状态 | 视口 × 主题 | 目标 | 比较口径 |
| --- | --- | --- | --- | --- |
| U1 订单列表 | 默认、空、加载失败 | 1440×900、390×844 × light | [orders.png](design/orders.png)、[orders-m.png](design/orders-m.png)；规范要点 U1-1 | 示例数据与头像不比；表头文案、列序和 token 须一致 |
| U2 新建订单 | 打开、必填校验、提交中、成功；键盘走查 | 1440×900 × light、dark | 规范要点 U2-1、U2-2 | 规范模式 |

## 规范要点

- U1-1：列表为空时显示插画和「新建订单」主按钮（PRD FR-3 AC2）。
- U2-1：提交中按钮禁用并显示进度，防止重复提交（PRD FR-5 AC3）。
- U2-2：表单控件纵向间距 `--space-4`（16px），标签字号 `--font-sm`（14px）（DESIGN.md「表单」）。

## 采集

- 计划：[<计划标题>](<相对路径>)
- 环境：<启动或访问方式、被测版本的取法、账号与角色、种子数据、语言、时区>
- 条件：<工具；视口与像素比；等待字体与网络空闲；关闭或等待动画；固定时间与随机数>

| 单元 · 状态 | 入口与前置 | 到达步骤 |
| --- | --- | --- |
| U1 · 空 | `/orders`，admin，seed `empty` | 打开页面，等列表请求完成 |
| U1 · 加载失败 | `/orders`，admin | 拦截 `/api/orders`，返回 500 |
| U2 · 提交中 | 在 U1 点「新建」 | 填好必填项，拦截提交请求让它挂起 |

## 变更记录

- <日期> R1 建立
````

**比较口径**写明哪些差异不算偏差（示例数据、头像、时间戳、第三方内容），哪些必须一致（文案、顺序、token）。这样评审不会要求改不了的东西，也不会放过该一致的地方。采集时尽量用与目标图相近的数据。

**目标指纹**：记录「单元」「规范要点」的规范化文本（统一 LF）及其直接引用目标附件的 SHA-256 清单，附件按相对路径排序；再对清单计算 SHA-256。缺失附件记缺证，远程目标图先保存本地。保存计算口径与输入清单，复审沿用同一口径；旧指纹口径未知时直接核对原始目标与附件，不猜相等，也不清零修复历史。「采集」节和变更记录不计入，只有期望或目标附件变化才重建基线。此计算不依赖特定 CLI。

**冻结与变更**：R1 建立后，「单元」和「规范要点」只能由用户修改，或经用户确认后修改，并写入变更记录。不能反过来拿被测实现当目标。

- 用户接受某处偏差时，把它写进该单元的比较口径，注明日期和用户原话；评审会据此不再扣分。
- 只改「采集」节时，可以直接修改并记录。
- 指纹一变，下一轮就按重建基线评审。

## 采集

### 先规划证据，再拍图

验收矩阵列的是需要验证的条件，不是截图任务清单。逐项标明「本轮实拍」「本轮实测」「历史复用」或「缺证」，允许多项引用同一证据。首轮覆盖所有单元的必要视觉与交互特征；复审只检查变化、未关闭问题及影响范围内的回归。既没有证据也没有有效复用依据的条件仍是缺证。

- **同状态共用一图**：页面/路由、状态、视口及 DPR、主题、语言、数据条件和被测版本相同，多个问题引用同一原图，并注明区域、元素或文字。问题编号不是截图维度。先查已有材料；新增一张图必须说明它补充了什么信息。
- **代表帧**：选择必要的默认桌面、最窄长文案语言、深色等样本；只覆盖产品实际支持的条件。普通复审以 6–12 张为预算参考，不是最低任务量或硬上限；简单页面 3–5 张甚至更少即可。预算包含 apply 自检的可复用图片；多页面首轮或真实异常需更多时说明增量信息，不为凑数补拍或漏掉不同页面。
- **操作与截图分开**：操作必须实际执行并记录观察结果；仅在弹层打开、校验反馈、成功/失败、布局或必要焦点状态发生可见变化时拍关键帧。重复点击、同一禁用入口、画面不变的检查不各拍一张。看不清先放大原图，仍不足才补实拍局部；局部图不能代替页面整体布局证据。
- **先实测**：优先复用现有脚本，在矩阵条件下验证溢出、可达性、关键文字、状态与交互断言，保存实际结果。成功断言通常不截图，异常或视觉判断需要时补图；断言不能替代层级、字体观感等视觉判断，也不能由少量样本推断整张矩阵通过。
- **前置阻塞**：先核对环境、账号、数据与状态入口。已有 seed/mock/拦截方法可在允许范围内尝试；同一阻塞条件未变时记录一次原因及解除条件，停止受阻项，继续独立项，不反复启动整轮验收。

```formal
RULE @remaining_space_coverage:
  WHEN: shared_layout_wrapper_or_viewport_height_rules_change
  MUST: |
    受影响单元至少覆盖「短内容且容器存在剩余空间」与「长内容撑满容器」两种条件，
    在本轮采集计划与 capture.md 分别登记到达方法、实测剩余空间和对应证据。
    在目标支持的视口范围内，短内容可用较少数据或较高视口到达；
    长内容不得替代短内容结论。任一条件无法到达时记缺证及解除条件。
  MUST_NOT: [infer_remaining_space_from_viewport_size_alone,
             substitute_long_content_evidence_for_short_content_result]
```

### 跨轮及 apply 证据复用

复用前核对原始材料可读、来源版本与目标指纹、采集条件及从该版本至今的影响范围。目标指纹变化时重新建立基线，不继承旧分数。共享组件、token、字体、素材、布局、依赖、数据或运行环境变化可能影响未直接修改的页面，必须纳入复查；无法判断的单元不沿用结论。代码 diff 只辅助判断失效范围，不能直接证明修复效果。

- 未受影响、已独立通过的单元可沿用原证据和整组评分，标明来源轮次及复用理由，不重新打分；已关闭问题不重复复核，除非相关变化或新证据显示回归。
- 新增/受影响单元与未关闭问题需当前有效实测或实拍。apply 留下的图片在目标、版本、条件均匹配且出处核验通过时直接引用，不搬运、改名或重复拍摄；它只提供事实，评分和关闭仍由独立评审完成。
- 历史截图标「复用 Rn」，apply 图片标原路径与版本；不写成「本轮新拍」。一张修复后的状态图可同时验证该页多条差距，原图保留作对照。
- `capture.md` 记录证据类型、原路径/轮次、版本与条件、覆盖的单元/状态/问题、中性有效性标记，缺证单列。复用理由与失效范围留报告；交给评审的清单只含中性出处、覆盖和复用标记；主 agent 的 diff 分析、修复解释和机器检查结论只留报告，不混入评审材料。没有变化、新证据或阻塞解除时续接记录，不创建空轮次。

### 截图真实性与保存

- **真实性**：每张新截图必须用截图工具在真实运行的产品上拍摄：从「采集」节写明的真实入口进入，由真实浏览器、模拟器或桌面应用渲染当前代码。以下都不能冒充截图，一律当作没采到：
  - 设计稿、目标图或它们的导出图；
  - 上一轮或别处的旧截图冒充本轮新采集（按上述合同明确登记的复用除外）；
  - 为评审临时写的模拟页面或静态 HTML；
  - 手工合成、拼接或修过的图；
  - 只渲染组件的沙箱（如 Storybook），除非该单元本身就以沙箱为入口，并在目标包写明。

  为到达某个状态而拦截请求、返回测试数据是允许的，但只能改数据、不能改界面代码，并在 `capture.md` 对应格子注明。
- **出处可查**：`capture.md` 为每张图记录实际访问的地址、视口宽高、DPR、主题、拍摄时间、所用工具及构建或工作树版本。交给评审前，主 agent 实际开图并核对采集轨迹：新采集确为本轮拍摄，复用材料保留原始出处并满足复用条件；尺寸与视口相符；画面是目标页面，不是报错页、登录页或空白页。文件存在、mtime 新或 hash 一致不能单独证明这些事实。不合格的重拍，重拍不了就记为没采到。
- **环境**：优先复用项目已有的 `e2e-*` 验证 skill、E2E 脚本或计划写明的走查方式，来启动、登录和造数。被测版本记 HEAD 和未提交改动指纹。构建产物必须来自当前代码：必要时重新构建，或用本次改动的可见特征确认拿到的不是旧包。
- **一致条件**：视口与像素比相同、字体加载完毕、动画关闭或已结束、网络空闲、数据和时间固定。视口取目标图的画框尺寸。同一版本重拍结果不一致时，记为环境噪声；无法稳定的格子标为不可比，不算实现差异。
- **命名与存放**：截图存到 `<前缀>.ui-captures/r<n>/<单元>-<状态>-<视口宽>-<主题>.png`，例如 `U1-empty-390-light.png`。
  - 交互仅在需要视觉证据的关键转折后拍，文件名后加步骤序号，如 `U2-flow-1440-light-03.png`。操作记录写入同目录的 `U2-flow-1440-light.md`，只写实际执行的动作和截图里看到的结果。
  - 同一视口 ID 同时绑定宽、高、DPR。同宽但高或 DPR 不同时加确定性后缀，如 `-h900-dpr2`。
  - 各轮首采文件同名，方便逐张对照；同轮补采保留原图，追加 `-a2`、`-a3` 等 attempt 名，不覆盖。
  - 默认截可视区域，目标是整页稿时截整页。
  - 截图要不要提交，按仓库约定。
- **登记与恢复**：在 `capture.md` 中追加采集记录，保留原图和出处。中断后续接原轮；同一材料不重复登记，补采以新的 attempt 文件名保存。
- **日志**：采集期间顺带把控制台日志和失败请求存到本轮目录，评审结束后再分析。
- **覆盖与回归**：根据实际影响范围选择复查状态，未受影响项复用有效证据；全局样式、共享组件或目标变化须扩大相关范围，不能只看被直接修改的文件。
- **差分（可选）**：有图像差分工具时，可以给还原模式的单元生成差分图，供评审定位差异。差分比例不直接计分。

### 用 Phoenix 取证命令采集（可选）

检测到可用的 `phoenix-ui capture` 时（宿主技能目录，如 `.claude/skills/phoenix-ui/`、`.agents/skills/phoenix-ui/` 或用户级同名目录，有 `scripts/phoenix-ui`，且 `<它> capture --help` 退出 0；找不到、退出 4 或提示未知命令都按未检测到处理，不安装、不下载、不提示安装），能用它的步骤到达目标状态的单元可以这样采集：

```bash
<phoenix-ui> capture <实际地址> --viewport <宽>x<高> --dpr <像素比> --color-scheme <主题> \
  --states <单元状态文件> --name '<命名模板>' \
  --out <前缀>.ui-captures/r<n>/ --report <前缀>.ui-captures/r<n>/logs/capture-report.json
```

- 命名模板按上面的命名合同生成后传入：首采为 `<单元>-{state}-{width}-{scheme}.png`；同单元另有同宽但高度或 DPR 不同的视口时加确定性后缀，如 `<单元>-{state}-{width}-{scheme}-h{height}-dpr{dpr}.png`；同轮补采追加 `-a2`、`-a3` 等 attempt 后缀，原图与报告里的原条目保留、不覆盖。
- `capture.md` 的地址、视口宽高、DPR、主题、拍摄时间与所用工具（`phoenix-ui capture <该图条目的 tool.version>`，附该条目 `binarySha256` 前 12 位；旧报告无逐张 `tool` 时回落顶层 `tool`）从报告抄录。报告标为无效的图（`<名>.invalid.png`）按「没采到」处理：重拍或记缺证，不交评审。
- 报告里的控制台错误、失败请求、横向溢出与 `findings` 只供主 agent 的机器检查与可选 critique 辅助审查，不进独立评审材料。
- 主 agent 仍逐张开图核对出处与画面；命令的自检不替代这一步。
- 到达目标状态所需的交互或前置超出命令能力（应用在 iframe 内、目标在 Shadow DOM 内等）时，该单元改用现有其他采集方式，并满足上面的真实性与出处要求，`capture.md` 记实际所用工具；只有现有方式也取不到真实状态才记缺证。
- 未检测到时按现有方式采集，本节不适用，`capture.md` 与报告也不提它。

## 盲测走查（可选）

检测到 Phoenix 走查子代理时（宿主可派出 `phoenix-ui-ux-walker`，或 phoenix-ui 技能目录有 `reference/degraded/ux-walker.md` 可交给全新上下文的子代理；其他情况一律视为未检测到），对有主要操作流程（填表提交、多步流程、会保存数据的操作）的单元，在采集之后、独立评审之外派一位走查者：

- 交接只含入口、视口、测试凭据的环境变量名与安全边界（只用测试账号，不对真实业务数据写入或破坏，交接不含真实业务账号），以及输出目录 `<前缀>.ui-captures/r<n>/walk-<单元>/`；不给目标包、期望、计划、代码、修复记录与历史报告，也不指定要完成的任务、预期路径或应看到的结果：走哪条路径由走查者看页面自己选，交接里多给一句就成了提示。
- 主 agent 把返回的报告原样存为 `<前缀>.ui-captures/r<n>/walk-<单元>.md`（随 Git 跟踪；截图按现有忽略规则不入库），并记录这次隔离调用的标识（子代理 ID、会话 ID 或运行目录）。
- 走查材料不交给独立评审。每条问题先分为可复现的产品问题、工具或数据问题、待复现的推测：可复现的卡住、走错由主 agent 按 [judge.md](judge.md) 的严重度定义定级，以来源「盲测走查」列入差距，指向走查截图与状态文件；犹豫列为建议；后两类不列差距，写进「采集与覆盖」。
- 走查者无法操作页面时，报告写「未完成 UX 走查」及原因；未检测到走查子代理或单元没有主要操作流程时不派，报告与原来一致。计分与判定规则不变。

## Phoenix critique 辅助审查（可选）

检测到可用的 Phoenix critique 时自动适用，无需用户额外点名。检测条件是：Phoenix UI 技能目录与 `reference/critique.md` 可读，且其 `scripts/phoenix-ui detect --help` 退出 0；其他情况均按未检测到处理，不安装或修复工具，不创建 `.phoenix-ui/critique` 状态，报告不写这一项。

检测到后，自动对本轮待评单元执行以下辅助流程；执行失败时在报告写「未完成 Phoenix critique 辅助审查」及原因，继续已有采集和独立评审：

- 读取该 Phoenix 版本的完整 `reference/critique.md`，采用其中 Assessment A/B 的隔离顺序与审查范围，不采用其设计评分作为验收分。
- **Assessment A**：用未接触本轮检测发现的全新上下文读取目标包、必要产品上下文、相关实现和真实页面，先独立完成设计审查；不给它 `capture findings`、detect 结果、历史 `judge.md`、门槛或主 agent 的看法。
- **Assessment B**：复用本轮同版本、同状态下有效的真实采集、`capture findings` 或 detect 结果；缺少必要检测时按 critique 合同补做，不重复已有有效扫描。A 完成前不向 A 或辅助合成上下文透露 B 的发现。
- 环境支持时使用未预先接触 B 的辅助合成上下文，在 A、B 完成后合成。不具备全新上下文时，主 agent 可整理辅助观察，但报告首行必须保留 `⚠️ DEGRADED: single-context (auxiliary isolation unavailable after capture)`，不声称 A/B 独立。
- 浏览器证据使用真实页面和本轮采集，不为辅助审查额外注入 overlay 或启动 critique live-server。
- 将 A、B 原文与合成报告按顺序保存到 `<前缀>.ui-captures/r<n>/critique-<单元>.md`，记录实际模型、隔离标识、复用的证据与降级情况。不同单元复用同一目标报告时分别登记来源，不复制截图。
- 不执行 critique-storage 持久化、改进方向提问、Recommended Actions 或修复；这只是 critique 方法辅助审查，不宣称运行了完整的 `$phoenix-ui critique` 命令。

主 agent 对合成报告中的每条候选问题分类：

- 确定性检测仍有当前运行时证据的，以来源「机器检查」登记；
- 语义或视觉问题经当前截图或实测复现的，以来源「主 agent 核实」登记；
- 无法复现或无当前证据的不开差距，列入报告的未核实项。

critique 的 Design Health Score、启发式分数、优点、趋势和推荐命令不进入 `review-ui` 分数、门槛、停滞或验收判定。辅助原文、检测发现与合成结论均不交给独立评审，也不写入 `judge.md`。

## 机器检查

确定性检查前置以筛选异常和减少截图，结果与感知判断分开，不把检查的通过结论交给视觉评审，以免先入为主。由主 agent 写进报告，按影响定严重度后列入差距清单，来源标「机器检查」；之后由主 agent 复查未关闭及受影响的差距；未受影响的已通过检查可复用，注明来源。

所有检查都在运行中的页面上执行：在页面里测量元素尺寸、读取计算样式、注入扫描脚本、用真实按键操作。从代码或样式表推断出的问题（例如「这个容器写死了宽度，窄屏可能溢出」）不算检查结果，只能提示去哪里补拍或实测。按工具可用性和目标包要求选做：

```formal
RULE @unexpected_flex_auto_margin:
  WHEN: page_or_region_has_unexpected_large_blank_space
  MUST: |
    实测空白相邻元素及其祖先的位置、尺寸、计算 margin/padding；
    检查 Flex 容器块轴是否存在剩余空间，以及子项是否因
    margin:auto / margin-block:auto 获得非零块向 margin。
    目标未要求垂直居中且实测空白与目标不符时，将其列为来源「机器检查」的差距，
    记录容器与子项、块轴剩余空间、非零 margin、预期顶部间距和对应截图。
  MUST_NOT: [infer_defect_from_stylesheet_alone,
             flag_auto_margin_without_nonzero_runtime_effect,
             flag_intentional_centering]
```

- 采集期间的控制台错误与失败请求，以及它们是否影响可见行为；
- 每个视口下的横向溢出，以及被截断或遮挡的内容；
- 可访问性扫描（如 axe、Lighthouse 可访问性）和关键文字的对比度；
- 主路径键盘走查：能否到达各控件、焦点是否可见、有无焦点陷阱、Enter 和 Esc 的行为；
- 计划或 PRD 有性能目标时，测量对应指标。

工具不可用就写「未检查」，不能当作通过。

### 主 agent 例行 UI 检查

以下项目需要语义或视觉判断，不能伪装成确定性扫描。
主 agent 按适用性在本轮报告「机器检查」节记录每个待评单元的「已检查」「不适用」或「未检查」及原因；
确认的问题附当前真实截图或页面实测结果，以来源「主 agent 核实」列入差距。
独立评审的材料隔离与评分规则不变。

```formal
RULE @user_facing_copy:
  WHEN: reviewing_any_rendered_unit
  MUST: |
    逐屏读取当前状态下的可见文案，检查是否混入与当前用户和任务无关的
    实现或调试信息、内部标识、面向开发者的说明，以及解释设计或实现、
    自我介绍、重复界面已表达信息而没有用户决策价值的生成式套话。
    对确认的问题记录原文、位置、用户影响和对应截图；优先删除，
    确有用户价值的信息改写为与当前任务有关的行动、后果或恢复方式。
  MUST_NOT: [flag_necessary_format_eligibility_consequence_or_recovery_help,
             flag_domain_appropriate_or_developer_product_terminology,
             infer_visible_copy_from_source_alone]

RULE @native_select_presentation:
  WHEN: rendered_unit_contains_native_select
  MUST: |
    在真实浏览器检查默认、聚焦、已选和展开状态；原生弹出层无法截图时，
    记录实际操作结果与未取得的视觉证据，不冒充看过。
    通过关闭态整体或局部截图核对下拉箭头与右边框有清晰间距，
    选中文字不与箭头或边框重叠，且控件外观已纳入产品控件样式而非裸用默认外观。
    计算样式只用于辅助定位；实测贴边、重叠或默认外观偏差列为差距并附证据。
  MUST_NOT: [flag_select_tag_or_native_popup_alone,
             infer_arrow_geometry_from_stylesheet_alone,
             require_custom_select_reimplementation]
```
