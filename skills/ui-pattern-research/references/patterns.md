# 模式判断与来源

以下为本 skill 的选型启发，不是每个项目的强制规范。先核实业务契约，再选择相关模式；官方来源支持局部依据，产品方案仍需自行判断。网站与组件 API 可能变化，使用时核对当前文档及项目版本。

## 筛选器

- 找已知名称可先用文本查询；只按少数明确属性筛选可用搜索加选择器；确有多属性、多值或逻辑组合需求时再考虑属性条件与查询构建器。
- 核对前后端支持的运算符、组合逻辑和作用范围。远程分页不能用「过滤已加载行」冒充全库筛选；无法提供全量查询时明确限制。
- 根据查询成本和用户是否需要一次设置多项，决定即时应用或显式提交。说明当前显示的是草稿条件还是已应用条件；处理加载、过期响应、失败、清空和无匹配，确定条件变更后的分页行为。
- URL 同步、保存条件和跨会话恢复仅在任务需要且语义明确时加入。

依据：[Cloudscape Filtering patterns](https://cloudscape.design/patterns/general/filter-patterns/)按资源复杂度和用户目标区分文本、选择器和属性筛选。这是比较起点，不要求项目采用 Cloudscape 的控件或全部运算符。

## 表格与批量操作

- 列间比较适合表格；需要单元格方向键导航或密集编辑时，再评估交互网格及其焦点管理成本。表格里有链接、复选框或按钮，不自动要求使用 `role="grid"`。
- 区分本页、跨页已选 ID、当前查询全部结果。表头选择框和操作条必须准确表达范围；服务端没有按查询执行或集合快照等能力时，不能承诺操作全部匹配结果。
- 明确翻页、筛选、排序、刷新后的选择策略，用稳定 ID 识别对象。保留不可见选择时显示其存在并提供清除方式；改变范围时不能悄悄扩大操作对象。
- 处理可操作与不可操作对象混选、执行中重复提交及逐项结果。部分失败时区分成功、失败、结果未知；重试范围、幂等性和重新确认状态依赖接口契约，不自动重放全部请求。
- 接口有单次数量上限时，比较「把选择限制在一次请求内」与「前端分批提交」。分批时说明批次顺序、某批失败后继续还是停止、用户离开或刷新页面时已发送与未发送部分的状态，并在结果中区分未发送项。
- 窄屏优先保留对象身份、状态和主操作；是否横向滚动、隐藏次要列或改成摘要列表取决于比较任务，不默认全部改卡片。

依据：[WAI-ARIA Table](https://www.w3.org/WAI/ARIA/apg/patterns/table/)说明表格可包含各自进入 Tab 顺序的控件，且鼓励使用原生表格；[Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)要求开发者管理内部焦点。[Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)提供选择后出现批量操作条的参考；它是可选交互例子，不代表当前后端支持跨页执行。

## 权限编辑

- 先确认谁给谁、对哪些资源授予哪些操作，以及继承、覆盖与有效权限如何计算。读取接口和产品规则；没有规则时不能通过控件样式发明优先级。
- 需要横向比较角色与资源/操作，且维度可控时，可比较矩阵；存在真实父子结构时可考虑树形导航；资源多且授权稀疏时可比较分组列表加详情。根据实际任务选择，不能只按资源数量设固定阈值。
- 区分直接配置、继承来源与最终有效结果。部分选中的 `mixed` 状态不能兼任继承、显式拒绝或只读语义；是否存在「拒绝」状态必须有业务依据。
- 聚合勾选是否影响后代、隐藏项和不可修改项，必须明确；只读或继承项说明原因。保存前后的变更摘要及生效时机按任务风险和接口能力设计，不把 UI 禁用当成服务端权限校验。

以上是产品选型启发。若选用树形表格，再核对 [WAI-ARIA Treegrid](https://www.w3.org/WAI/ARIA/apg/patterns/treegrid/) 的键盘与焦点模式；采用树形控件不意味着权限本身必然继承。

## 行内编辑、抽屉、详情页与向导

- 少量独立字段、保存局部且错误易定位时，可用行内编辑；需保留列表上下文并反复查看不同对象时，可比较抽屉或分栏。
- 深层内容、独立访问或复杂编辑可比较详情页；真正有先后依赖、需要分阶段决策时再考虑向导，不只因为字段多就分步骤。
- 无论采用哪种容器，都说明对象切换、关闭、后退和提交失败时如何处理未保存修改；根据模态或非模态行为定义焦点进入、返回和键盘退出。
- 在窄屏确认列表上下文是否仍可用；必要时以同一任务的全屏视图承接，不凭桌面抽屉截图假定手机体验成立。

这些是候选方案的比较维度，不是对某个外部产品已观察行为的断言。已有组件库时先查其容器、表单和导航契约。
