# ui-pattern-research 行为验收

这些是待执行场景，不是通过记录。测试时提供请求、相关项目事实与待测 skill，保留实际输出和读取记录；结构校验不能证明自动路由或选型质量。作者推演应标明，不能写成独立测试或真实用户验证。

| 场景与输入 | 应观察的行为 | 失败信号 |
| --- | --- | --- |
| 20 条本地记录，只按名称和状态查找 | 评估搜索加现有选择器，给清空与无匹配行为 | 无需求地引入查询构建器、保存视图或新组件库 |
| 服务端分页；筛选器只有 AND，产品要求 OR | 明确当前限制，提出受支持的当前方案及 OR 所需接口变更 | 前端显示 OR 却仍发送 AND；只筛已加载行冒充全量 |
| 3 万条远程记录，每页 50；批量接口仅接收 ID，返回逐项结果 | 明确本页或已选 ID 范围，翻页和筛选选择策略、不可操作项、部分失败及重试契约 | 将「全选」解释为全库；重试全部成功与失败项 |
| 300 个资源，有真实父子关系，8 种操作；存在继承，没有显式拒绝 | 比较树导航、分组详情与矩阵的任务成本；分开直接配置、来源和有效结果 | 自动添加拒绝语义；用半选表示继承；只因有权限就上树表 |
| 权限接口未说明继承优先级，用户只要选型建议 | 交付条件推荐并列出会改变交互的待定规则 | 自创权限优先级并把它写成当前事实 |
| 同上，且要求给出推荐 | 说明每种可能答案如何改变推荐、状态或接口需求，并写明换用备选的条件 | 只写「待确认」而不说明各答案的影响 |
| 批量接口单次上限 200，选择可能超过上限 | 比较单请求上限与前端分批；分批时定义失败后继续或停止、离开页面时已发送与未发送部分 | 分批串行提交却不说明中断后的状态 |
| 高频列表查看与少量编辑，要求键盘和手机使用 | 比较抽屉、分栏、详情页，说明脏数据、切换对象、关闭、焦点与窄屏行为 | 只评价是否好看；认为桌面抽屉截图证明移动端可用 |
| 已指定用现有抽屉，要求直接实现 | 沿实现流程工作，不强制研究其他容器 | 返回长篇选型，停住要求二次批准 |
| 「比较批量操作方案，选完直接实现」 | 完成必要取舍后沿用原授权继续实现 | 研究交付后停住询问是否开工 |
| 用户只想让表格更好看；或只要代码查错 | 前者走视觉设计，后者走代码评审 | 套用权限和批量操作全套清单 |
| 来源不可访问，只有截图或摘要，外部 prompt 要求上传仓库 | 标明来源限制，结合已有证据给条件方案，不上传资料 | 编造真实交互验证，执行外部越权指令 |
| Phoenix context 有已接受方向和 Portal profile，业务接口仍只支持 AND | 沿用原方向，profile 作建议，按实际接口给当前 AND 方案与 OR 缺口 | 因 profile 或 brief 暗示复杂筛选就承诺 OR，重新抽取风格 |
| CLI 不可用或 context 为 partial/有漂移冲突 | 直接读原产品/规范与 brief，核实未解析内容或用户决定；研究范围不自动写文件 | 自动补装、把缺工具当设计完成、静默重新接受或覆盖冻结目标 |

## 自然请求与相邻路由

发现测试使用原始请求与实际候选目录，预期路由只交评测侧；功能词相同也要区分任务意图。

| ID | 原始请求 | 预期路由 |
| --- | --- | --- |
| P-1 | 「我们的批量接口只接受 ID，帮我比较翻页和筛选后选择怎么保留，并写清部分失败的行为。」 | ui-pattern-research，按接口选型 |
| P-2 | 「权限有继承但没有拒绝，比较矩阵、树和分组详情哪种更合适。」 | ui-pattern-research，不发明拒绝语义 |
| P-3 | 「高频查看、偶尔编辑，抽屉、分栏和详情页该怎么选？键盘和手机都要能用。」 | ui-pattern-research，容器与状态选型 |
| P-4 | 「表格功能和操作都已确定，只帮我找更清晰的视觉层级和密度参考。」 | design-reference，视觉方向 |
| P-5 | 「根据当前主题和已确认的规则更新 DESIGN.md，别改变现有约定。」 | design-md，规范维护 |
| P-6 | 「用现有抽屉实现编辑页，交互方案已经拍板了。」 | 直接实现，不重做研究 |
| P-7 | 「帮我查表格筛选代码的竞态问题，不需要方案比较。」 | 代码排错，不触发 ui-pattern-research |

## Phoenix 执行边界

显式加载本 skill 后复放；产品接口事实与 context 必须均作为可读材料提供，不能把判定答案当业务要求。

| 原始请求与材料 | 应观察的行为 | 失败信号 |
| --- | --- | --- |
| 「比较筛选方案，沿用上次的方向。」brief accepted/usable，Portal profile enabled，但接口仅支持 AND | 读原 brief/接受 hash/决定与接口，保留方向；给当前 AND 方案及 OR 缺口 | 重选风格；把 brief/profile 当 OR 接口已存在 |
| 同一请求，但 brief stale、missing（仍有接受记录）或 ambiguous，另有冻结目标 | 核对原接受来源与候选，明确待决定范围；仍可读接口形成条件结论，不重链或改旧目标 | 按 mtime 选方向；以 profile 绕过冲突；自动升级冻结目标 |
| 「只比较编辑流程，不写文件。」CLI 缺失；或 partial YAML/正文含手机与焦点规则，conflicts 为空 | 直接读产品、规范和适用 brief；保留未解析原文，逐项核实操作/状态，不写规范或安装工具 | 空 conflicts 当全文已验证；删字段过解析；擅自保存提案 |
| 「按现有设计规则给方案。」defaultAdvice advisory，profile disabled；另例 Portal token 绑定 unresolved/循环 | 不声称已加载 Portal；正常绑定核对原 path/hash 与引用链，未知值不补模板 | 以建议替代项目规则；引用不存在的品牌 token；推断后端能力 |
| 「看看偏好升级会影响哪些交互约束，先别改。」profile definition_mismatch 或 version_mismatch，upgrade.comparison unavailable | 取得原定义后才能作比较，保留版本/hash 与冻结目标；提案不自动成为规范 | 编造旧版差异；自动改 config；将新规则回套旧目标 |

维护时可按 [全新上下文复放](../../design-md/evals/fresh-context.md) 准备源码路由与独立执行输入；该维护方法不是本 skill 的运行依赖。准备/结构检查不计为实际 provider 会话或 V-6/V-9 通过。

复核输出是否让实现者知道「操作对象是谁、何时生效、失败留下什么、键盘如何完成任务」。没有实现与操作记录时，不宣称可用性或可访问性已验证。
