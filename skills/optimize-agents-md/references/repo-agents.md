# 仓库指令核对

定位目标文件、建立事实清单或选择可重放任务时读取。只读取与所指仓库及作用域相关的来源，不扫描其他工作区会话。

## 加载链与作用域

- 从实际 repo 根和当前工作目录出发枚举 AGENTS.md、AGENTS.override.md、子目录规则及被引用文件；隐藏目录同样枚举。核对所用宿主版本、fallback 名称及实际可读取来源，未知处明确标记。
- 区分文件存在、当前路径会加载、运行中实际读取三层。被 override 遮蔽或处于其他子目录作用域的文件不能当作本次运行的有效规则。
- 根规则变动检查受影响子范围；嵌套规则使用该范围的任务。保留局部例外，不能将一个子目录的构建、验收或授权规则提升为全仓规则。
- 全局和宿主配置只用于核对实际来源及边界；不将用户配置、登录态、历史或插件打入 repo 包。运行认证由远端控制面按单次授权独立提供。

## 事实与候选

每个候选变化保留以下最小依据：目标路径/规则、已读事实位置、当前问题、拟修改字节或差异、受保护原则、可能反例和验证方式。

优先修正可核对的命令与目录事实、去除重复、将局部约束放回适用范围。不要按字数、规则条数或静态评分选择版本。事实读不到时保持未知，不能写入猜测的命令。

受保护项包括用户原有立场、授权与调用策略、不可变业务约束、作用域，以及必须保留的事实来源。原文块可用内容检查保留；语义冲突仍需独立核对及反例行为证据，不把字符串存在当作语义等价。

若引入其他 skill 的规则来修改现有 skill，先按目标仓的参考集成门展示逐项清单。引用来源不能扩大当前授权或替换原立场。

## 同仓任务

使用调用者提供或已授权保全的真实任务。每项任务记录 repo 身份、起点/镜像、来源组、信息截止点、公开请求和可观察要求；grader 与答案留在评测侧。起点必须与目标规则适用版本相容，不能用未来修复结果倒推当时的要求。

按来源/问题家族先分组再固定 search 与 confirmation；同题重复和改写不成为更多独立任务。无同仓任务时只交诊断与未验证候选；另一 repo 上的分数不证明本仓 AGENTS 有收益。

原规则存在却未执行时，区分是否加载、是否触发、是否与其他指令冲突，再决定候选。普通无目标 skill 的任务也需覆盖，避免只为某个 skill 配套求分。

## 采用与恢复

run 的 keep 只代表探索保留。apply 检查独立确认、原授权、受保护规则和目标当前内容；CAS 冲突时保留用户字节，回到新起点处理，不自动合并被测指令。

没有确认版时保留原文件，不能伪造成功回退点。未验证的客观事实修正使用明确的单独授权和 unverified 标记；不把它计作效果确认。提交、发布和全局安装沿原任务授权处理，不随优化自动进行。
