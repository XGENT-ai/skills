## Coding Principles

Odyssey 片段：`RULE` 声明本文作用域内的常驻规则；`MUST` 必须，`MUST_NOT` 禁止，`SHOULD` 通常应满足，`PREFER` 在不冲突时优先；`=>[a, b]` 表示若 a 则 b，`&&[a, b]` 表示同时满足。直接嵌入 AGENTS.md，不加外层包装。

```formal
RULE @execution_basis:
  MUST: ["Execute based on the current user request, applicable AGENTS.md or active development plan.",
         "Treat historical plans, handoffs, old prompts and old audit feedback as factual background only."]
  MUST_NOT: historical_material_independently_authorizes_or_expands_current_work

RULE @think_before_coding:
  MUST: [state_assumptions_explicitly_before_implementation,
         when_uncertain_or_confused_stop_identify_and_ask,
         present_competing_interpretations_and_tradeoffs,
         surface_simpler_approaches, push_back_when_warranted]
  MUST_NOT: silently_choose_or_hide_alternative_interpretations

RULE @simplicity:
  MUST: [simplest_correct_solution,
         "Validate only at system boundaries, including user input, external APIs and files.",
         "Trust internal code, established contracts, invariants and framework guarantees.",
         handle_only_real_actionable_failures]
  MUST_NOT: [speculative_abstractions, unnecessary_fallbacks,
             excessive_defenses, impossible_scenario_guards,
             repeated_validation_along_internal_call_chains,
             layered_catches_or_silent_recovery_masking_programming_errors]

RULE @scope:
  MUST: [implement_requested_scope_only, preserve_existing_patterns,
         reuse_or_simplify_before_abstracting,
         allow_deleting_confirmed_unused_code_within_agreed_scope]
  PREFER: small_changes
  MUST_NOT: ["Add unrequested features, configuration, compatibility layers, UI or architecture changes.",
             "Add feature flags or backward compatibility shims when direct code changes suffice.",
             "Add compatibility hacks through underscore renaming of unused variables or type reexports."]

RULE @requirement_confirmation:
  WHEN: non_brainstorming
  MUST: [propose_unrequested_requirements_only_when_deemed_necessary,
         obtain_user_confirmation_before_adopting_suggested_requirements]
  MUST_NOT: unilaterally_add_unrequested_requirements

RULE @legacy_compatibility:
  UNLESS: user_explicitly_requests_legacy_compatibility
  MUST_NOT: [add_legacy_compatibility_requirements,
             add_legacy_mode_branches_or_compatibility_layers]

RULE @user_experience:
  MUST: [design_around_user_expectations, user_facing_copy_serves_users]
  MUST_NOT: ["Put unnecessary engineering details, internal state or obvious interaction explanations in the UI.",
             "Put developer notes, implementation comments or internal instructions in the UI.",
             "Add prompts or warnings unless they help meaningful decisions or prevent major errors."]

RULE @current_documentation:
  MUST: [comments_explain_why,
         "Add comments only for nonobvious logic or code that is not self explanatory.",
         "Update or remove stale comments and documentation when behavior changes.",
         current_concise_searchable_sources_of_truth,
         code_comments_and_docs_present_correct_current_result,
         explain_current_rationale_without_discarded_alternatives,
         task_status_discloses_actual_failures_and_unverified_items]
  MUST_NOT: ["Add docstrings, comments or type annotations to otherwise unchanged code.",
             comments_paraphrasing_code,
             "Leave development error stories, discarded plans, historical corrections or explanations of why X was not done in code comments and documentation.",
             accumulate_history_or_append_corrections_to_stale_text,
             "Add AI attribution markers such as Generated by or AI Co-authored-by signatures.",
             "Add formulaic model transitions or openers such as here is to authored output.",
             duplicate_documentation]

RULE @evidence:
  MUST: ["Read relevant source, specifications and documentation passages fully before drawing conclusions.",
         cover_relevant_sections_and_tail_of_long_documents,
         disclose_unverified_items,
         investigate_existing_behavior_and_contracts_before_changes,
         acknowledge_correct_work_when_supported_by_evidence]
  MUST_NOT: [infer_unread_content, invent_requirements_or_constraints,
             manufacture_findings_for_appearances_or_review_quotas]

RULE @meaningful_tests:
  MUST: [protect_meaningful_behavior_key_boundaries_and_real_regressions,
         exercise_interfaces_from_external_caller_perspective,
         assert_actual_caller_observable_outcomes,
         "Delete tests that still pass when all tested function bodies are empty and return no data.",
         remove_obsolete_or_redundant_tests_within_agreed_scope,
         "Reuse valid verification when relevant code, configuration and conditions are unchanged.",
         run_smallest_relevant_check]
  MUST_NOT: [redundant_tests, trivial_assertions, implementation_coupled_tests,
             per_function_coverage_chasing, exhaustive_imaginary_failures,
             add_unnecessary_regression_burden,
             "Repeat the whole suite solely for reassurance or because a report was challenged."]

RULE @live_uncertainty:
  MUST: |
    Before any check, state in one sentence the specific unresolved failure it will
    detect and how failure would change the next action; if either cannot be stated,
    do not run it. Default to one minimal real-data sanity check and one recheck
    directly tied to the change, only when each answers a live uncertainty.
    Reuse a completed real full run that covers the same path; do not add a smoke
    check for that path. Add further checks only for a newly observed concrete failure.
    Scope required acceptance up front from the current execution basis; this default
    does not waive explicit acceptance requirements or authorize extra checks at milestones.

RULE @automated_test_scope:
  MUST: automated_tests_assert_outcomes_produced_by_deterministic_code
  MUST_NOT: [write_automated_tests_for_llm_output,
             write_automated_tests_for_static_source_text]

RULE @complete_milestones:
  MUST: [prioritize_quality_and_completeness_over_token_savings,
         "Apply full effort to required reasoning, investigation, implementation and verification.",
         concise_communication, respect_agreed_scope_and_stopping_rules,
         autonomously_finish_actual_remaining_work_within_agreed_scope,
         fix_related_in_scope_defects_found_during_verification,
         understand_full_scope_and_acceptance_before_long_tasks,
         deliver_coherent_complete_milestones,
         working_first_correct_before_delivery,
         treat_forward_progress_as_part_of_delivery,
         verification_at_each_stage_follows_live_uncertainty,
         measure_progress_by_complete_usable_deliverables]
  MUST_NOT: [stall_unfinished_functionality_with_excessive_defensive_work,
             repeated_stops_after_fragmentary_changes,
             full_suite_after_every_micro_edit, test_frequency_as_progress,
             stop_at_findings_despite_actionable_in_scope_work,
             open_ended_hunts_for_hypothetical_or_unrelated_problems]

RULE @temporary_resource_cleanup:
  WHEN: code_and_test_reviews_completed
  MUST: ["Inspect task-related temporary directories, Git worktrees, branches and Docker containers.",
         identify_resources_safe_to_remove,
         verify_no_background_task_dependencies_before_cleanup,
         promptly_delete_safe_temporary_resources_to_reclaim_space]

RULE @proportionate_recovery:
  MUST: |
    Choose failure handling from actual user impact and the cost of starting over.
    For cheap, safely repeatable work with disposable intermediate state, default to
    reporting failure and allowing a fresh attempt; preserve existing user data and
    perform only the cleanup needed to make that attempt safe.
    Add transaction journals, checkpoints, resumable execution or recovery state
    machines only for an explicit requirement or demonstrated material loss of user
    data, nonrepeatable side effects or expensive rework, within the authorized scope.
    Use the smallest mechanism that addresses that concrete consequence.
  MUST_NOT: [infer_recovery_requirements_merely_because_interruption_is_possible,
             treat_optional_tools_as_critical_infrastructure_without_evidence,
             "Add old-version restoration or downgrade support without an explicit user requirement."]

RULE @complexity_budget:
  MUST: ["Ensure every added check, abstraction, dependency, error branch, test or UI element justifies its maintenance cost.",
         remove_redundant_complexity_before_adding_abstractions_or_dependencies,
         rethink_overcomplicated_design, complete_necessary_work_correctly,
         =>["Adding complexity for speculative or vanishingly unlikely race conditions or security edge cases.",
            &&["Explain the concrete failure mode, its likelihood and the complexity cost to the user.",
               explain_then_obtain_buy_in_before_adding_complexity]]]
  MUST_NOT: ["Add hashes, checksums or fingerprints unless they replace a materially more expensive operation AND their result changes the next action.",
             add_layers_to_an_overcomplicated_design,
             silently_expand_scope_for_theoretical_robustness]
  PREFER: fewer_additions
```
