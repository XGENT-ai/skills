# Optimize AGENTS.md

从目标仓库的事实和真实任务改进仓库指令。交付诊断、可审查的最小候选、实际验证等级，以及授权范围内的采用或恢复结果。

## 边界

- 沿用会话已有的 repo、文件、写入和远端数据使用授权，不逐轮重新询问。仅诊断保持只读；普通编码请求不附带指令优化或长期搜索。
- 保留原原则、立场、调用策略、授权与作用域。原文仍在不能证明新增内容与它不冲突；语义不明或原则冲突时不自动采用。
- 普通初始化沿用现有初始化入口及其已有文件保留约定。本 skill 不创建或镜像 CLAUDE.md，不安装全局 skill，不更新用户全局 AGENTS。
- Eval 持有判定，Hillclimb 持有搜索和唯一状态；agi-mode 仍保持显式调用。使用其可选执行工具不自动启用整个模式。
- 优化器、被测 agent 和判定执行使用远端独立环境；本机仅做确定性打包、编排和报告。缺能力时交付未验证候选，不切换成本机模型评测。

## 执行

1. 确定目标仓库、所指文件与操作范围。按 [仓库指令核对](references/repo-agents.md) 枚举根、嵌套、override、fallback 和引用来源，核对当前工作目录的实际加载链。被遮蔽文件不能冒称已经生效；变更另一文件须在既有授权内。
2. 从可读取的仓库命令、代码、配置与现有规则记录事实和受保护规则。逐项区分错误事实、重复、过时流程、作用域、冲突，以及规则存在但未执行的问题。每个结论指向已读来源；不从其他 repo 搬构建命令或业务规则。
3. 只读请求交付诊断并结束。优化请求提出一个有机制依据的最小候选，写明预期改变、可能回归与反例。已有工具能可靠执行的要求优先引用该仓现有工具；新增脚本或其他文件须在原范围内。原有规则未执行时先检查路由、可见性与冲突。
4. 需要行为比较或连续搜索时，定位实际安装的 agi-mode，并读取其中的 [远端执行手册](../agi-mode/references/remote-evolution.md)。工具路径以实际安装目录为准。任务必须属于目标 repo，具有可恢复起点、公开要求、固定验收和有限预算；新质量实验使用 v2，先冻结独立量表并 calibrate，确认能区分同样成功的不同产物，再检查基线余量、判定/生成噪声及预算可辨别性。默认诊断不通过则交付真实分数与缺口，停止自动候选生成；显式获准的 bounded_exploration_v1 仅在来源精度不足、其余质量门通过时最多一候选，不晋级/确认/采用，整体 inconclusive。不把任务成功等同高质量，也不改目标追分。保护 confirmation 材料，搜索者只收 search 视图。TypeSafe 仅在既有材料导出授权、独立辅助校准和子预算内提供 search 线索，主分及采用权仍由原评测持有。无同仓任务、环境或数据导出授权时，保存可审查候选并明确缺口，效果为未验证。
5. 冻结唯一候选和量表后按固定协议独立确认。确认通过、原则核对通过且已有写回授权时，使用统一工具的 apply 重算原质量证据、检查全部资源/凭证清理及当前文件 CAS 后采用。TypeSafe 不参加确认评分，辅助高分不能替代主质量或底线；报告同时交付 task_success、逐项 task_quality、依据和未知项。确认未通过时保留原文件与候选；客观事实修正的未验证写回仅在其单独明确授权下进行，标记 unverified，不更新 confirmed_best。

交付实际差异、事实来源、keep/discard/inconclusive/invalid、最终确认状态、调用/资源与未知成本、适用仓库/任务范围和恢复入口。文件可加载、内容被读取、任务结果改善分别说明；没有行为对照时不宣称能力提升。
