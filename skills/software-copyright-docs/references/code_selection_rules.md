# 代码抽取规则

## 选择方式

脚本只生成候选源码清单，不默认决定抽取文件。模型需要先理解项目业务、页面入口和源码职责，再决定抽取哪些完整文件，并在 `代码文件选择.json` 中填写：

- `selected`
- `model_reason`

选择时通常优先考虑审核员能看懂软件功能和运行逻辑的源码，例如入口、页面、业务组件、数据交互、状态处理、业务服务等。具体选择由模型根据项目实际判断，不能用固定路径规则直接拍板。

候选发现采用内容检测而不是编程语言扩展名白名单：可读、大小合理且不属于明确文档/配置/二进制类别的文本文件都进入候选范围。新增语言、游戏引擎脚本或项目自定义脚本不需要先修改扩展名列表；候选是否与申报软件相关，仍由模型和用户在确认门禁中决定。

## 排除项

排除以下内容：

- `node_modules`
- `dist`、`build`、`.next`、`.nuxt`、`coverage`
- lock 文件
- 图片、字体、二进制文件
- sourcemap、minified 文件
- 自动生成文件
- 过短且无业务意义的配置文件

## 真实性要求

- 保留原始代码结构和非注释文本；注释仅按下述规则清理 AI 痕迹。
- 可添加文件路径标记用于追溯。
- 不改写业务逻辑。
- 不使用 AI 补齐代码。

## 注释中的 AI 痕迹清理

选中的源码包含注释时，模型必须逐文件审读，并在提交 Markdown 草稿确认前完成清理；只修改代码材料副本，不修改原项目源码。

- 删除仅描述 AI 生成过程、没有技术信息的注释，例如“由 ChatGPT 生成”“Generated by AI”、模型对话口吻、提示词残留或“下面为你实现……”等说明。
- 注释同时包含 AI 痕迹和技术信息时，只去掉生成来源、对话口吻和空泛套话，保留业务含义、设计原因、约束和必要说明，改成简洁、客观的技术注释。
- 不得因出现 AI、模型名或工具名就整段删除；软件自身的 AI 功能、模型调用和相关业务规则属于真实技术信息，应保留。普通技术注释、版权声明、许可证和第三方归属说明也必须保留。
- 注释中的 emoji 由 `extract_code_material.py` 在抽取时自动删除，「」自动换成“”，字符串和界面文字不改；人类很少在注释里写 emoji，它会被视为 AI 痕迹。
- 只清理注释中的自然语言，不修改标识符、字符串、业务逻辑或具有运行、编译、类型检查等作用的指令性注释，不新增源码中没有的技术结论。
- 清理后核对材料行数、分页及 `代码提取清单.md/json` 中的来源映射；发生变化时同步更新，再交用户确认，不能直接沿用清理前的统计和范围。

## 用户确认要求

- 代码抽取前必须先生成 `代码文件候选清单.md` 和 `代码文件选择.json`。
- 模型必须先填写抽取选择和 `model_reason`，再让用户确认或手动调整 `selected`。
- 代码材料按确认后的完整文件抽取并去除纯空行，不支持只截取某个文件的中间行段，避免遗漏上下文或产生难以追溯的片段。
- 抽取脚本必须以 `代码文件选择.json` 为准，不能绕过确认步骤直接抽全量代码库。
- `代码提取清单.md` 必须记录每个文件的完整源码范围和材料行范围，便于回溯。
