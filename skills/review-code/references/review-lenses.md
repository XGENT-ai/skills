# 审查视角与取舍

这些是调查线索，不是自动判错规则。每项仍须通过主流程的引入性、影响和证据门槛。

| 视角 | 需要追踪的行为与证据 |
| --- | --- |
| 需求符合性 | 用户请求/计划中的本期验收 → 入口 → 实现 → 可观察结果；遗漏、误解和越界是否产生实际契约或范围后果。需求歧义列待决策，不用“常见做法”替作者决定 |
| 正确性与兼容性 | 调用链和状态转换、边界与错误路径、重试/幂等/并发、事务与资源释放；API/类型/序列化/配置默认值变动对现有消费者的具体影响 |
| 安全与数据 | 不可信输入是否可达危险操作、身份与对象级授权/租户隔离、敏感数据流、注入、路径与请求边界；数据迁移、约束、失败回滚和读写兼容性。报告敏感证据时隐藏实际密钥 |
| 性能与资源 | 真实规模下的查询次数、无界读取/队列/循环、阻塞、缓存一致性、订阅或连接泄漏；复杂度与实测分开，不强制缓存/批处理，不虚构毫秒或容量 |
| 测试与交付 | 测试断言是否能捕获改变的行为，mock 是否掩盖协议/权限/事务，回归用例能否在基线失败而目标通过；构建、入口接线、配置、依赖和部署产物是否一致 |

## 可选开发计划

只核对所审变更承担的任务与验收。最小映射为 `需求/章节 → 本次任务 → 实现证据 → 验证状态`，状态区分已核实、存在缺陷、未核实、后续范围。不要求计划必须采用某个模板或有正式 ID。

计划符合性发现问题后仍继续安全与正确性审查，不用“先修计划偏差”跳过其他风险。用户明确改变需求时以当前用户要求为准，列出与旧计划的差异；不自动改计划，也不把服从新要求视为缺陷。没有被本次变更触及/承诺的旧功能缺失不属于新增问题。

无测试本身不自动成为 finding。说明本次改变的哪个重要行为无法被现有测试保护，以及具体失败风险；若缺陷已在 findings 中，测试建议归入同条，避免重复计算。仅凭测试覆盖率数字不能宣布质量达标。

有 UI 时按变更检查主要路径、加载/空/错误状态、键盘操作和可访问性。静态推演、实际浏览器走查、自动化结果分开记录；没有运行页面不声称视觉或交互验证通过。

## 来源与有意取舍

以下是本 skill 的设计来源，运行评审时无需加载来源文件：

- **Codex CLI 0.159.3**（2026-10-02 本机 `codex --version`、`codex review --help` 及二进制内嵌 review prompt）：沿用新增且可行动的缺陷门槛、具体受影响代码证据、允许空 findings、P0–P3、短 diff 定位、适用仓库规则引用、单段说明和不自动修复。官方 [CLI 文档的 review 说明](https://learn.chatgpt.com/docs/codex/cli) 也列出未提交、commit、基准分支三类入口。
- **`local/code-review`** 的 `SKILL.md`、`references/requesting-code-review.md`、`references/verification-before-completion.md`：吸收明确评审范围、证据先于结论、反馈先核实；不引入每个实现任务都必须再派 reviewer、固定包管理器或自动修复的流程。
- **`local/code-reviewer/SKILL.md`**：吸收快速筛查逻辑、导入导出、安全和性能线索；不采用每次保存触发、固定函数行数阈值、模式匹配即报错或未经实测的速度承诺。
- **`local/code-reviewer2/SKILL.md`** 与 `references/spec-compliance-review.md`、`references/review-checklist.md`、`references/report-template.md`：吸收先理解意图、需求映射、多维审查和可行动反馈；不强制赞美、建议代码或因需求未通过而停止其他审查。
- **`skills/review-dev-plan/references/report-contract.md`**：沿用完整报告默认落盘、路径优先级、防覆盖、单写者、回读和失败披露。代码报告用 `.code-review.md` 区分计划报告的 `.review.md`；不继承计划的就绪状态或固定四 reviewer 编排。

commit 范围、可选计划映射和 `inconclusive` 是本 skill 的扩展。默认 Markdown 是有意选择，并不宣称与 Codex 原生 review JSON schema 完全相同。以上内容是综合后的工作约定，不复制社区技能的整套协议。
