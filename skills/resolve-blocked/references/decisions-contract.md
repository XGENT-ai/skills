# 阻塞决策记录合同

## 路径与续写

- 路径优先级：用户指定路径 → 本地计划同目录的 `<计划文件名去掉扩展名>.decisions.md`；例如 `goal/LOGIN.md` 对应 `goal/LOGIN.decisions.md`。计划只有远程链接或聊天文本时，遵循仓库文档目录约定；无约定则写 `docs/plan/<主题短名>.decisions.md`。按需创建目录。
- 每份计划只维护一份决策记录，多次运行按轮次续写。已存在时读取后续写：沿用已有 B-ID，新增项分配未占用编号；已确认的决定不改写。新决定推翻旧决定时，旧条目保留并标注“被 B-xx 取代”，新条目写明取代原因。
- 每轮在「处理轮次」追加一行；阻塞总览的结果列只写最新状态并注明轮次；逐项记录的后续轮次结论追加在条目末尾，不改写前几轮。「未解除阻塞」与「就绪结论」反映最新一轮。无实质变化的重跑不追加轮次。
- 本地链接相对**记录所在目录**计算，不写机器绝对路径。
- 无法写入时说明“决策记录未落盘”、原因与目标路径，并在聊天中给出完整内容；不声称已保存。

事实可查的项可省略“选项”和“推荐与理由”，结论写证据。负责人未知写“待指定”，不虚构承诺。

## 结果状态

| 状态 | 使用条件 |
| --- | --- |
| 已解除（证据） | 查证得到足够事实，计划已据此修订 |
| 已解除（用户确认） | 用户明确选择或授权按推荐，计划已据此修订 |
| 降为非阻塞 | 用户确认或证据表明不影响开工，计划已移出阻塞并保留风险项 |
| 不再适用 | 范围调整等使该项失去意义，写明依据；不等于已解决 |
| 重新打开 | 已解除项的计划落点被删改或推翻，需要重新处理；保留原结论并写明依据 |
| 仍阻塞 | 缺证据、外部依赖未到位，或用户未作答 |

只有用户的明确回答才能形成“用户确认”；默认值、空回答、超时一律记为仍阻塞。
