# agi-mode 自进化方法论

本方法用于让 agent 从真实任务中积累经验，提出可检验的改进，并用实际结果决定保留、撤回或继续调查。最终要评估的是：**agi-mode 能否利用经验，在既定目标与资源约束下，持续找到并验证有效改进。**

本文面向维护这套技能与组织实践的成员，说明通用方法、证据要求、运行顺序和能力评价边界。具体执行规则由 skill 内的 playbook 与 reference 维护，本文提供整体解释与阅读入口。

当前工作重点是保存可用样本、建立证据关联，为后续实践准备材料。文档约定已经形成，不代表自动采集已经接入，也不代表自进化能力已经得到实证。

## 1 自进化的对象与评价层次

本仓的进化可以改变技能指令、prompt、工具或执行流程，也可以改进任务中的代码与配置。每轮先限定允许修改的对象，再研究它对真实效果的影响；不能用规则数量、修改次数或自我评价作为能力证明。

需要始终区分三个层次：

| 层次 | 回答的问题 | 需要的证据 |
| --- | --- | --- |
| 进化方法 | agi-mode 怎样从经验中找到、筛选和确认改进？ | 可见样本、机制假设、实验选择、验证、成本及去留依据 |
| 被优化对象 | 本次允许改变什么？ | 初始版本、候选差异、父版本、采用版本与恢复点 |
| 效果环境 | 使用这个对象完成任务，实际发生了什么？ | 当时的输入、执行条件、产物、验收结果、失败与补救成本 |

被优化对象最终表现良好，可能来自原有能力、人工补救或环境变化。要评价进化方法，还需要核对改动、执行条件和效果之间的关系。一次失败同样不能直接归因于某个 skill；归因不足时保留未知。

具体业务为这套方法提供实践环境。一个案例的有效改善支持该条件下的结论；对通用能力的判断需要来自不同任务族的证据。层次与记录约定见 [进化证据](../skills/agi-mode/references/evolution-evidence.md)。

## 2 通用方法与实践案例分别维护

agi-mode 内维护任务无关的规则：如何建立结果契约、取得信息、比较候选、验证、恢复、收敛，以及怎样保存进化证据。业务字段、阶段结构、采集入口和效果解释放在实践案例或目标项目中。

本仓的职责分工如下：

| 部分 | 职责 | 交付给下一环的内容 |
| --- | --- | --- |
| [Eval](../skills/agi-mode/playbooks/eval.md) | 建立并持有判定协议，校准评测，管理可见性与不确定性 | 有依据的采用、拒绝或证据不足结论 |
| [Hillclimb](../skills/agi-mode/playbooks/hillclimb.md) | 持有搜索状态，提出假设，执行实验，管理最佳版本和退出 | 可追溯的候选、尝试记录与最终确认状态 |
| [Arena](../skills/agi-mode/playbooks/arena.md) | 在有价值的设计分叉上产生不同候选，比较并合成 | 候选与比较依据；合成结果需要重新验证 |
| [Reflection](../skills/agi-mode/playbooks/reflection.md) | 从授权材料中提炼有出处的教训、反例和机制假设 | 值得试验的修改建议，不能替代效果验证 |
| [Skill 编写](../skills/agi-mode/playbooks/authoring-a-skill.md) | 把有依据的变化落实到合适的指令或结构位置 | 最小修订及其实际验证等级 |

各部分共享目标、协议和记录，按当前缺口调用。无需每次都运行全部流程。`autoresearch`、`arena`、`reflect` 保留为对应内部流程的兼容入口；通用流程的权威位置在 agi-mode，具体协作见 [技能演化约定](../skills/agi-mode/references/skill-evolution.md)。

评测规则的修订与候选改进分别进行：候选在固定规则下接受检查；发现评测错误时，先保留旧结果，修订协议并重测可比基线。不能同时修改对象与评分口径，再把分数变化全部算成对象的改进。

## 3 两类数据共同支持能力评价

### 工作样本

工作样本记录真实任务的输入、处理条件、产物和效果。它可以来自已经保存的文档、代码、阶段记录、测试输出、截图或用户反馈。材料的格式不决定价值；能否恢复当时情境并核对结果才决定它支持什么判断。

| 内容 | 最少需要保留的信息 |
| --- | --- |
| 身份与来源 | 稳定身份、项目／任务来源、同源关系和关联阶段 |
| 当时的任务 | 请求、已知约束、确认的决定及信息截止点 |
| 输入与输出 | 实际版本、可恢复位置、内容指纹；输入与输出分别记录 |
| 执行条件 | 实际使用的方法、可获取的模型／工具／环境配置；未知项如实标明 |
| 效果证据 | 原始产物与观测、适用版本、覆盖范围、首次及补救后结果 |
| 后续反馈 | 反馈发生时间、针对的原版本、依据及替代关系 |

反馈与事实分开保存。采纳意见不自动证明意见正确，拒绝意见也不自动证明它是误报。没有发现缺陷只支持已检查范围内的结论，不能把未观察到的行为记为通过。

### 进化尝试

进化尝试记录 agi-mode 如何利用样本改变被优化对象。它从开始实践时产生，不能根据最后版本反向编造。

每轮关联：进化方法的版本与运行条件 → 目标、范围、预算及可见样本 → 假设和来源证据 → 父版本与候选差异 → 实际验证及成本 → 去留理由 → 最终确认状态。沿用 [评测记录模板](../skills/agi-mode/references/eval-protocol.md)，不另建一套冲突台账。

**工作样本提供经验，进化尝试提供学习和选择过程的证据。** 只有前者，可以建立案例库；两者关联起来，才能评价 agi-mode 是否有效利用了经验。

## 4 保存边界和恢复能力

在三个时点保存有意义的状态：任务或阶段开始时保全输入，交付或中断时保全输出，后续效果到达时追加关联反馈。当前工作文档可以更新，归档版本与原始结果应当保持可核对。

优先复用已有版本和证据位置，避免重复复制。内容 hash 可以检查是否变化，但不能恢复文件。Git SHA 只有在对应内容仍可取回时才足够；未提交的修改、必要新文件和临时材料需要保留可恢复内容。不能等原稿已经修订，再把现状补记为原始输入。

截图、日志和报告必须关联它们实际观察的版本。截图可以支持界面可见状态，交互、数据语义或性能仍需对应证据。后续报告更新不会使旧截图自动成为新版本的验证；成功重跑也不能抹去前面的失败和补救成本。

只保存任务需要且已授权的材料，不要求完整聊天、每条命令或内部推理。缺失材料如实记录，采集失败与业务交付结果分别报告。恢复能力逐项判断：

- 能否核对历史效果及其证据范围。
- 能否还原某个阶段开始时的输入。
- 能否重新执行并产生可比较的新结果。

这三个能力可能不同时成立。只有效果记录的案例仍有复盘价值，但不能宣称它已经具备完整执行重放条件。

## 5 从历史材料建立可用评测

先明确需要改变的实际结果，再选样本和判定方式。样本应覆盖有价值的常见任务、重要失败、边界与不应触发的场景。不能只收成功项目，也不能只收某个模型恰好做错的题。

同一来源的任务链、修订和近重复保持同组。来源关系比文件数量更重要：一条任务链产生十份报告，不等于十个独立任务。

持续搜索时，将可见的搜索样本与未见的最终确认样本分开。数据充足且需要搜索中的泛化检查时，可以增加验证集；一旦验证反馈用于选择候选，它就属于开发证据。分组与可见性在搜索前确定，不能看到结果后重抽样本。

候选得到完成任务所需的公开要求和当时可见材料，后来的答案、修复与结果留给评判侧。目录、分支或 worktree 分开不保证信息隔离；实际权限、可读历史、缓存和上下文也要核对。做不到时明确评测限制。

判定器先接受校准：用已知好坏及边界产物检查是否能区分目标行为，核对真实评分依据。能运行客观检查时优先使用；需要判断时使用有证据锚点的标准。基础设施无效、候选行为失败与判定器波动分别记录，不能通过筛掉不利运行制造改善。执行细则见 [Eval](../skills/agi-mode/playbooks/eval.md)。

## 6 重放分为三个证据层级

| 层级 | 做什么 | 可以支持的结论 |
| --- | --- | --- |
| 历史效果复核 | 按明确口径重读原始产物与记录 | 原任务发生了什么、材料缺什么、哪些机制值得调查 |
| 代理验证 | 给候选当时的输入，检查决策、输出或错误识别是否变化 | 局部机制假设获得支持；仍需核对实际效果 |
| 实际效果验证 | 让候选参与新的可比执行，检查新产物和结果 | 候选在这些条件下产生的真实效果变化 |

历史材料不能直接给新候选赋予效果分。候选改变了工作步骤时，也不能机械使用旧工具响应或旧截图冒充新执行。环境无法恢复时，可以采用范围明确的替代实验，或在后续真实任务中收集证据，但结论必须对应实际执行层级。

分析者可以读取开发案例的完整历史来提出假设；候选执行者仍受阶段信息截止点约束。后来出现的要求或纠正不能倒推为当时已知输入。

## 7 运行有边界的进化实践

实践开始前固定目标、主指标、质量底线、最小值得采用的收益、可修改范围、比较条件和预算。保存初始基线、探索最佳和已确认版本，三者不能混成“最后一次尝试”。恢复方案只撤回本轮拥有的改动，保护用户工作。

每轮围绕一个机制假设推进：

1. 从允许读取的样本中找出问题，解释预期影响和可能回归，注明什么观察会推翻假设。
2. 从明确父版本产生候选。实现一个机制可以修改多处内容，但不堆叠无法归因的猜想。
3. 在固定协议下执行比较，先判断运行有效性，再检查质量底线、收益、不确定性与维护成本。
4. 记录保留、撤回、未定或无效及理由，再进入依赖它的下一轮。组合候选和移植片段都需要作为新版本重新验证。

连续有效尝试停滞时，先诊断任务、指导、执行、环境、评测和随机波动，不强求每轮都改代码或增加规则。评测有缺陷就修评测；已有指导未被执行就调查位置、冲突和可见性；需要结构分叉时才使用 Arena。

达到预设条件后，冻结候选，在未参与选择的代表性任务上确认。最终反馈一旦用于下一轮改动，这批材料就不再未见。确认失败时恢复仍有效的已确认版本，不能反复试同一确认集直到出现赢家。

保质降成本需要事前定义可接受的质量损失边界；“没有显著下降”不能自动证明保持。目标达到、用户停止、既有资源边界到达或后续探索缺乏合理信息价值时结束，并区分“目标达成”和“此次搜索结束”。完整流程见 [Hillclimb](../skills/agi-mode/playbooks/hillclimb.md)。

## 8 怎样评价 agi-mode 的进化能力

评价首先看独立确认的实际改善，再看获得改善所付出的代价，以及方法如何处理失败与未知。以下是评价维度，具体指标和门槛由实践目标预先确定：

| 维度 | 核对的问题 |
| --- | --- |
| 有效收益 | 相对初始对象，是否改善了真实效果？是否超过测量噪声且具有实际价值？ |
| 回归控制 | 是否保住质量底线和重要相邻场景？是否拒绝或撤回有害候选？ |
| 资源效率 | 在可比预算内，用多少实验、验证、运行和维护成本取得收益？ |
| 证据与判断 | 假设和结论是否有来源？能否区分未知、执行失败、环境无效与评测失真？ |
| 学习与迁移 | 能否避免重复已被反驳的方向？改进是否适用于未参与调优的任务？ |

过程记录用于核对方法是否可靠，不能抵消缺少实际效果证据。诚实地没有找到有效改进，可以证明某些判断与停止行为正确，但尚不足以证明具备改进能力。

若要比较不同进化方法，应保持被优化对象起点、任务分布、底层模型／工具、执行条件与总预算可比，分别记录方法版本和对象版本。底层模型升级或人工投入增加不能直接归功于进化规则。评价材料与确认反馈的可见范围也必须一致。

当修改对象就是 agi-mode 本身时，同样把新规则作为候选接受固定协议检查。候选不能通过改写评价标准或自评结论获得晋级。只有在相关输入、模型、工具与任务分布仍适用时，已有结果才支持复用；条件改变后重新检查受影响部分。

## 9 文档交付链作为实践案例

本仓选择 PRD、开发计划、评审和实施记录作为一种可持续积累样本的实践环境。它的价值是已有文件能够连接前期决策与后续效果：需求和计划描述承诺，评审指出问题，修订说明处置，阶段记录及验收材料呈现实际执行。

在这个案例中，被改进的对象是 `prd`、`dev-plan`、`review-*` 等生成与评审方法。评分依据来自它们引导的实际交付，包括用户目标是否兑现、体验与行为、回归、返工和必要人工补救。文档长度、章节齐全程度或评审意见数量只能提供诊断信号。

例如，假设某次交付因遗漏一个边界条件而返工。先核对该条件在当时是否可知、计划是否覆盖、评审是否有足够材料发现、执行是否遵循计划。若证据支持上游方法存在缺口，可以据此提出修订；新版评审能识别这个已知问题，只达到代理验证。是否真的减少返工，还要观察候选引导的新执行。

实践以完整任务关系组织材料，保留多对多关系和各阶段实际消费的版本。历史报告中的意见并非完整正确答案，后续采纳与拒绝也需要理由和证据。具体采集、关联和评分边界见 [文档交付链实践案例](../evals/agi-mode/practices/delivery-chain.md)。

该案例保存在仓库级评测目录，不是 agi-mode 的运行依赖。业务字段、阶段记录格式与截图采集流程留在参与技能或目标项目，不能由这个案例限定通用进化方法。

## 10 当前落地状态与推进条件

当前仓库已形成以下说明和约定：

- agi-mode 内的 Eval、Hillclimb、Arena、Reflection 与 skill 修订流程。
- 区分工作样本、进化尝试和实际效果的通用证据约定。
- 独立于通用 skill 的文档交付链实践案例。

这些文件不表示参与技能已经自动生成统一归档，也不表示已有项目材料已经完成采集与审计。当前阶段先选择实际项目、核对已有材料并接入必要的版本保全。此后按下列条件推进：

| 阶段 | 进入下一阶段前需要成立的事实 |
| --- | --- |
| 样本积累 | 能定位真实输入、输出和效果；可恢复程度、同源关系及缺口明确 |
| 评测准备 | 样本具有目标代表性，判定器经过校准，基线可测，隔离和资源条件成立 |
| 进化实践 | 按固定目标运行有边界的尝试，所有候选及去留均有记录 |
| 能力评价 | 候选效果经过独立确认，方法贡献与限制可解释，结论不超出任务覆盖 |

不预设积累多少天或多少份文件就足够。决定下一步的是材料能否回答评测问题。现阶段可以先抽查真实案例的恢复与关联能力，发现缺口后补采集；无需为了填写结果提前启动版本对比。

## 11 参考来源与维护入口

方法调整时，先维护对应执行规则，再同步本文中受影响的解释，避免形成两套标准：

- [进化证据](../skills/agi-mode/references/evolution-evidence.md)：样本、尝试、效果与能力评价边界。
