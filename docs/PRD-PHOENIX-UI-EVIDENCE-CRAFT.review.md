## 1. 确认问题

### F-01 · [P1] 按截图类型定义尺寸有效性，避免拒绝合法整页图和元素图

- **定位**：[有效证据定义，第 85 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L85)、[WORK-F1/AC-1、AC-5，第 169–173 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L169)、[WORK-F3/AC-2，第 216 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L216)。
- **场景与问题**：主代理在 1440×900、DPR=1 的视口截取 3000px 高的整页，或截一个小于视口的元素。F1/AC-5 允许这两种模式，但有效证据定义和 F3/AC-2 没有模式限定，尺寸与所报视口不符即无效。实现按统一判据拒绝合法图片，或自行忽略该判据，均无法同时满足现有验收。
- **证据**：上述要求直接冲突。现有 [finish-reviewer 检查 0，第 29 行](../skills/phoenix-ui/src/subagents/phoenix-ui-finish-reviewer.md#L29) 要求尺寸对截图声称的视口合理，并规定任一必需图无效即整轮 `recapture`；该冲突会影响实际完工交接，不能只当报告措辞处理。
- **修订**：分别定义视口、整页、元素截图的有效尺寸与取景范围；视口和 DPR 保留为拍摄条件，实际图片尺寸按模式判断。明确序列帧、遮字图、缩略图、拼图属于辅助证据，适用各自条件，不冒充终态原图。同步 F1、F3 和调用方引用。
- **复核**：同一视口下，合法视口图、长整页图、元素图均可判有效；实际尺寸或取景范围与所声明模式不符时仍拒绝。未来实现验收再验证这些结果，本次改稿先消除判据冲突。
- **置信度**：高，正文与现有评审输入合同可直接核对。**阻塞**：P1 的 WORK-F1、F3、F16 证据交接。

### F-02 · [P2] 将禁止联网的范围与既有 URL 检测区分清楚

- **定位**：[WORK-N1 约束及 AC-4，第 541–549 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L541)、[D6，第 640 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L640)；关联 [§4 既有约束，第 611 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L611)。
- **场景与问题**：用户检测一个外网 URL，或页面加载远程字体、图片。N1/AC-4 禁止 detect 发起素材检索或“其他外网请求”，D6 又写 detect 永不联网，因而正常访问被测页面及其资源也不允许。保留现有 URL 检测则不能通过这条验收；照字面收紧则改变既有产品能力。
- **证据**：[安装说明第 28 行](phoenix-ui.md#L28) 禁止的是普通运行中联网补下载；[第 87 行](phoenix-ui.md#L87) 明确支持 http(s) 页面检测。源码 [browser/src/lib.rs，第 355–362 行，scan_page_inner](../tools/phoenix-ui/crates/browser/src/lib.rs#L355) 设置视口后实际调用 `page.goto(url, …)`，不是仅解析 URL。PRD 自身也要求既有流程行为不变。
- **修订**：区分自动更新/补下载、主动素材检索与用户指定目标页面的渲染访问，明确各自允许范围；统一 N1、D6、§4 和验收。保留素材仅在显式调用时联网的决定，不把它扩大为检测器无法加载目标页面。
- **复核**：远程页面检测、静态源码检测、素材检索三个场景均能唯一判断允许哪些网络行为，且不违背既有 URL 产品契约。
- **置信度**：高，源码行为与引用约束已核实。**阻塞**：共同网络约束；P1 URL 取证、P2 中文 URL 检测进入计划前须澄清，P3 的 WORK-N1/AC-4 按同一口径终验。

### F-03 · [P2] review-ui 应在 Phoenix 不适用于目标场景时继续使用原采集方式

- **定位**：[WORK-F16 行为、AC-1–5，第 498–508 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L498)、[N13，第 60 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L60)、[F1 边界，第 164 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L164)、[Q4，第 654 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L654)。
- **场景与问题**：review-ui 要在真实宿主的 iframe 或 Shadow DOM 中操作才能到达必要状态；Phoenix 已安装，命令可执行，但该状态超出 F1 能力。F16 要求检测到命令就用它采集，失败后只写重拍或缺证。全文给 feature-demo 明确提供了 iframe 场景回退，却没有给 review-ui 同样的场景级出口；原工具能采到的单元可能因为安装了增强工具反而被判缺证。
- **证据**：[review-ui 的 @tool_independence，第 53–56 行](../skills/review-ui/SKILL.md#L53) 明确工具缺席或不兼容不能阻塞验收；[采集真实性及环境合同，第 95–105 行](../skills/review-ui/references/target-and-capture.md#L95) 要求从真实产品入口取得目标状态，不能随意换成脱离宿主的模拟页。PRD §4 的兜底只明确覆盖浏览器/安装不可用，未覆盖命令已安装但场景不支持。

- **复核**：未安装、已安装且适用、已安装但场景不适用三种情况均有明确路径；只有真实产品状态无法取证时才记缺证。
- **置信度**：高，排除范围、强制调用条件及原 skill 合同均已读取。**阻塞**：P1 的 WORK-F16 交接。

### F-04 · [P2] 中文字体规则须区分正常泛型解析与意外回退

- **定位**：[WORK-F5 字体规则，第 264 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L264)、[WORK-F5/AC-3，第 274 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L274)。
- **场景与问题**：中文正文声明 `font-family: sans-serif` 或 `system-ui`，浏览器按平台选择实际字体。实际字体名通常不是这两个 CSS 关键字；按“实际字体不在声明列表内”即报 advisory 的字面判据，正常系统字体解析也会被当作异常，无法稳定表达“意外回退”。
- **证据**：[W3C CSS Fonts 4 §2.1.5](https://www.w3.org/TR/css-fonts-4/#generic-font-families) 将泛型定义为系统可用字体的别名或组合；`system-ui` 的实际字体可因平台和语言变化，计算样式仍保留该关键字。本次读取日期为 2026-11-09。这里是根据规范对 PRD 判据的推演，没有声称已运行新规则或测得误报率。
- **修订**：定义何种回退才是待修问题；泛型及声明别名的正常解析不因名称字符串不同而被报错。无法确认实际渲染来源时如实表达核实限制，不把未知当异常；具体检测方法交开发计划。
- **复核**：正常泛型字体、正常加载的指定字体、指定字体缺字而发生意外回退的结果可区分；AC-3、规则表和 UAT 的预期一致。
- **置信度**：高，缺口是明确产品判据与标准行为的冲突。**阻塞**：P2 的 WORK-F5 字体规则验收；不要求改变已确认的行高/行长门槛。

### F-05 · [P2] 图片处理场景应与格式和多宽度选项使用同一通过口径

- **定位**：[S11，第 129 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L129)、[WORK-F9 行为及 AC-1–2，第 354–363 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L354)、[UAT-11，第 725 行](PRD-PHOENIX-UI-EVIDENCE-CRAFT.md#L725)。
- **场景与问题**：3000px 宽的不透明 PNG，显示宽度为 600px，普通处理得到 1200px JPEG，未请求多宽度版本。它符合 AC-1 允许 WebP 或 JPEG 的规定，也没有触发 AC-2 的多宽度要求；但 S11/UAT-11 无选项前提就要求 WebP 与 srcset，同一结果会同时通过 AC、失败于 UAT。
- **证据**：F9/AC-1 允许两种不透明输出格式；AC-2 只在请求多宽度版本时要求 `srcset`/`sizes`。S11/UAT-11 未写对应选择条件，直接收窄结果。该冲突由文档即可确认，不依赖新增命令是否已实现。
- **修订**：在 S11/UAT-11 明确该场景已请求 WebP 和多宽度输出，或让预期结果兼容正文允许的格式与条件；两种修法均不增加功能。
- **复核**：相同输入与选项在功能 AC、S11、UAT-11 得到一致判定，原图不变和来源保留要求继续成立。
- **置信度**：高，验收原文直接冲突。**阻塞**：P3 的 WORK-F9 验收交接。
