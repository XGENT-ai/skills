## 1. 确认问题

1. **[P2] F-01 · 补定“变更”项在前后普通图中的显示含义。**
   - 定位：[WORK-F7 行为](PRD-ELINTP-VISUALS.md#L244)、[AC-1 / AC-2](PRD-ELINTP-VISUALS.md#L250)、[UAT-6](PRD-ELINTP-VISUALS.md#L459)。
   - 场景与问题：作者把 erd 字段类型或节点描述标为“变更”，读者切到“变更前”想知道画面是否代表原值。AC-2 只规定新增、删除如何进入前后图，未规定“变更”项两侧显示什么；UAT-6 也只有增删场景。开发者可合理选择两侧同值或分别显示前后值，但这两种结果向读者表达不同事实，当前无法唯一验收。
   - 证据：PRD 的 [D8](PRD-ELINTP-VISUALS.md#L397)选择单输入标记；参考源码 [er.js:67](../local/answer-me-with-html-main/src/components/er.js#L67)明确变更标记不展示旧值；[delta.js:7–20](../local/answer-me-with-html-main/src/runtime/delta.js#L7)仅切换视图类。因此不能从参考的 Before / After 名称推断已经定义了旧值重建。
   - 修订：保留单输入方向，明确“变更”表示什么及三种视图分别显示什么。最小可沿用参考语义：仅提示对象发生变化，两侧保留输入中的同一描述，并明确不代表恢复旧值。同步 AC-2 与 UAT-6；如选择携带前后信息，应先形成明确产品决定，不能由输入格式设计暗定。这里不要求两份输入或扩展成完整差异引擎。
   - 复核：仅凭修后 PRD 即可唯一判断一个仅标为“变更”的字段在三种视图中的内容，以及读者能否将其视为旧值。未来实现验证再检查对应输出，本次不宣称运行通过。
   - 置信度：高，正文与参考契约直接支持；阻塞：P5 的 WORK-F7 及其经 WORK-F5/AC-6、WORK-F9/AC-6 消费的变更视图范围；其他独立范围不受此项阻塞。
