## 0. 一句话

让用 Phoenix UI 做界面的 agent 在任何宿主上都能拿到自检有效的实拍证据、经过一次不知任务的真实走查，交付符合中文排版口径、动效与细节有章可循的界面，设计稿能用来源清楚的真实素材预览，并能让用户按真实尺寸比较已构建方案后再选定；装有 Phoenix 时，feature-demo 与 review-ui 也能借用同一取证与走查能力。

## 1. 背景与目标

### 1.1 问题陈述与现状

Phoenix UI 的方向生成（concept-seed 抽签与决策页）、设计稿驱动构建（comp-spec / comp-diff 门禁）和完工评审子代理已比 oil-ui 更严，本 PRD 不重复这些能力。以下是对照两边源码后确认的缺口。缺口的直接后果是：完工评审子代理没有浏览器，只能读主代理交来的截图；宿主没有浏览器或截图不合格时，评审只能退回 `recapture`。有操作流程的界面没人以“不知道任务的人”身份走过。中文页面的排版问题检测不出来。真实素材要靠 agent 临时找、自行判断许可。

### 1.2 目标（终局）

- G1 证据可靠：Web 界面的完工评审拿到的证据覆盖要求的视口和声明的交互状态，并已自检有效；没有可用浏览器时如实报告“未取证”，不以缺失或无效证据报告 ship。装有 Phoenix 时，feature-demo 的录制前核对与 review-ui 的验收采集也能使用同一取证与自检。
- G2 操作经过真实检验：有主要操作流程的 Web 界面交付前，至少经过一次不知任务的独立走查；可复现的“卡住/走错”在交付前修复并复验，或由用户明确接受。装有 Phoenix 走查子代理时，review-ui 验收也能派出同样的走查。
- G3 中文排版可设计可检测：以汉字为主的界面有明确的行高、行长、断行和字体口径；`detect` 能检出这些问题，拉丁文页面的既有检测结果不变。
- G4 素材与细节交付完整：设计稿预览所用素材的来源与许可在设计阶段可查，且不进入产品；交付图片的尺寸和格式合适；动效与细节按明确规则完成；已构建方案可按真实尺寸比较后由用户选定。

数值门槛（如中文行高 1.5、行长 40 字）是本 PRD 的产品提案（见 §5.1 D5），不是已实测基线。

## 2. 领域语言、用户与场景

### 2.1 领域语言

| 规范词 | 定义 | 避免/易混用词 | 依据 |
| --- | --- | --- | --- |
| 取证命令 | Phoenix 自带、在临时浏览器里打开页面、按步骤操作并保存截图与报告的命令；工作名 `phoenix-ui capture`（§5.2 Q1）；也可被 feature-demo、review-ui 等 skill 检测后调用 | 不与 comp-led 的 `component-review capture`、`build-phase` 原生截图混称 | 本次决策 D2、D3、D11 |
| 可选接入 | 独立 skill 检测到 Phoenix 的取证命令或走查子代理可用、且适用于当前目标时才使用；检测不到，或能力不适用于当前目标（如目标在 iframe 或 Shadow DOM 内）时，按自身原流程完成，不安装、不下载、不阻塞 | “依赖 Phoenix”“集成” | AGENTS.md `@skill_tool_independence`；D11 |
| 状态组 | 一组命名的步骤，从重新打开的页面执行到某个界面状态 | “state 参数”“?state= 路由” | shoot.mjs `--steps` |
| 截图类型 | 状态截图的取景方式：视口图（默认，只截当前视口）、整页图（从文档顶部截到底部）、元素图（只截指定元素区域）。视口与像素比是拍摄条件，截图类型决定图片应有的尺寸 | “长图”“局部图” | shoot.mjs `--help`；finish-reviewer 检查 0 |
| 有效证据 | 满足以下全部条件的状态截图：声明的步骤全部执行；入场动效已稳定或关闭；无空白或全黑区域、画布已绘出；尺寸与取景符合该图的截图类型（视口图的像素尺寸等于视口宽高乘像素比；整页图宽度等于视口宽乘像素比，从文档顶部截到底部；元素图只含指定元素区域，尺寸等于该元素渲染区域乘像素比）；内容与文件名所称状态一致。整页图高于视口、元素图小于视口不构成无效。前四项由取证命令自检（不论由谁调用），最后一项由调用方的主 agent 与评审核对。WORK-F2 的序列帧、遮字版、扫视缩略图、标注图、状态并排图与拼图是派生证据，按其自身验收判定，不计入也不替代所需的状态截图 | “截到了就算”“尺寸等于视口才有效” | new-work.md §7、finish-reviewer 检查 0 |
| 盲测 UX 走查 | 全新上下文的子代理，不拿任务、预期路径、源码与设计说明，从真实页面推断目标并走一条主路径；由 Phoenix 完工轮或 review-ui 派出 | 不等于 critique 的 persona 走查、polish 的主代理走查、review-ui 的独立评审 | ux-reviewer.md |

### 2.3 关键业务场景

主场景（code-led 新页面完工）：

1. 主代理按选定方向构建完一个带筛选和提交表单的 Web 页面。
2. 主代理用取证命令一次截出桌面与手机的初始状态、“打开筛选”和“提交空表单”两个状态，每张图都附页面规则发现。命令确认证据有效后，写进 `.phoenix-ui/review/`。
3. 主代理在同一轮派出完工评审子代理和盲测走查子代理。走查者只拿到页面入口和测试账号。
4. 评审回 `fix`，走查报告“提交后没有任何反馈，不知是否成功”（卡住，可复现）。主代理把两者放进同一修复批次，修完重取同一组文件，再由主代理在真实页面复验提交流程。
5. 交付报告原样给出评审的处置词，单列走查结果与处置，标出“正常速度手感未核对”，末尾给出最多三条带代价的下一步。

### WORK-F5 检出中文排版问题

- **优先级 / 重要度**：high / high。**承接**：R3 · G3 · S7、S15。**分期**：P2。
- **背景**：内置 `line-length` 按 80 字符、`tight-leading` 按 ≥1.3 判定，中文正文每行 50 多字、行高 1.4 都不会被报出。
- **行为**：在 detect 的页面规则（`detect <url>`）中新增 5 条 xgent 规则，作用于以汉字为主的正文与标题文本，检查的元素范围与现有 `line-length` 相同。规则名为工作名：

| 规则（工作名） | 判定 | 级别 |
| --- | --- | --- |
| `xgent/cjk-tight-leading` | 至少两行渲染的正文，行高与字号之比 < 1.5 | warning |
| `xgent/cjk-line-length` | 至少两行渲染长度超过 40 个汉字 | warning |
| `xgent/cjk-orphan` | 多行段落或标题的末行只有 1–2 个汉字（不计标点） | advisory |
| `xgent/cjk-split-unit` | 数字与紧随的单位（如“38 秒”“1,238 位”）被拆到两行 | advisory |
| `xgent/cjk-font-fallback` | 汉字发生意外回退（§2.1「汉字字体意外回退」）；通用字体族的正常解析不报；无法确认实际渲染来源时不报，并注明该段字体来源未核实 | advisory |

  以汉字为主的文本不再由内置 `line-length`、`tight-leading` 重复报告。新规则与现有 xgent 页面规则一样默认启用，可用 `detector.ignoreRules`、`hooks ignore-rule` 关闭，advisory 可用 `--no-advisory` 隐藏。
- **边界**：页面规则不经 hook、不进 live 叠层与浏览器扩展（N11）；不判断日文、韩文；不改拉丁文本的判定。
- **依赖**：同 `detect <url>` 的浏览器渲染。

### WORK-F6 按中文口径设计排版

- **优先级 / 重要度**：medium / high。**承接**：R3 · G3 · S7、S8。**分期**：P2。
- **背景**：typeset 对中文正文只给出 45–75 字符的拉丁口径；comp-led 构建要求逐字沿用设计稿文案，而生成的中文设计稿常有伪汉字。
- **行为**：界面语言为 zh-CN 或 zh-TW 时，craft-floor 与 typeset 给出中文口径，项目 DESIGN.md 另有规定的从其规定：
  - **字号起点**：阅读型页面正文 16–18px；产品界面正文 14–16px；长时间使用的高密度工具 13–14px。不靠 9–12px 的说明文字营造精致。
  - **行高**：正文 1.6–1.75；多行中文标题从 1.2–1.35 起，逐视口核对字形不碰撞；标题高度不固定为单行，不用负外边距挤压后续内容。
  - **行长**：中文正文约 25–40 字。
  - **断行**：数字与单位、不可拆的词不换行；首屏说明、图注这类短段落按语义手动断句；行末只剩 1–2 字或词被拆到两行算缺陷。
  - **中英混排**：核对基线与视觉字重；窄幅展示字只用于展示标题与极短标签。
  - **字体回退**：核对汉字的实际渲染字体，不出现意外回退（§2.1）。
  - **comp-led**：已批准设计稿中的伪汉字、乱码或与界面语言不符的繁简字视为稿件缺陷，沿用现有“设计稿缺陷可修正”的让步条款，构建时替换为真实文案。
- **边界**：不改变 Phoenix 字体选择与方向规则；伪汉字之外的稿件文案仍逐字沿用。
- **依赖**：WORK-F5 的规则用于核对。

### WORK-F11 按编排规则设计与核对动效

- **优先级 / 重要度**：medium / medium。**承接**：R5 · G4 · S1。**分期**：P4。
- **背景**：animate 有动效论点、时长与减少动态效果，但缺“动作怎样彼此接上”的具体规则，动效容易各动各的。
- **行为**：animate 在既有内容之上补充以下规则。
  - **编排**：变化从被操作的元素出发；一次切换只朝一个方向；主角先动，被影响的元素晚 40–80ms、以更小幅度跟随；上一状态的元素变成下一状态的元素（形状接力）。
  - **过渡**：只改变尺寸或位置时外框直接变形、内容立即显示新状态，不做交叉淡化；离开、加入、留下的元素分开处理；选中指示用一块滑块移到新位置，首次显示、窗口缩放、字体加载后直接就位；目的地内容先准备好再过渡；到第一项或最后一项时轻顶 10–15px 作为反馈。
  - **手感**：用“动作 + 实物”命名并给出弹簧刚度/阻尼。大面积元素过冲不超过 1–2%，小物件可到 10–20%。弹簧可采样写成缓动曲线，不支持时退回相近曲线。回弹类曲线只在方向或 brief 支持时使用，保留现有“不凭反射用弹跳”原则。
  - **反馈**：复制、后台保存、发送等看不见结果的操作，用短提示说出结果本身。
  - **核对**：用 WORK-F2 的序列帧看状态变化，手感靠实际操作判断。
- **边界**：保留“一处精心动效”原则，不强制新增动效（N3）。
- **依赖**：WORK-F2 的序列帧。

| --- | --- | --- |
| AC-1 | 主代理为一处会改变状态的操作做动效时，交付报告写明起点（被操作的元素）、方向与跟随顺序；该操作的序列帧显示被影响元素晚于主角开始移动且方向一致。 | P4 |
| AC-2 | 只改变尺寸或位置的过渡（展开、筛选、切换视口）在序列帧中不出现新旧两层内容交叠的重影；选中指示以同一块滑块移到新位置，首次显示与窗口缩放后直接就位。 | P4 |
| AC-3 | 交付报告以“动作 + 实物”命名动效手感并给出对应的弹簧参数或缓动；整页、面板等大面积元素的过冲不超过 2%。 | P4 |
| AC-4 | 复制、后台保存、发送等无可见结果的操作完成后，界面用一条短提示说出结果本身（如“已复制：<内容>”），而非只显示“成功”。 | P4 |

### WORK-F12 把模糊反馈翻译成可观察的改动

- **优先级 / 重要度**：medium / medium。**承接**：R8 · G4 · S13。**分期**：P4。
- **背景**：用户常用“高级、精致、克制、简洁、不够好看”评价界面；Phoenix 只为方向轮定义了更大胆/更稳妥两档，其他场景下 agent 容易随机换风格。
- **行为**：用户在已有界面上给出模糊评价时，主代理先把它翻译成可观察的变量，写出“要改的变量 → 预期变化”再动手，交付后逐项说明实际改动。翻译依据：
  - 高级：先说清是哪一种，再定字体对比、分隔方式、间距尺度、色相数量。
  - 精致：公差，即字距、网格对齐像素、阴影级数、色相上限。
  - 克制：饱和度预算（如强调色占面积比例）、动效幅度上限、色相上限。
  - 史诗：尺度，即展示字大小、主图面积、明暗对比。
  - 简洁：密度档位，以及删什么、为什么删。

  无法从上下文判断时，只问一次并给两个具体选项，或提供两个可比较的变体（元素级用 live，整页用对比页）。
- **边界**：方向轮进行中，“更大胆/更稳妥”仍是方向轮的语义；用户要求换方向时走既有方向流程。
- **依赖**：WORK-F10（整页变体比较）。

- **背景**：review-ui 要求每张截图真实、出处可查、条件一致，并由主 agent 逐张开图核对；取证命令能当场给出无效原因和出处字段，少让不合格截图进入评审。
- **行为**：review-ui 检测到已安装 phoenix-ui 且取证命令可用时，对命令适用的单元，用它在真实运行的产品上按验收矩阵采集截图，文件名与出处字段按 review-ui 采集合同写入；命令标为无效的图按「没采到」处理；命令输出的控制台错误、失败请求、横向溢出与 detect 发现只进机器检查，不交给独立评审。到达某单元目标状态所需的交互或前置超出取证命令能力（如目标在 iframe 或 Shadow DOM 内）时，该单元按 review-ui 原合同改用其他可用采集方式，仍满足其真实性与出处要求；只有真实产品状态无法取证时才记缺证。未检测到时沿用现有采集方式。
- **边界**：不改 review-ui 的计分、门槛与判定（N1）；命令自检不替代主 agent 开图核对；不扩大取证命令对 iframe、Shadow DOM 的支持（N13）。
- **依赖**：WORK-F1、WORK-F3（可选；不可用时进入 AC-5 的状态，不适用于某单元时进入 AC-6 的状态）。
