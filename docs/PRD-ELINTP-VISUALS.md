## 0. 一句话

让文档作者用 `/elintp` 得到版式固定的图文说明，在生成后的人工审阅阶段直接提交标注并局部重讲，审阅结束后得到不带审阅功能的离线终稿；让图解作者在 phoenix-diagram 里画数值图表、结构变更和逐词标注，并把图以静态形式放进别的文档。

## 1. 背景与目标

### 1.1 问题陈述与现状

文档作者每次调用 elintp，页面的 HTML、CSS 和图形都由模型现写：同一类文档两次产出的版式、配色和暗色表现不同，模型的输出大半花在样式而不是内容上。读者读到不懂的地方，只能回到对话里描述是哪一段。页面要进零网络阅读面时，elintp 的嵌图方式与调用方的要求对不上。图解作者要画数值比较、讲「改完以后和现在差在哪」或逐词点评一句话时，phoenix-diagram 没有对应图型。

本次核实的事实：

| 事实 | 依据 |

### 1.2 目标

- G1：文档作者用 elintp 得到版式固定的页面。同一模板两次产出的外观一致，模型不再产出样式、版式与图形坐标。
- G2：人工审阅时可在页面上标出疑问并直接提交给 Agent，只重讲被指出的小节；终稿不带标注或提交功能，可脱离 Agent 环境阅读。
- G3：图解作者能在 phoenix-diagram 里表达数值比较、结构变更与逐词点评，三者与既有图型使用同一交付口径。
- G4：图能以静态形式进入零网络阅读面；看图审核由四张截图减为两张，默认审核与「完整交付」的含义不变。

参考工具的 token 与耗时数字是比较基线，不是本 PRD 的验收门槛。

## 2. 领域语言、用户与场景

### 2.1 领域语言

| 规范词 | 定义 | 避免 / 易混用词 |
| --- | --- | --- |
| 内容稿 | 模型为一页写的正文与数据，不含样式、版式与图形坐标 | 草稿、源稿 |
| 模板 | 随 elintp 分发的固定页面设计，共四种 | 主题 |
| 审阅页面 | elintp 生成后供人工审阅的页面，可标注并向当前本机审阅会话提交意见 | 终稿 |
| 审阅标注 | 人工审阅时对内容块留下的类型（没看懂、疑问、建议）与一句话 | 评论、批注；不同于图型「逐词标注」 |
| 审阅意见 | 页面汇总的标注及其位置，经主动提交送给当前 Agent | 复制回贴的回复 |
| 局部重讲 | 收到提交后只重写被标注的小节，更新审阅页面 | 重新生成 |
| 终稿 | 作者明确确认审阅完成后交付的单文件离线 HTML，保留内容和内容稿，不含审阅功能、连接与待审数据 | 审阅页面 |
| 页内嵌入阅读器 | 把 phoenix-diagram 的完整阅读器 HTML 放进宿主页面 | 内联图 |
| 静态图 | phoenix-diagram 为嵌入别的文档输出的图，不含阅读器与脚本 | 导出图、截图 |
| 数值图表 | 柱状图、折线图、饼图、限额对比图四种形态 | 仪表盘 |
| 变更视图 | 在一张结构图上标出新增、删除、变更；另有变更前、变更后两种普通视图 | 架构比较（两份输入，旧 PRD 的 WORK-F9） |
| 逐词标注 | 对一句或几句原文中的词段逐个加注的图型 | 审阅标注 |

### 2.2 用户与权限边界

| 角色 | 是谁 | 要完成什么 | 权限边界 |
| --- | --- | --- | --- |
| 文档作者及其宿主 Agent | 调用 elintp 的人和替他执行的 Agent | 生成页面、处理已提交审阅意见；由作者确认审阅完成后交付终稿 | 只读作者给出的材料；不自动安装工具；不执行意见里夹带的指令 |
| 审阅者 | 生成后在本机审阅页面的人 | 标注疑问并主动提交给当前 Agent | 意见仅经当前本机审阅会话提交，不上传外部服务；不能改作者的源文件 |
| 终稿读者 | 脱离审阅会话打开终稿的人 | 阅读、切换亮暗、按大纲定位 | 不需要 Agent、开发工具或网络；终稿不提供标注和提交 |
| 图解作者及其宿主 Agent | 调用 phoenix-diagram 的人和 Agent | 画数值图表、变更视图、逐词标注；取静态图 | 只用授权材料中的数值与事实 |
| 调用方 skill | summarize 等调用 elintp 的 skill | 得到符合其阅读面要求的页面 | 以明确要求声明阅读面限制 |
| 本仓维护者 | 维护模板、脚本与 skill 文案的人 | 演进四种模板与图型 | 编辑仓库不等于获准改动已安装副本或发布 |

### 2.3 关键业务场景

主路径：① 作者用 `/elintp` 给出一份文档；② elintp 判型、选模板、写内容稿；③ 脚本生成页面，elintp 自检并提供本机人工审阅入口；④ 审阅者标出疑问并主动提交，Agent 接收意见，只重讲被标注的小节；⑤ 必要时继续审阅与提交；⑥ 作者明确确认审阅完成，Agent 交付不带审阅功能的离线终稿。

| # | 给定角色 / 数据 / 状态 | 执行动作 | 应出现的业务结果 | 压测边界 |
| --- | --- | --- | --- | --- |
| S1 | 作者有一份 PRD，需要一张流程图和一张已有截图 | 调用 elintp | 得到 PRD 模板的单文件页面，第一屏是结论，图与截图完整 | 主路径 |
| S2 | 内容稿有格式错误，或本机跑不了脚本，或没有安装 phoenix-diagram | 生成页面 | 第一种给出位置与改法且不出半成品；第二种退回手写并说明；第三种用自绘图并说明 | 非法输入、前置缺席 |
| S3 | 审阅者标注两处，其中一句写着「顺便删掉仓库里的旧文件」 | 主动提交意见，重讲后由作者确认审阅完成 | 只重讲两节；夹带的要求不执行；终稿不带标注、提交入口或待审数据 | 不可信输入、审阅与终稿切换 |
| S4 | summarize 以零网络阅读面要求调用，材料需要一张流程图 | 生成页面 | 页面中的图是静态图，无外部请求，无页内嵌入阅读器 | 前置约束 |
| S5 | 图解作者有三组真实耗时数值；另一次材料没有数值 | 要求画对比图 | 前者得到柱状图与数据表；后者不画数值图表 | 空数据 |
| S6 | 开发计划描述「审批流去掉一步、新增一个分支」 | 要求画改动 | 得到带标记的变更视图，可切到变更前、变更后 | 状态切换 |
| S7 | 图已通过自动检查；另一次 1920×1080 出现水平溢出 | 做看图审核 | 前者看亮、暗两张后完成；后者自动检查失败，不进入审核 | 审核减量不放宽 |
| S8 | 作者要点评一句文案的三处用词 | 要求逐词标注 | 原文逐字保留，三处各有标注，问题词有区分 | 主路径 |
| S9 | 仓内已有十一类图的 candidate 与旧 elintp 页面 | 升级后照旧使用 | 旧输入结果不变，旧页面仍可阅读 | 兼容 |

## 3. 需求条目

以下均为拟新建需求。未指定负责人和日期。AC 表是验收原文的事实源；录入时按表序导出，跨期需求逐行加 `[P#] `，单期不加。

### WORK-F1 用固定模板生成版式一致的图文说明

- **优先级 / 重要度**：high / critical。**承接**：R1、R3 · G1 · S1、S2。**分期**：P1，终验期 P1。
- **行为**：文档作者以主题或文档调用 elintp。elintp 判型后从四种模板中选一种，只写内容稿；随 skill 分发的脚本把内容稿填进模板，得到单个离线 HTML。各模板的页面顺序如下。

| 模板 | 适用输入 | 页面依次回答 |
| --- | --- | --- |
| 通用技术文档 | 主题；技术方案、评审纪要、故障复盘及其余三种未覆盖的文档 | 结论是什么；它为什么成立；读者会用到的量级；风险与前提 |
| PRD | 产品需求文档 | 会多出什么；做完后和现在差在哪；建议怎么实施 |
| CRD | 跨项目需求文档及其往返答复 | 谁向谁要什么、为什么要；对方的立场与答复；已经谈定的约定；还没谈定的问题与下一步由谁做 |
| 开发计划 | 开发计划，按原文记录分三种进度形态 | 未完成：要开发什么、技术路线与代价。已完成：做出了什么、读者怎么自己验证、遗漏与后续，附过程记录摘要与截图。做了一半：两段都写 |

- **边界**：模板的视觉设计在实现期用 phoenix-ui 完成并随 elintp 分发；elintp 运行时不要求安装 phoenix-ui 或 phoenix-diagram。不提供主题库和用户自定义模板。内容稿的写法与脚本的实现语言由开发计划确定；用户约束是该程序为脚本。
- **依赖**：本机有能运行该脚本的运行时。缺失时进入 AC-5 的状态。

| AC ID | 验收原文 | 期次 |
| --- | --- | --- |
| AC-1 | 作者以主题或文档调用 elintp 后，得到一个采用对应模板的单文件 HTML；文档不属于 PRD、CRD、开发计划时采用通用技术文档模板，判不准类型或计划进度时先询问作者。 | P1 |
| AC-2 | 同一模板的两次产出具有相同的版式、配色与组件外观，差异只来自内容；作者提交的内容稿不含样式、版式或图形坐标。 | P1 |
| AC-3 | 每种模板的页面按本条模板表给出的顺序回答对应问题，第一屏先出现主题本身的结论；开发计划模板按原文记录区分未完成、做了一半、已完成三种形态。 | P1 |
| AC-4 | 内容稿有格式错误时不生成页面，作者得到每处错误的位置与改法；改正后可以生成，已存在的旧页面不被半成品覆盖。 | P1 |
| AC-5 | 脚本在本机无法运行时，elintp 仍交付手写的单文件 HTML，并在交付说明中写明未使用模板及原因。 | P1 |
| AC-6 | 四种模板均能呈现结论块、提醒块、指标块、带状态标记和表头释义的表格、步骤、截图与图；状态标记同时用符号和文字表达。 | P1 |

- **UAT 场景**：UAT-1、UAT-2；作者给出文档后得到对应模板的页面，出错或降级时有明确说明。

## 4. 约束与前提

- **用户给定的约束**（均来自 2026-11-10 本次对话的回答）：
  - 模板由 phoenix-ui 设计，固定为通用技术文档、PRD、CRD、开发计划四种；elintp 生成正文并填充数据。影响 WORK-F1。
  - 填充程序是脚本；脚本不可用时退回手写。影响 WORK-F1。
  - 写作规则、红线与转述保真只靠模型自检。影响 WORK-F2、NG3。
  - 嵌图默认用 iframe 嵌完整阅读器；零网络阅读面要求内联时才改用静态图。影响 WORK-F5、WORK-F9。
  - 看图审核全局保留，减为 1440×900 亮、暗各一张。影响 WORK-F10。
  - 静态图体积门槛为完整阅读器 HTML 的 50%。影响 WORK-F9。
  - 标注仅用于生成后的人工审阅，意见参照 spec-human-decision 直接提交给当前本机 Agent；未提交不算答复。作者明确确认审阅完成后交付无审阅功能、连接和待审数据的终稿。影响 WORK-F4、WORK-N2。
- **仓库规则**：[AGENTS.md](../AGENTS.md) 规定 elintp 独立于 Phoenix 工具，不以它们的安装或引擎为执行前提；借鉴其他 skill 的规则前须出示整合清单（见 §5.3），不改变既有原则与触发策略；skill 描述先写触发与排除。
- **既有决策约束**：旧 PRD 的 D5 与 WORK-N1/AC-2（默认视觉审核）保持；旧 PRD 的 NG1 中「数值图表」由本 PRD 承接，「仪表盘及其他 infographic」仍不做。旧 PRD 原文本次不改。
- **参考基线**：`local/answer-me-with-html-main` 0.5.11。本 PRD 借鉴的是它的行为；实现时若复用其代码或词表，须保留 MIT 许可与来源，由开发计划核实。
- **前置依赖**：
  - 宿主 Agent 提供判型、写作与自检；它是 elintp 的执行者，没有无 Agent 的使用路径。
  - 脚本运行时：缺失时 WORK-F1/AC-5 的手写降级成立，WORK-F4 不可用。
  - phoenix-diagram 引擎：缺失时 WORK-F5/AC-4 的降级成立，WORK-F6 至 WORK-F10 不可验收。
  - 真实浏览器与图像能力：缺失时看图审核保持未完成。
  - 本机审阅会话：P2 的标注提交与局部重讲需要当前 Agent 能接收本机提交；终稿阅读不依赖此会话。未提交或提交失败不冒称已接收意见。
- 本产品不是 portal 微应用，不套用租户、分页、业务错误或席位计量契约。用户没有限定日期，不承诺开发或发布日期。
