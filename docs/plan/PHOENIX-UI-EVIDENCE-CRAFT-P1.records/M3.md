## 交付

- 序列帧：`frames`（`last-step` 在最后一个动作前开始录，`entry` 先打开白底空白页取基准帧再导航）；窗口为动作或导航起到有限动画结束后 100 ms（300–3000 ms），等距取帧、不取未来帧、无更早帧标“无帧”，≤4 列网格，报告含 `count/missing/windowMs/from/note`，未见动画时注明“未检测到出场动画”/“未检测到动画”。
- `--mask`（检查器样式表，文字透明、`color` 不改）、`--thumbs`（首个视口缩到 480/180 宽；遮字版另出 `.mask.thumb.png`）、`mark`（2 px 框与编号牌，编号按声明顺序，找不到的进 `unmarked`）、`--sheet`（每视口有效主图并排、标状态名）、`capture stitch`（按共同元素统一比例、缩放后坐标裁切、越界退出 1 不写文件）。合成在同一浏览器的合成页完成，每边上限 16384 px，超出或失败记 `derived.problems`/`sheets[].problem` 并退出 2。重取时同名派生旧图一并删除。

## 偏差

- 帧时刻用帧到达本进程的时间，而不是 Chrome 的帧时间戳：实测后者比本机时钟快 10–20 ms，会让动作前收到的基准帧显得晚于动作，首格误标“无帧”。到达时刻不早于真实捕获时刻，仍满足“不取未来帧”（§5.6 原文不变）。
- 缩略图用现有 `impeccable_comp::raster` 裁切缩放，不经合成页：不含文字，D10 不引入新依赖的目的不变。
- 动画是否出现除轮询外还靠 `animationstart`/`transitionrun` 计数（`entry` 用 `Page.addScriptToEvaluateOnNewDocument` 注入），因入场动画可能在 `networkidle0` 返回前已结束。
