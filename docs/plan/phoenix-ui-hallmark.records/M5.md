## 偏差与说明

- V-8 首次 `test:phoenix` 在 cargo workspace 阶段失败：`crates/rules/tests/text.rs` 的 `registry_rows_match_the_reported_findings` 仍是 M1 期的两行断言（M2 已把 `ROWS` 扩到 8 条，M2 只跑了 `--test dom` 未覆盖该文件）。修正断言为 8 条并按 §9.1 重跑完整 `test:phoenix` 通过；该项属测试同步遗漏，不影响规则行为，已作为本次偏差记录。
- 构建顺序偏差：`cargo xtask bundle` 会重新生成 `crates/live/assets/detect-antipatterns-browser.js` 与 `bundle-inputs.json`（其中绑定 Cargo.lock/workspace Cargo.toml/inline_ignores.rs 字节），因此首次「先 deps --write 再构建」的审计报 workspace 清单过期；正确处理为「构建 → deps --write → 重建（复制新清单到 distribution）→ 审计」，实际按此完成并全绿。`V-8` 计划文字未覆盖该先后细节，记录为实施偏差，不改变交付。
- `DELTAS.md` 属固定导入 corpus，新增节同步重绑 `UPSTREAM.json` 的 `importedFiles` 与 `importManifestSha256`、`capabilities.baseline/sourceFiles/current.sourceFiles`（M3 记录详述）；golden 与 case 未改。
- oracle 的 win32 `platformFields` 已按「路径分隔符整体替换」语义重放到新期望上，`oracle.test.js` 的 Windows 分隔符不变量通过；本机为 darwin-arm64，未在真实 Windows 运行（仓库 CI 矩阵不含 Windows），记录为未验证平台。
- `oracle.test.js` 的 italic 单文件证明测试扩展了「四个注册的 xgent advisory 发现」断言（golden 未变），使该证明与新的精确期望登记一致。
- `docs/phoenix-ui.md`、`compatibility.md` 的 M3 内容在 M5 构建后保持有效（规则表与 ROWS 未变）；`capabilities.json` 的 generatedBundle/engineManifestEvidence 按开发构建重绑。
- V-9 的会话权限被 CLI 参数固定而非项目 settings（Claude Code 对未信任项目忽略 settings.permissions），已在证据 README 记录；这不影响判定。
