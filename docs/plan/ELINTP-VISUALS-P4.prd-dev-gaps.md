## 2. 三类差异

### A · 明确遗漏

#### G-01 · 多系列图例的色块写系列 id，不是系列键 · A

- PRD 期望：WORK-F6/AC-2「多个系列时带图例，系列之间除颜色外还有文字或图形上的区分」；§2.4「图自带图例……可独立看懂」。计划 §5.5「图例符号：系列为色块加系列键」、D6。
- 实际交付：`tools/phoenix-diagram/src/render/chart.rs` `legend_glyph`（L284–L293）用图例 kind 的后缀（`series:<id>` 的 id）作色块文字，而不是 `facts.key`。id 超过一个字符时，9 px 文字溢出 14 px 色块，压在色块和「A · 系列名」上。官方最小示例 `examples/minimal.chart.json`（id `before`/`after`）的导出图面为「be█foreA · Before」「af█terB · After」。图例文字「A · Before」本身正确，因此 AC-2 的文字区分仍在，但图例错乱。
- 证据链：计划 §5.5 → M1 记录看图结论称 volumes「色块内含键字母」，而该 candidate 的系列 id 是 `min`/`max`（`local/phoenix-diagram/elintp-p4-out/volumes.json`）；M2 记录写「图例『ins A · 新增行数』」，已把 id 当作所见文字记下却未识别为缺陷 → 内容检查 `check/chart.rs` L165–L185 只核对图例文字「包含」键 · 系列名，不核对色块文字 → 本次实测：`deliver` 最小示例后 Chrome 导出 light/still PNG（见 §5）。
- 影响：所有多系列柱、折线（含阅读器、导出、静态图、elintp 页面）；作者按 schema 写常见的多字符 id 即触发。不阻塞交付流程（自动检查全过），但图例可读性受损，正是 PRD 要求「可独立看懂」的部分。
- 分类依据：计划已定行为，实现偏离；补齐不需要新的产品取舍。
- 处置：补齐。
- Follow-up：色块文字改为系列键；内容检查同时核对色块文字等于键；用多字符 id 的两系列柱、折线回归，阅读器与静态图看图确认。

#### G-02 · 超限填充与饼图收尾扇区退回浅色，超限项比正常项更弱 · A

- PRD 期望：WORK-F6/AC-4「限额对比图中超过上限的项有明确标示」；行为段「显示每项的当前值、上限及是否超限」；§2.4「颜色不是唯一区分手段」。计划 §5.4「超限即填充条用 `security` 色槽，文字后加『· 超限』并加粗」，饼图「最后一行改用 `external`，避免首尾相邻同色」。
- 实际交付：`render/chart.rs` L58–L66 只为 `TONES`（frontend、backend、database、cloud、messagebus）生成 `.ch-fill/.ch-slice/.ch-bar.c-<tone> { fill: var(--<tone>-stroke) }`；`layout/chart.rs` L819 的超限填充 `security` 与 L562 的饼图收尾 `external` 没有对应规则，落到通用 `.c-security`/`.c-external` 的浅色填充。实测：亮色下超限填充是淡粉、正常项是饱和青色，暗色下超限是近底色的暗红；图例「超限」色块同样浅。6 行饼图第 6 扇区（`external`）在亮色下接近背景灰白，几乎看不见。
- 证据链：计划 §5.4 → M2 记录看图「security 红填充、加粗『· 超限』」（V-2 quota 样例）→ 本次实测：quota 阅读器导出 light/dark PNG、6 行饼图 `static` 亮色截图（见 §5）。V-2 的饼图只有 4 行，不触发 `external`。
- 影响：限额对比图的读者先被颜色引向正常项；「· 超限」加粗文字仍在，故 AC-4 的文字标示成立但视觉强调颠倒。饼图行数为 6、11、16…时收尾扇区几近不可见，序号与列表仍可对应。
- 分类依据：计划已定色槽，实现漏写样式规则；补齐不需要产品取舍。
- 处置：补齐。
- Follow-up：`security`、`external` 两个色槽获得与 `TONES` 相同的 chart 规则（填充、扇区、图例色块）；静态样式转换保持通过；quota 与 6 行饼图在阅读器、静态图亮暗下看图确认超限项比正常项醒目、收尾扇区可辨。

## 4. Triage 与决策账本

### 问题卡（已回答，保留原上下文）

**Q1（G-05）数据表单元格怎么写？**

- 差异与来源：多系列柱、折线的表格单元格写「A 4200」，饼图写「14 files」，列头单位用全角括号（en 下「Before（ms）」）。计划 §5.3 与 §5.8 示例互相冲突。
- 影响与原因：复制进电子表格得到文本而非数字；英文表头标点不一致。图面不受影响。
- 选项：
  1. **（推荐）表格只放纯数字**：所有形态的数值单元格写 `js_to_string` 原值；单位只在列头（饼图「数值（单位）」，限额保留单位列）；列头括号随语言（zh 全角、其他半角）。图面标注仍带键。理由：符合 §5.8 示例和「可复制」的目的，图与表通过列头系列名对应。影响阅读器表格、静态图 `data-phoenix-table` 内容、内容检查与相应测试；elintp 无需改。
  2. 只去掉系列键，饼图单位与全角括号不变：改动最小，饼图复制仍带单位、英文表头仍是全角括号。
  3. 保持现状，在计划 §5.8 改示例以对齐实现：零代码改动，复制体验不变。

**Q2（G-06）只有上限、没有当前值的限额行怎么画？**

- 差异与来源：计划 §5.4 把填充画到上限，颜色与「当前值」相同；图例声明该颜色是当前值。
- 影响与原因：只看图形会读成当前值 = 上限；文字「上限 12 GB」与表格「—」能纠正。
- 选项：
  1. **（推荐）不画填充**：只画轨道和上限线，右侧文字不变。理由：图形只表达真实存在的数，与「没有真实数值不画」一致；改动在限额布局、内容检查（填充比规则）与测试。
  2. 画到上限但换成区别于当前值的样式（如浅色或描边空心），图例增加「仅上限」一项：保留条形长度的视觉，但多一种图例。
  3. 保持现状。
