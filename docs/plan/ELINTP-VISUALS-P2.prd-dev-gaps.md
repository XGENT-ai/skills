## 2. 三类差异

### A · 明确遗漏

#### G-01 · 无图注的截图不能被标注 · A

- PRD 期望：`WORK-F4/AC-1`「审阅者对**任一内容块**选择没看懂、疑问或建议……该块显示标注」（[PRD §3 WORK-F4](../PRD-ELINTP-VISUALS.md#work-f4-人工审阅时直接提交标注并局部重讲终稿不带审阅功能)）；行为段把「图」列为内容块。
- 实际交付：内容稿格式允许 `![](本地路径)` 空图注（[draft.mjs:230](../../skills/elintp/scripts/draft.mjs#L230) 正则 `[^\]]*`），渲染为空 `<figcaption>`。审阅脚本对图取图注文字作引文，引文为空就不登记该块（[review.js:7–9](../../skills/elintp/assets/review.js#L7)），因此这张图没有标注按钮。
- 证据链：计划 §3/§6 定义「图的引文取宿主图题/图注」，未覆盖空图注 → M1/M4 记录只用带图注的图 → 本次实测：当前渲染器对空图注图片退出 0，输出 `<figcaption></figcaption>`、`alt=""`；静态核实 `register` 在引文为空时直接返回。未在浏览器复现（结论只依赖上述确定性代码）。
- 影响：审阅者对这类截图有疑问时无法在页面标注，只能回对话描述；不阻塞主路径。`:::figure` 图题是必填项，不受影响。
- 分类依据：AC 明确，证据确认部分缺失；没有批准的变更。补齐只需给空引文一个非空兜底，不涉及产品取舍。
- 处置：补齐。
- Follow-up：空图注图片也登记为内容块，引文用非空兜底（如图片文件名）；验收为该图出现标注按钮，提交结果的 `quote` 非空且服务端接受。不改内容稿语法，P1 已有内容稿照常渲染。

### B · 合理变更

#### G-03 · 每轮重开新的本机审阅地址，而不是原地刷新已打开的页面 · B

- PRD 期望：`WORK-F4/AC-3`「只重写被标注的小节并**更新审阅页面**」；`AC-5`「页面更新后……审阅者有新意见时可继续提交」。
- 实际交付：每轮写回同一审阅 HTML 路径，启动新的一次性 loopback 服务（新端口），默认自动打开浏览器；上一轮服务提交后已退出（[review.mjs:131–141](../../skills/elintp/scripts/review.mjs#L131)）。
- 证据链：计划 [ADR-1](ELINTP-VISUALS-P2.md#adr-1按轮次交接的一次本机提交服务) 比较了常驻服务方案 → M3 V-3（round 2 实际显示仅 s2 旧标注，s1 可新增意见）→ M4 V-7 两轮交接 → R1 独立 Chrome 复现 round 2。
- 影响：审阅者每轮在新打开的页面继续，旧标签页失效；新页面内容与标注符合 AC-5。
- 分类依据：有宿主后台事件与跨会话恢复的可行性约束，有备选与取舍，用户可见的验收语义（页面更新、只保留未改区域标注、可继续提交）保持；PRD 未承诺同一标签页原地刷新。
- 处置：保留。
- Follow-up：无。ADR-1 已写明重新评估触发条件。

### 问题卡（已决，保留原上下文）

**D-01 → G-02：终稿要不要保留资源快照？**

- 差异：终稿既显示资源，又在 `elintp-assets` 存一份原字节 base64；本次实测 4 张截图的终稿从 1,241,228 字节变为 2,469,998 字节，加一个阅读器从 2,129,473 字节变为 4,440,550 字节。PRD AC-6 只要求终稿保留内容稿。
- 影响：带截图的已完成计划总结经 summarize 提交时，P1 能放进 2MB 的页面现在可能超限并报错；终稿附件约翻倍。原因是计划为「从终稿也能不依赖原资源再次开审」把快照写进终稿，没有评估体积。
- 已知约束：审阅页必须保留快照（AC-3 跨会话续接依赖它），不在本题范围。图片 data URI 是原字节，可从页面还原；内联 SVG 已加 id 前缀，阅读器 `srcdoc` 注入过 noscript 样式，二者不是原字节，不能直接从显示内容还原。
- 选项：
  1. **终稿只内嵌内容稿，不内嵌资源快照（推荐）**：终稿体积回到 P1 水平，符合 AC-6 原文，改动最小。代价是只拿终稿再次开审时需要原资源目录，或从最近的审阅页 / result.json 取快照；`--assets-from` 读终稿的说明需要改掉。
  2. **保留可恢复性，终稿资源去重**：图片从 data URI 还原，只为 SVG/阅读器保留原字节。截图类体积基本恢复，含阅读器的页面仍偏大；实现与测试面都更大。
  3. **接受现状**：保持全量可恢复；SKILL 或交付说明写明终稿约为资源两倍、可能超出 summarize 上限，超限时由作者精简内容。
