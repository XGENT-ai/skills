已取得的契约（同时覆盖 code mode 和直接函数调用）：

- 根线程实际身份来自当前 transcript 的 `session_meta.id`，与本次 hook 的 `session_id` 一致。fork 的 `id`、`session_id` 都是新线程，另有 `forked_from_id`。子线程的 `id` 是子线程，而 `session_id` 是父线程；输入含 `agent_id`，元信息含 `parent_thread_id` 和对象形式的 `source.subagent`。不能仅按 `session_id` 读取父 goal。
- hook 继承的 `CODEX_HOME` 指向隔离 home，JSONL 与数据库均在该 home 下；继承的 `CODEX_THREAD_ID` / `CODEX_SESSION_ID` 却仍是外层开发线程。因此线程环境变量不具备当前 hook 身份权威性。
- 项目通过真实 TUI 审阅并信任探针，未伪造 trusted hash。macOS 的 `/var` 与 `/private/var` 指向同一目录，但信任 key 含来源路径；使用前者启动的线程列出 untrusted，使用 TUI 所记录的规范化路径后为 trusted，随后真实 hook 执行。部署说明须提示规范化项目目录，并以 `/hooks` 的实际状态确认生效。
- 真实填充线程读取到 190023 / 258400，首次提醒为 73.54%。agent 按用户事先对该 goal 明确的 65% 暂停请求，先写已有 `threshold-progress.md`，再调用 `update_goal(status="paused")`，随后 `get_goal` 确认。暂停前后 objective、tokensUsed=1998、timeUsedSeconds=32 保持一致。
- 暂停后 Stop 探针返回 `{}`，对应 `hook/completed` 为 completed，随后 `turn/completed` 为 completed、线程 idle。再次通过 `thread/read` 与 `thread/goal/get` 观察到 idle / paused；该测试捕获的 `turn/started` 仅一次。证据支持本次结束边界没有触发下一自动回合，不作跨构建或无限时间保证。
- 普通 Bash 的真实入口通过 `features.code_mode.enabled=true` 与 `features.code_mode.direct_only_tool_namespaces=["functions"]` 暴露。实际 rollout 为 `function_call` / `exec_command`，目标创建、暂停、查询也为直接函数调用；首次提醒 73.42%（189715 / 258400）。agent 先用 apply_patch 保存已有记录，再原生暂停，目标与 tokensUsed=192602、timeUsedSeconds=24 保持一致，Stop 后 completed / idle，捕获的 turn/started 仅一次。见证据的 `ordinary_direct`。该配置只用于隔离验收，不是生产 guard 的安装要求。
- 用户指定的替代工具也已检查：Kimi 2.1.1 直接 Bash/pwd 成功；pi 1.0.0 暴露 bash 参数 schema，但默认服务额度耗尽，没有执行工具。Kimi 本机 update_goal 的 status 参数仅有 active / complete / blocked；这些独立工具的结果不代替 Codex V-1。见证据的 `alternatives`。
- 阈值探针本次 8 次运行耗时为 44–54 ms，均低于 3 秒；这是隔离小探针的样本，不能当作生产脚本的耗时承诺。
