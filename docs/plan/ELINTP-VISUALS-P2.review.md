## 1. 确认问题

### F-01 · [P1] 把图与截图资源纳入自包含恢复和局部更新契约

- **定位**：[计划](ELINTP-VISUALS-P2.md) §2（第 333 行 `renderPage`）、§3（第 343–349 行）、§5.3–5.4（第 415–425 行）、§9.4（第 493 行）；关联 WORK-F4/AC-3、AC-6，M2/M3。
- **问题**：新会话只拿到审阅 HTML 和 result.json 时，提取出的 Markdown 仍然引用旧 cwd 下的图片、SVG、reader 文件。计划只定义保存 Markdown，没有定义资源与原引用的映射及恢复输入，直接重渲染会丢图片或报图文件不存在。即使原目录仍在，只改图文件而不改 Markdown，区域原文比较也检测不到未标注小节的图已经变化。这使“只靠两份产物续接”和“未标注小节内容不变”不能同时得到保证。
- **证据**：[draft.mjs](../../skills/elintp/scripts/draft.mjs) 第 228–231 行按 `resolve(cwd, file)` 读取图片，失败生成缺图占位；第 257–264 行读取 SVG/reader，缺失时产生格式错误。[内容稿参考](../../skills/elintp/references/draft-format.md) 的图片及图语法只保存本地路径。[P1 M6 记录](ELINTP-VISUALS-P1.records/M6.md) 第 26 行记录过只修图稿再生成页面，证明资源会独立于 Markdown 变化。[PRD](../PRD-ELINTP-VISUALS.md) 第 196、199 行要求新会话续接、未标注内容不变和终稿保留图表。facts reviewer 用内存稿调用现有 `parseDraft`：不存在的 SVG 返回读取错误，不存在的 PNG 返回 WARN 和缺图占位；未写文件。
- **修订**：在现有页面嵌入数据和渲染接口中补齐原资源引用到资源内容的可恢复映射，明确新会话、下一轮和 final 如何消费保存的资源，不依赖原目录。保留原始 Markdown；未改区域复用原资源，资源内容变化须归入所属区域的局部变更判断。同步 §2、§3、§5.3/5.4 和 M2/M3 的改动落点；不扩展为通用资源管理系统。
- **复核**：沿含图片、SVG、reader 的稿件核对“仅交 HTML+结果 → 恢复 → 改一节 → 未标注图文保持 → 终稿”的每个输入来源。实现期由既有 V-3/V-7 承接，不增加检查组或里程碑门。
- **置信度**：高，现有文件读取行为与计划恢复输入直接不匹配。**阻塞**：否；这是明确需求下的内部契约修订，无须用户或外部系统作新决定。M2/M3 按此契约实现前须修正文案。

### F-02 · [P2] 同轮重启须保留该轮原有的 `--previous` 参数

- **定位**：[计划](ELINTP-VISUALS-P2.md) §5.1（第 378–400 行）与 §8（第 452 行），§11（第 533 行）复述恢复约定；关联 WORK-F4/AC-2、AC-5，M2。
- **问题**：第二轮或之后在尚未提交时服务停止，§8 要求相同输出、结果路径及端口重启，却一概禁止使用 `--previous`。按 §5.1，没有该参数就固定为 round=1；若沿用结果文件路径，还会因旧结果存在直接退出 1。即使使用独立的新结果路径而启动成功，旧页面提交的 round=2 也会被拒绝。浏览器虽保留了意见，公开恢复流程仍无法让它提交。
- **证据**：同一计划第 399–400 行明确“无 previous 为首轮 / 有 previous 为上一轮加 1”，第 407 行要求提交 round 等于当前轮；第 452 行的恢复指令与这些规则互斥。无需假设未来实现或额外故障机制。
- **修订**：同轮重开原样复用启动该轮的参数，并固定原端口。首轮不传 `--previous`；第 n 轮继续传创建它的第 n−1 轮已提交结果。当前轮尚未成功提交时该上一结果未被替换，因此仍产生第 n 轮。区分重开当前未提交轮与消费当前轮新结果进入下一轮；无需新增 resume 命令、守护进程或状态文件。
- **复核**：对首轮、第二轮、上一结果与输出结果同路径三种情形推演，核对重启后的 round、pageKey 与旧页面一致，并同步 §5.1、§8、§11。实现期沿用 V-1/V-3 的失败重试与多轮场景。
- **置信度**：高，计划内有明确冲突。**阻塞**：否。
