## 确认问题

1. [P2] F-01 · 新增空图注图片会重排旧 `blockId`，升级续接可能错挂标注
   - 定位：[计划 §0.1 C-3](ELINTP-VISUALS-P2-gaps.md) 与 §5.1 第 2～3 步（第 235、313～315 行）；关联 D2、M1、WORK-F4/AC-3、AC-5。
   - 问题：旧 P2 稿件中，空图注图片不进入标注目录。若它位于同小节已有标注块之前，按计划实现后，该图片会占用原块的 `bN`，后续块编号依次后移。使用旧 `result.json --previous` 续接，或以相同 `pageKey` 重开含未提交标注的一轮时，旧标注仍按原 `blockId` 找回，可能显示并继续提交到新登记的图片上，而非原内容块。这与 C-3 的续接不变及未改小节标注保留语义冲突；§5.1 仅写“blockId 编号不变”不能避免该行为。
   - 证据：`skills/elintp/assets/review.js:6-18` 按实际登记顺序编号；`skills/elintp/scripts/review.mjs:54-64` 原样保留未改小节的旧 items，不重映射 ID；`skills/elintp/assets/review.js:81,106-107,123-129` 仅按 `blockId` 编辑、保存和展示标注；`skills/elintp/scripts/review.mjs:98` 的 `pageKey` 不包含脚本版本，代码升级不会改变浏览器存储键。
   - 修订：在 §5.1 定义升级兼容编号规则，保证既有可登记块的 ID 不位移，再给新增空图注图片分配不冲突的后续 ID；例如每个 section 先按旧规则编号既有块，再登记本次新增图片。同步 C-3、D2 与 M1，不要只保留“编号不变”的笼统表述。采用该局部规则无需修改服务端或结果 schema。
   - 复核：核对修订后的机制能保证旧 result 与同轮浏览器草稿的块身份稳定。现有 V-1/V-2 都从同版或全新页面出发，无法发现此问题；在既有 V-2 并入一个“含前置空图注图片的旧轮次续接后，旧标注仍附着原块、新图片可独立标注”的场景，不新增检查 ID 或里程碑。
   - 置信度：高；由确定性的编号、保留与查找代码可直接推出。阻塞：否。

2. [P2] F-02 · “`quote` 为原引用”与统一折叠、80 字截断不能同时成立
   - 定位：[计划 D2、§5.1 第 2 步、V-2](ELINTP-VISUALS-P2-gaps.md)（第 242、314、340 行）；关联 G-01、WORK-F4/AC-1。
   - 问题：D2/V-2 要求空图注图片的提交引文可对回并等于内容稿中的原引用，但 §5.1 又沿用普通可见文字的空白折叠和开头 80 个 Unicode 字符截取。合法本地图片路径超过 80 字或含连续空白时，提交的 `quote` 只是规范化后的前缀，不是原引用；短路径验收样例无法暴露这一差异。
   - 证据：`skills/elintp/assets/review.js:7-8` 对所有引文统一执行 `text.replace(/\s+/g, ' ').trim()` 和 `.slice(0, 80)`；`skills/elintp/scripts/draft.mjs:229-243` 的图片引用没有 80 字或连续空白限制；`skills/elintp/scripts/review.mjs:15-25` 只要求服务端引文非空，不要求截断。差异核查 G-01 的 follow-up 同样要求引文使用原引用。
   - 修订：在 §5.1 明确空图注图片使用 `element.dataset.ref` 的原值作为 `quote`，不经过普通可见文字的折叠与 80 字截断；其他块行为不变。同步 D2、V-2 与 `references/draft-format.md` 的 `quote` 定义。
   - 复核：核对 D2、§5.1、V-2 和格式参考使用同一例外规则；可让 V-2 现有缺失图片采用长路径或含连续空白的原引用，并在同一提交场景中核对精确相等，不另增检查组。
   - 置信度：高；计划文字与现有确定性转换直接冲突。阻塞：否。

4. [P3] F-04 · CLI 用法与 V-1 未区分新终稿和仍含快照的旧 P2 终稿
   - 定位：[计划 C-3、§1.2、§3.1、§5.2 与 V-1](ELINTP-VISUALS-P2-gaps.md)（第 235、276、296、320、339 行）。
   - 问题：C-3/§3.1 明确带快照的旧 P2 终稿仍可作为 `--assets-from` 来源，但拟改 CLI 用法只写“审阅页.html 或 result.json”，V-1 又不加限定地写“用终稿作来源退出 1”。这会隐藏仍有效的旧终稿入口，也容易把新终稿断言误套到旧终稿。
   - 证据：计划 D3/§5.2 的实际触发条件是“HTML 中没有 `elintp-assets`”；旧 P2 终稿仍含该节点，因此不会进入新错误分支。上述无限定措辞与同一计划的兼容契约不一致。
   - 修订：用法写明“含快照的审阅页或旧 P2 终稿 / result.json”；V-1 改为“不含快照的新终稿退出 1”，并保留旧 P2 终稿可读取的文字契约。
   - 复核：对照 C-3、§3.1、§5.2 和 V-1，确认新旧终稿两种结果不再共用无限定措辞；无需新增检查。
   - 置信度：高；为计划文本的直接不一致。阻塞：否。
