## 规范要点

- C1：第一屏先出现主题本身的结论，指标块与大图优先于长段落；四模板组件外观相同，仅亮暗两套；使用系统字体，零外部字体与资源（PRD §2.4、WORK-F1/AC-2/3；计划 §6.4）。无已确认的像素目标或具体 token 数值，不能以被测 CSS 反定目标。
- C2：结论块、提醒块、指标块、带状态与释义的表格、步骤、截图、图均可呈现；状态同时有符号与文字（PRD WORK-F1/AC-6）。用 U1 完整组件与其余模板的共用组件作代表。
- C3：正文、表格、指标与内联图在亮暗下文字线条可辨认；初次跟随系统偏好，手动切换后再次打开保留；存储被拒绝时仍可切换和阅读（PRD WORK-F3/AC-1/3；计划 §6.2）。嵌入阅读器的主题控件独立，不要求随宿主联动。
- C4：三个及以上小节有大纲，链接能跳到对应小节；滚动时当前项带颜色以外的粗细或标记区分。少于三个小节无大纲（PRD WORK-F3/AC-2；计划 §6.2）。
- C5：360 CSS px 和 1440×900 均无页面级水平滚动，宽表及宽图在自身区域滚动，文字不裁剪，图片和 iframe 不超过容器（PRD WORK-N1/AC-1；计划 §6.1）。
- C6：跳到正文、主题、大纲、释义按钮、宽表滚动区可用 Tab 到达并以键盘操作，焦点可见；状态与类型不只靠颜色（PRD WORK-N1/AC-2；计划 §6.2）。
- C7：无脚本时正文、表格、图完整，释义直接显示，主题按钮隐藏；打印含全部正文、表格、图和释义，固定亮色，大纲和交互控件隐藏且不遮内容（PRD WORK-N1/AC-3；计划 §6.2）。
- C8：简体、繁体、英文界面与内容语言对应；其他语言用英文界面并保留 html lang。单文件本地阅读无网络请求，原文脚本标签作为文字而不执行；本地截图内嵌，缺失时显示缺图、路径与图注（PRD WORK-N1/AC-4、WORK-N2/AC-1/2/4）。
- U1-1：结论 → 会多出什么 → 和现在差在哪 → 建议怎么实施。状态 ✓/✗/! 配文字；表头释义由按钮展开、aria-expanded 表达状态。真实阅读器以 iframe srcdoc 嵌入，图、标签、图例完整；能平移、缩放、独立切换主题，窄屏宽内容在嵌入区内滚动（计划 §5.2、§6.1/2、§9.4 第 11 项；PRD WORK-F5/AC-1/5）。
- U2-1：todo 为要开发什么 → 技术路线与代价；done 为做出了什么 → 怎么自己验证 → 遗漏与后续，存在过程记录时附记录/截图；partial 两段都写，按 built → verify → build → route → gaps/records。页头进度为符号加文字“计划记录：未完成 / 做了一半 / 已完成”（计划 §5.2、§6.1）。
- U3-1：结论后按谁向谁要什么 → 对方立场与答复 → 已经谈定 → 还没谈定与下一步，界面用繁体（计划 §5.2、§6.2、§9.4 C）。
- U4-1：结论后先说明为什么成立；只有 why 时不显示大纲。英文控件为 Switch theme / Image missing / Sources，ja 仍用英文界面且 html lang=ja。自绘 SVG 跟随亮暗，注入例文作为原文显示（计划 §5.2、§6.2、§9.4 D）。
