实验在测什么

测的是一份给智能体看的仓库指令。基线 A0 的 AGENTS.md 只有 219 字节，装着两条受保护规则：保持既有公开接口、改动不超出请求范围。候选 A1c 有 356 字节，在这两条之上追加了两条测试纪律：

  • 改动的 Python 代码要跑相关的单元测试；
  • 报告跑过的测试命令和结果；没跑的要说明原因。

两条受保护规则在候选版里逐字保留——这个实验关心的正是「加纪律」会不会在不破坏接口与范围约束的前提下提高成功率。

这次运行本身是一次重新校准（协议号 ssh-acceptance-agents-scope-control-v3-fresh-calibration）：此前预检时发生过一次 Python 解释器段错误，协议要求在全新沙箱里重测同一组对照，并保留那次失败的运行。

怎么测

执行环境：通过 SSH 在远程机器（wisley@100.90.115.31）上的 Docker 沙箱里运行，Codex 0.162.1，模型 gpt-6.1-sol，单次任务超时 1800 秒，总预算 18 次执行、deadline 28800 秒（8 小时）。每道题的成败由固定验证器（grader）判定，智能体拿不到验证器和标准答案。

开跑前的冒烟检查验证了隔离性：环境探针确认凭据隐藏、控制面不可写、外网阻断、无验证器泄露等 11 项全部通过；oracle 标准解法在两道题上得分 1.0，空提交得分 0.0——验证器能区分「解出来了」和「没解」。

为什么仍然是「无法下结论」

问题不在结果，在样本量。协议的判定门槛是：至少 5 个独立用例组（minimum_groups: 5），最小可采纳效应 0.05。这次每个对比只有 1 个独立组——每道题只跑了一次 A0 和一次 A1c。独立组不够，统计方法（paired_source_group_bootstrap_with_bounded_mean_guard）给不出有意义的区间，只能退回有界护栏的整个取值范围 [-1.0, 1.0]，也就是「从完全无效到完全有效都排除不了」。判定原因记为 missing_pairs_checks_or_independent_groups。

「6 次全过」不等于「指令无所谓」：它同样兼容「两条测试纪律有帮助，但题太简单、两组都过了」。这次运行区分不了这两种情形，这正是 inconclusive 的含义。

口径与未知项

  • 18 与 6 的关系：报告口径是「有效任务运行 6、基础设施无效 0、登记执行 18」。results.jsonl 里可读到的记录是 5 次冒烟执行（1 次环境探针，每道题各 1 次 oracle 和 1 次空提交）加 6 次任务执行，每次任务执行另对应一次独立的 grader 评分执行。报告没有逐项拆解 18 的完整构成。
  • 成本未知：所有运行的 cost 字段为空；报告注明原因是远程登录不暴露可靠的计费数据（missing_or_invalid_resource_evidence）。
  • 证据缺口：报告记录为无。
  • 结论边界：只对冻结的仓库、任务族和指定模型成立；provider 快照身份可能不可观测。换模型、换任务族，结论不算数。

接下来

报告原文的处置是：「Search keep alone does not permit adoption.」——这次结果不能作为采用 A1c 的依据。要判定两条测试纪律是否有效，需要按协议补足独立用例组（至少 5 个）后重跑对比。完整的配对估计在 report.json，原始尝试与失败运行保留在 attempts.jsonl 和 results.jsonl。
