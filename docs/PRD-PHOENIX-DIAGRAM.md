## 0. 一句话

让使用 Agent 的作者以自然语言、Mermaid、已有 JSON 或仓库事实，获得由 Rust 核心生成、能离线阅读与导出、证据可核对的交互图解，并以 `phoenix-diagram` 接替现有 `archify`。

### 1.2 目标

- G1：作者能用统一入口完成十种图解；图的事实、方向、关系与领域语义完整，不为布局通过而删去用户要求的内容。
- G2：作者交付的确切 HTML 能分别追溯生成校验、真实浏览器检查与视觉审核结果；失败、跳过、旧证据均不能被表述为本次通过。
- G3：使用者通过既有 Phoenix 分发渠道获得匹配工具，在支持平台上无需 Rust 编译器；安装、升级、冲突与回滚均有明确结果，旧图与用户修改得到保留。
- G4：维护者能自主演进 `phoenix-diagram`；接入方不再依赖 `archify` 活跃入口，增加新图解类型不破坏已支持的输入与已交付文件。

## 2. 领域语言、用户与场景

### 2.1 领域语言

| 规范词 | 定义与边界 |
| --- | --- |
| candidate | 作者可修改的图解 JSON；通过检查只对当时的确切字节有效 |
| 已校验产物 | 已通过确定性生成与产物检查的 HTML；该称谓不包含浏览器或视觉审核结论 |
| 完整交付 | 当前产物的自动检查、浏览器证据和默认视觉审核均有真实结果；全部通过才可声称完整通过 |
| canonical 导出 | 包含完整图语义与选定视觉风格，排除临时搜索、焦点、路线、相机与动画叠层的导出 |
| Route / Reach | 已著关系上的有向路径 / 上下游可达集合；不是运行时因果或故障影响推断 |
| Repository evidence | 钉住仓库身份和提交的源码依据；工作树修改不能冒充该提交的字节 |

### 2.2 用户与权限边界

| 角色 | 任务与权限 |
| --- | --- |
| 图解作者及其宿主 Agent | 使用用户授权的材料、仓库切片和输出位置；不推测私有事实、不自动安装或启动预览服务 |
| 图解读者 | 本地打开成果、探索与主动导出；不需开发工具或在线服务，不反向修改作者源文件 |
| 接入项目维护者 | 显式安装、升级、迁移、恢复或回滚所选项目/provider；其他项目和个人配置不在该授权内 |
| 本仓维护者 | 维护源码、skill、示例及固定发行资源；编辑仓库不等于获准改动全局安装或公开发布 |

### 2.3 关键场景

主路径：① 作者描述对象或提供材料；② Agent 选择图型并生成 candidate；③ 对确切版本完成自动检查并修复诊断；④ 采集并审核真实阅读效果；⑤ 交付 HTML 链接与必要限制；⑥ 读者离线探索或导出。

| 场景 | 前置与业务动作 | 应到达的状态 / 压测边界 |
| --- | --- | --- |
| S1 | 首次使用者只有安装说明、示例和受支持平台，创建一张图 | 无需 Rust 编译器，得到完整图和可分辨的检查结果 |
| S2 | 作者提供自然语言、Mermaid 或旧版有效 JSON | 保留已给语义；缺失事实明确询问，迁移不覆盖原输入 |
| S3 | 作者解释真实仓库或带时间信息的执行记录 | 事实能追溯到固定来源；未提交内容、无记录时长与不确定时间不冒充已验证事实 |
| S4 | 已有成功产物后，candidate 非法、生成失败、证据缺失或审核发现遮挡 | 保留适用的旧产物，明确本次失败对象；不把旧文件或未做的审核当本次通过 |
| S5 | 读者在暗亮主题下搜索、追踪、缩放、播放与导出 | 交互不改变已著事实，导出与阅读状态有清晰边界 |
| S6 | 维护者升级旧 archify 安装，遇到自定义文件、安装中断或随后回滚 | 只处理受管范围；冲突不覆盖，备份和恢复可定位，后来修改受保护 |
| S7 | 作者要求比较两版架构或主动开启本地编辑预览 | 变化来自输入差异；预览只推进当前有效版本，失败仍显示最近成功产物 |

### 2.4 体验要求

| 任务 | 信息层级与反馈 | 验收落点 |
| --- | --- | --- |
| 创作 / 修复 | 先交付候选；诊断指出对象、事实与可采取的修复，避免要求作者阅读工具内部实现 | WORK-F2、WORK-F4 |
