# Phoenix oracle adapter

Run from the repository root:

```sh
node scripts/check-phoenix-oracle.mjs --bin /absolute/path/to/current/phoenix-ui --json --include-actual
node --test test/phoenix-ui/oracle.test.js
```

The checker requires an explicitly selected `phoenix-ui-engine 0.1.0` executable. It neither builds nor downloads an engine. `--prefix` selects an initial diagnosis; a filtered run cannot prove complete acceptance. The report records the executable and active adapter SHA256 values and rejects inputs that change during replay. Missing goldens, execution errors and unexplained differences fail. Platform skips remain separate and prevent `acceptanceComplete`.

The original 860 case IDs and execution steps are retained. All 1257 imported oracle/fixture files are checked against the unchanged `UPSTREAM.json` source pin `508d7e8955de3b3caf2d8676e85206723d41a887`. Original case modules, workspaces, normalizers, `DELTAS.md` and goldens are read only. The historical runner's accepted-ID parser is not used: `DELTAS.md:76–77` explicitly retires the detector section's accepted status, even though the old parser still collects its bullets.

`phoenix.json` lists every input edit by original JavaScript string offset, exact before/after text and source references, with before/after SHA256. The adapter imports those patched case modules in memory. It changes the state directory, current environment keys and active launcher identity. Retired network/update inputs remain negative controls. Internal DOM attributes, schema markers, component names and retired `hook.mjs` inputs retain their original spelling. The harness still owns execution and output normalization; its executable-path and temporary-path masks are carried to the new binary/state path. The renamed `node_modules/.phoenix-ui-live` tree is snapshotted and tested with a real controlled child process.

Output adaptation is a separate exact list of case IDs, JSON field paths, original golden hashes, field hashes and literal edits. Actual output is never rewritten. State/launcher path edits retain every other byte. Public help expectations come from the read Rust string literals in `detect/src/cli.rs`, `detect/src/lib.rs` and `skills/src/commands.rs`; they record the Phoenix command and explicit local bundle contract. New output differences still fail. These patches are independent expectations, not new recordings of historical goldens.

The fixed upstream CI replayed the oracle only on Linux; Phoenix also replays it on native Windows. Windows-only adaptations are kept separate and exact. `windows.mjs` serializes object stdin by substituting placeholders inside string values, because a Windows workspace path spliced into raw JSON text becomes invalid escapes; POSIX bytes are unchanged for every original object stdin. The same file adds the Windows spellings of existing masks: the JSON-escaped executable, the `quote_command_arg(self, true)` hook command, forward-slash workspace paths and backslash relative climbs. The external-project normalizer also accepts the backslash spelling. `phoenix.json` `platformPreconditions` establishes two POSIX fixture facts on Windows, or reports one listed skip: a live question-server pid (pid 1 does not exist on Windows), a read-data deny ACE instead of `chmod 000`, and a root-write case that the Windows administrator runner cannot reproduce. Win32 `platformFields` replace only path separators in whole path tokens with literal edits; one YAML field also gains the quotes required by its drive-letter colon. Node tests reject any separator edit that changes another byte, touches a URL or alters POSIX expectations.
